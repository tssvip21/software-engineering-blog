# [개선 기록] 테일리 — 기능이 작동하는 것과 쓰기 편한 것은 달랐다

> 2026-11-05 · 사용자 검토 전 로컬 초안

## 사용자가 다시 지적한 것

앞선 개선에서는 드래그와 저장, 권한 검사에 많은 주의를 기울였다. 하지만 사용자는 모듈을 찾고 기록을 읽는 과정과 한국어 표현, 종합 결과의 이해가 충분히 나아지지 않았다고 지적했다. 버튼이 정상 작동한다고 화면까지 잘 설계됐다고 결론 내린 것이 문제였다.

이번에는 구현 전에 외부 사이트의 구성·사용 흐름·한국어 표현을 검토하고, 기록 도구 연구와 설계 지침을 실제 작업에 연결했다. 기록은 쉬워도 다음에 찾아보거나 결과를 해석하기 어렵다면 사용을 이어가기 어렵다는 점을 함께 봤다. 연구의 표본과 적용 범위를 구분했고, 사람의 건강 기록 연구를 반려동물의 임상 근거로 옮기지 않았다.

## 기능을 넣으려고 다른 화면까지 갈 필요를 줄였다

기능 추가는 분류 제목 옆에서 끝내도록 했다. 해당 분류의 기능만 고르고 적용하면 같은 화면에 반영된다. 선택 취소와 저장 실패, 다른 구성원이 먼저 바꾼 경우도 구분한다. 기능을 빼는 것은 사용 설정의 변경이지 기록 삭제가 아니다.

실제 브라우저 검사에서 선택창의 Tab 초점이 밖으로 빠졌다. 네이티브 창을 썼다는 이유만으로 키보드 동작을 충분히 확인했다고 볼 수 없어, 초점 순환과 닫은 뒤 돌아갈 곳을 명시하고 다시 검사했다.

## 기록을 읽는 시작점을 바꿨다

전체 기록에 들어갔을 때 긴 날짜 목록부터 읽게 하지 않고, 먹이·체중이나 활동·휴식처럼 찾는 종류부터 고르게 했다. 상세와 수정을 거쳐도 보던 분류·검색·기간·페이지로 돌아온다. 특정 활동을 선택했을 때 다른 분류의 건수가 0으로 보일 수 있던 조회 범위도 바로잡았다.

## 결과 문장과 계산 과정을 분리했다

사용자에게 필요한 것은 어떤 기록이 달라졌는지와 관련 날짜·값이었다. 계산 설명과 여러 그래프를 먼저 읽어야 하는 구성을 바꿨다. 내부 계산은 남기되 쉬운 결과를 먼저 보여주고, 누르면 날짜와 원래 값을 확인하게 했다.

로직도 다시 확인했다. 한 번 크게 달라진 값이 지속 변화 조건에 못 미친다고 조용히 묻히지 않도록 했다. 하루가 끝나지 않은 합계와 완성된 날을 비교하지 않고, 기록 횟수가 늘어 합계가 커진 경우를 실제 생활 변화와 구분했다. 서로 다른 날짜의 변화가 단순히 기록 날짜가 겹친다는 이유로 연결되지 않도록 했다.

## 한국어는 문맥별로 다시 썼다

메뉴 이름뿐 아니라 등록, 초대, 공유 범위, 입력 도움말과 오류를 따로 읽었다. 예를 들어 초대 링크를 중단하는 것과 이미 참여한 사람을 내보내는 것은 결과가 다르므로 같은 ‘삭제’로 뭉뚱그리지 않았다. 기록한 사람과 돌본 사람, 준 먹이의 양과 실제 먹은 양도 구분했다. 사용자 이름이나 메모를 자동으로 고치지는 않았다.

Unslop으로 화면을 다시 보며 중복 이동 링크와 반복 문구, 글자 크기·대비·간격을 정돈했다. 제작자·원본·라이선스는 [사용 도구 및 출처](../../THIRD_PARTY_NOTICES.md)에 유지한다.

## 확인한 것과 아직 모르는 것

같은 기록 105건으로 대표 작업을 재생했다. 분류 안 기능 추가에서 다른 화면으로 나갔다 돌아오는 이동은 2회에서 0회가 됐다. 기록 상세와 수정을 거쳐도 조회 조건이 유지됐다. 글자를 키운 만큼 일부 설정 화면은 길어질 수 있어 모든 화면이 짧아졌다고 적지 않았다.

자동 검사와 개발자 관점의 작업 점검은 실제 사용자 실험이 아니다. 사람을 모집하지 않았으므로 사용 시간 단축률·오류율·만족도를 만들어 쓰지 않는다. 실제 반복 사용의 효용과 실기기·실계정 검증은 이후 별도로 확인해야 한다. 이번 결과와 확인 방법은 [4차 개선 결과](../../docs/16_테일리_4차개선.md)에 정리했다. 이 글은 아직 게시하지 않은 초안이다.
