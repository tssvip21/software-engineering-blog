# [개선 기록] 테일리 — 입력을 줄이고 화면의 역할을 나누다

> 2026-11-04 · 로컬 검수용 초안 · 외부 서비스 배포 전

## 1. 기능이 많아도 기록하기 어려우면

첫 구현에서는 20개 돌봄 모듈과 공동 기록, 권한, 루틴, 통계를 연결했다. 그러나 실제 화면을 검토하니 입력 항목이 많고 비슷한 카드와 긴 행이 반복됐다. 사용자가 기록 하나를 남기기까지 여러 화면을 거쳐야 했고, 정보를 어디서 확인해야 하는지도 분명하지 않았다.

이번 개선은 색상이나 문구만 바꾸는 작업이 아니라, 사용자가 무엇을 하려고 들어오는지부터 다시 나누는 작업으로 정했다. 외부 사이트의 구성과 사용 흐름을 참고해 검토하되, 개인·공동 반려동물 돌봄이라는 목적에 맞는 구성을 선택했다.

## 2. 같은 기록을 서로 다른 목적으로 보여주기

오늘은 지금 할 돌봄과 빠른 기록에 집중한다. 돌봄 모듈은 활동 종류별 관리와 해당 기능의 설정·통계로 이어지는 곳이다. 전체 기록은 날짜와 시각을 따라 과거 일을 찾는 이력 화면이다. 통합 상태에서는 여러 기록을 함께 읽고 이전 기간과 비교한다.

각 화면에 같은 20개 카드를 다시 놓는 대신, 주요 행동과 정보 밀도를 다르게 구성했다. 데이터는 같은 활동 기록을 사용하므로 화면마다 별도 완료 표시를 만들거나 숫자를 중복 입력할 필요는 없다.

## 3. 정확히 모르는 수치를 요구하지 않기

일상 활동은 최소한의 선택으로 저장하고 추가 설명은 펼쳐 입력하도록 바꿨다. 기록 시각과 작성자는 이미 아는 정보를 사용한다. 식사량과 활동 시간을 모르는 경우에도 완료 여부를 남길 수 있지만, 모르는 값을 0으로 채우지는 않는다. 체중·투약량처럼 실제 측정이나 수행에 필요한 수치는 해당 모듈의 기준대로 요구한다.

최근 제품이나 활동 값은 사용자가 직접 선택한 경우에만 가져온다. 지난번의 양을 이번에도 실제로 수행한 값처럼 자동 저장하지 않는다. 산책 시작과 종료는 같은 기록을 갱신하며, 저장 응답이 끊겨 다시 눌러도 같은 요청이 중복 저장되지 않게 했다.

## 4. 기능을 켜는 것과 오늘 보여주는 것은 다르다

활성화한 모듈을 전부 오늘 화면에 고정하면 자주 쓰는 동작을 찾기 어려워진다. 따라서 모듈 활성화, 오늘 고정, 활동별 주기를 구분했다. 같은 위생 모듈 안의 양치와 목욕도 서로 다른 간격을 설정할 수 있다.

주기가 도래한 활동은 오늘 화면에 나타나며, 완료 기록을 남기면 다음 시점을 계산한다. 이번 안내를 미루는 동작은 반복 간격을 바꾸지 않는다. 근거가 없는 간격을 의학적 권장값처럼 제시하지 않았고, 기록이 없다는 이유로 실제 돌봄을 빠뜨렸다고 판단하지도 않는다.

## 5. 조작과 기록 보존을 함께 검증하기

모듈 구성은 넣은 모듈과 전체 모듈을 두 영역으로 나눴다. 드래그하는 동안 주변 항목이 실제로 자리를 옮기고, 놓으면 같은 순서를 저장한다. 마우스뿐 아니라 터치와 키보드 조작을 확인했다. 모듈을 빼는 것은 기능 구성을 바꾸는 것이지 기존 이력을 지우는 것이 아니다.

테스트는 별도 DB에서 진행했다. 자동 회귀 143개, 브라우저 검사 지점 55개, 주요 화면의 여섯 가지 폭 60개 경우를 확인했다. 실제 기록용·시연용 DB도 백업 후 마이그레이션 전후의 기존 테이블 값을 비교해 변화가 없음을 확인했다. 민감 정보와 설정 권한은 화면에서 버튼을 감추는 데 그치지 않고 서버에서 검사한다.

## 7. 현재 상태와 다음 확인

이번 변경은 로컬 구현·검증을 마친 상태다. 실제 구글 계정의 OAuth 연결과 공개 서버 운영까지 확인했다는 뜻은 아니다. 화면 검수 후 필요한 조정을 하고, 별도로 인증과 배포 환경을 검증해야 한다. 검사 범위와 실행 방법은 [2차 개선 문서](../../docs/10_테일리_2차개선.md)에 정리했다.
