# [개선 12] 일정을 옆에 두고, 설정과 물품의 역할을 나누기

> 2026-11-14 로컬 과정 초안. 공개 전 사용자 검토용이다. 이전 8차 피드백 원문은 그대로 보존했다.

## 시작점

사용자는 오늘과 돌봄 기능을 사용하는 동안 일정을 보기 위해 아래로 내려가야 하는 점, 넓은 모니터에서 본문과 빈 공간의 비율이 어색한 점을 지적했다. 반려동물 정보와 일반 설정, 사료·간식 등록과 재고가 어디에 속하는지도 다시 정리할 필요가 있었다.

이번 지시는 통계 계산을 다시 바꾸는 것이 아니었다. PC·모바일 사용 흐름을 연결하고, 기존 자료를 잃지 않은 채 설정과 물품의 역할을 나누는 데 범위를 맞췄다. 3열·4열은 고정 요구가 아닌 배치 후보였으므로 실제 가용 폭에 따라 결정했다.

## PC의 옆 패널과 모바일의 펼침 영역

오늘과 돌봄 기능이 같은 일정 부분을 사용하게 했다. PC에서는 본문 오른쪽에서 완료·건너뜀·안내 닫기와 관리 화면으로 이어지고, 화면이 좁아지면 빠른 기록 위에서 접었다 펼친다. 같은 일정이 본문과 패널에서 두 번 나오지는 않는다.

카드마다 설명이 길어져도 버튼은 하단에서 찾을 수 있도록 기존 공통 동작 부분을 유지했다. 첫 모바일 화면을 보니 PC 카드를 한 열로 쌓는 것만으로는 여전히 길었다. 그래서 제목 옆에 핵심값을 두고 설명과 버튼을 아래로 모아 높이를 줄였다. 화면이 좁다는 이유로 기능을 숨기지는 않았다.

## 설정을 많이 만드는 대신 적용 범위를 나눴다

공식 서비스 도움말에서 개인 알림과 공동 공간 설정을 구분하는 방식을 살폈다.[1][2] 테일리에서는 실제로 이미 작동하던 항목만 먼저 정리했다. 개인에게만 보이는 일정 안내, 공간 전체에 적용되는 시간대, 방장만 변경하는 민감 기록 공개 범위를 일반 설정에 넣었다. 반려동물 상태에는 이름·종·품종·생일·성장 상태·체격만 남겼다.

사용자는 체격 자동값을 비활성으로 보여주는 방법도 제안했다. 나는 기존 수동 예외와 품종을 알 수 없는 경우를 보존하기 위해 제안값을 직접 바꿀 수 있도록 구현했다. 별도의 '선택 방법' 단계는 없애고, 자동 제안을 썼는지 직접 선택했는지는 저장 정보로만 구분한다.

## 물품 목록을 하나 더 만드는 대신 기존 정보를 연결했다

사료·간식 등록은 기존 Product를 사용하고 있었다. 이를 버리고 새 목록을 만드는 대신 영양제·약·위생용품·생활 소모품 분류와 선택 메모를 추가했다. 음식일 때만 영양정보를 보여주고 일반 물품에는 불필요한 열량 입력을 요구하지 않는다.

등록한 물품은 급여·투약·위생·청소 기록에서 고를 수 있다. 재고는 별도의 소비 기록을 자동으로 또 만드는 대신 그 돌봄 기록의 실제 사용량을 읽는다. 수정하거나 취소하면 같은 원기록의 효과를 다시 계산한다. 양을 적지 않은 사용은 임의로 1개를 차감하지 않는다.

약품이 일반 참여자에게 숨겨져 있어도 재고 이름으로 노출될 수 있다는 경로도 확인했다. 그래서 물품 목록뿐 아니라 재고·이력·상세·통계의 조회 전에 같은 권한을 적용했다. 기존 제품을 나중에 바꾸더라도 당시 사용 기록의 이름·연결은 유지한다.

## 검사하면서 고친 두 문제

기존 테스트 일부는 현재 시각에서 두 시간을 빼서 '오늘 기록'을 만들고 있었다. 새벽에 실행하니 실제로는 전날이 되어 검사 결과가 달라졌다. 서비스 계산을 시험에 맞춰 바꾸지 않고, 검사용 시각은 정오에서 흐르도록 고정했다. 자정 전후를 의도적으로 확인하는 검사는 별도로 남겼다.

다른 문제는 낮은 화면에서 연속으로 설정창을 여는 경우였다. 새 폼에 이전 폼의 세로 위치가 잠깐 남아 하단 저장 버튼이 화면 밖으로 나갔다. 창을 보여주는 순간 새 크기·위치를 계산하도록 바꾸고, 실제 보이는 화면 높이가 달라지면 다시 맞추게 했다.[3][4]

## 이번에 확인한 범위

자동 검사 418개와 Chromium·Firefox의 28개 동작, 76개 배치·경계 검사를 통과했다. 물품을 등록하고 10개를 입고한 뒤 2개 사용, 3개로 수정, 취소하여 10개로 돌아오는 과정은 화면 결과와 DB를 함께 확인했다. 같은 요청 재전송과 설정 저장 후 화면 갱신도 검사했다.

자료가 없는 목록, 긴 물품명, 32개 일정, 375px와 글자 확대를 확인했다. 실제 스마트폰으로 키보드를 띄워 본 것은 아니다. 화면 높이를 줄인 브라우저 검사는 그 공간을 모의한 것이라고 구분해 기록한다.

기존 시연 예시와 사용자 문서는 재생성하지 않았고, 동작 검사는 복사 DB에서 했다. 최종 로컬 반영에서도 기존 필드의 값이 유지되는지 대조한다. 이 글과 코드는 로컬에만 두며 외부 게시·배포는 하지 않는다.

구체적인 항목별 역할·권한·검사와 로컬 실행은 [8차 사용 흐름과 물품 관리](../../docs/23_테일리_8차_사용흐름과물품관리.md)에 정리했다. 실제 보호자의 사용 시간이 줄었다는 실험이나 건강 분석의 효과를 확인한 것은 아니다.

## 후속 피드백 — 모듈 영역 가로폭 조정

2026-11-14, 사용자가 오늘·돌봄 기능의 모듈이 양쪽 메뉴 사이에 좁게 끼어 보인다며 약 30% 확대를 직접 요청했다. 일정 패널을 추가한 뒤에도 이전 본문 최대 폭 1480px 제한이 남아 있어 큰 화면의 오른쪽 공간을 활용하지 못하고 있었다.

두 화면의 PC 본문 제한을 1820px로 조정했다. 2560px 화면에서 모듈 영역은 1136→1476px(약 30%), 오늘 카드는 368→481px, 돌봄 기능 카드는 242→308px로 넓어졌다. 돌봄 기능의 카드 최소 폭도 조정해 늘어난 공간에 열만 추가되지 않도록 했다. 일정 패널은 320px를 유지하며, 1200px 미만의 기존 반응형 규칙은 유지한다.

로컬 8036의 CSS에 반영하고 Chromium에서 두 화면의 375·768·1199·1200·1440·1920·2560px 배치 14건을 확인했다. 가로 넘침은 없었고 PC 일정 패널이 본문 옆에 표시됐다. 두 브라우저를 대상으로 시작한 검사는 대기가 길어 중단했으므로 Firefox 재검증 완료로 기록하지 않는다. 변경 전후 화면과 폭 측정은 `tmp/handoff/phase8-size/`에 남겼다. 화면 크기 조정이며 기록·저장 로직은 바꾸지 않았다.

## 후속 피드백 — 일정 패널 전체 고정과 긴 목록

사용자가 스크롤할 때 “오늘 일정” 제목이 잘린다고 지적했다. 실제 확인 결과, 기존 고정 시작점은 상단 메뉴보다 높아 제목이 메뉴 뒤로 들어갔고, 페이지 끝에서는 부모 영역의 끝에 밀려 패널 전체가 위로 올라갔다.

제목·완료 개수·목록을 포함한 패널 전체를 상단 메뉴 아래에 유지하도록 변경했다. 패널 폭과 좌우 위치는 기존 일정 열을 따르고, 화면에서 남는 높이 안에서 내부 목록만 스크롤한다. 화면 크기 변경과 본문 갱신 시 위치를 다시 맞추고 모바일에서는 기존 펼침 영역으로 돌아간다.

사용자 요청으로 시연 DB를 백업한 뒤 보리에 당일 스크롤 확인용 루틴 12개를 추가했다. 이름은 “시연 · …”이며 기존 3개와 합쳐 오늘 15개가 표시된다. 시작일·종료일은 2026-11-14이고, 기존 루틴·완료 기록은 변경하지 않았다. 추가 ID와 백업 위치는 `tmp/handoff/phase8-size/scroll-routines.json`에 기록했다.

Chromium에서 오늘·돌봄 기능의 세 화면 크기, 처음·중간·페이지 끝 위치 18건을 확인했다. 제목이 상단 메뉴에 가려지지 않고 패널 하단이 화면 안에 유지됐다. 패널 위 휠 6건에서 내부 목록만 이동하고 바깥 페이지 위치는 유지됐다. 모바일 전환과 본문 갱신 후 고정 복구도 확인했다. 첫 검사 도구의 대기 함수가 CSP에 막혀, 앱 보안 정책은 그대로 두고 검사 대기 방식을 바꿔 완료했다. 실제 휴대전화 검사는 하지 않았다.

## 후속 피드백 — 일정 목록 간결화

전체 패널 고정은 유지하되 오른쪽에 큰 카드가 반복돼 무겁게 보인다는 피드백을 받았다. 사용자가 제안된 간결한 목록을 적용해 보라고 요청해 오늘·돌봄 기능의 패널을 바꿨다.

시간·이름·완료 체크를 약 53px의 한 줄에 배치했다. 이름을 펼치면 설명·상태·건너뛰기 또는 원기록 링크를 볼 수 있다. 완료한 루틴은 아래의 “완료한 루틴” 묶음에 접어 두고, 알림은 별도 구역에 제목·날짜·상태로 짧게 표시한다. 목록이 짧으면 패널도 내용 높이만큼 줄어들고, 길면 기존 내부 스크롤을 사용한다.

완료 후 목록 순서가 바뀌어도 다른 항목이 잘못 펼쳐지지 않도록, 일정 상세의 펼침 상태는 목록 순번 대신 일정 식별자로 복원한다. 저장 처리 자체는 기존 함수를 유지했다.

복사 DB의 Chromium에서 두 화면·4개 화면 크기 배치 8건, 완료 체크와 연타 시 단일 저장, 건너뛰기 시 기록 미생성, 완료 목록 접기와 다른 항목의 펼침 상태 유지를 확인했다. 처음 관찰 메모 루틴으로 완료를 검사했을 때는 내용 미입력으로 기존 서버 검증이 거부했다. 해당 경우의 오류 표시·미저장을 확인하고, 추가 입력이 필요 없는 물 교체 루틴으로 성공 경로를 확인했다. 필요한 내용을 임의로 채우거나 입력 검증을 제거하지 않았다.

8036 서버에 반영 후 실제 시연에는 미완료 12개·완료 3개가 그대로 유지되는 것을 확인했다. 완료·건너뛰기 검사는 복사본에서만 수행했다. 자료는 `tmp/handoff/phase8-compact/`에 남겼으며 Firefox·실제 휴대전화 검사는 이번에 수행하지 않았다.

체크 표시 후속 조정: 사용자 요청으로 일정의 원형 완료 버튼을 모서리가 둥근 사각형으로 변경했다. 미완료는 빈 사각형, 완료는 녹색 바탕의 흰 체크로 구분한다. 8036에서 표시를 확인했으며 저장 동작은 변경하지 않았다.

체크 표시 재조정: 사용자는 완료 후 항목이 완료 묶음으로 이동하는 동작에 체크박스가 맞지 않는다며, 상태 상자 없이 체크 기호 자체를 원한다고 정정했다. 버튼을 테두리 없는 ✓로 바꿔 8036에서 확인했다. 저장 동작은 유지했다.

필수 입력 관련 발견: 사용자가 완료되지 않는 이유를 물어 실제 시연 루틴을 저장 없이 검증했다. 추가한 12개 중 메모 2개는 특이사항 메모, 청소 2개는 청소 대상, 손질 1개는 관리 항목이 없어 완료 저장이 거부된다. 기존 완료 요청이 상세 활동 기록 저장과 연결돼 있고 오류에 필드 이름이 없어 원인이 드러나지 않는다. 루틴 완료와 상세 기록의 관계 및 입력 필요 시 동선을 별도 정리할 필요가 있다. 이번에는 필수 검증이나 데이터를 임의로 변경하지 않았다.

## GitHub 반영 범위

사용자는 2026-11-14 체크 기호(✓) 변경까지 GitHub에 올리도록 지시했다. 이번 범위는 소스 버전 관리이며 서비스 외부 배포·클라우드 재시작·블로그 사이트 공개는 포함하지 않는다. 루틴의 필수 입력과 완료 동선 문제는 알려진 미해결 사항으로 남겨 다음 작업에서 다루기로 했다.
