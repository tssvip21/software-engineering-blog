# [개선 12] 일정을 옆에 두고, 설정과 물품의 역할을 나누기

> 2026-11-14 로컬 과정 초안. 공개 전 사용자 검토용이다. 이전 8차 피드백 원문은 그대로 보존했다.

## 시작점

사용자는 오늘과 돌봄 기능을 사용하는 동안 일정을 보기 위해 아래로 내려가야 하는 점, 넓은 모니터에서 본문과 빈 공간의 비율이 어색한 점을 지적했다. 반려동물 정보와 일반 설정, 사료·간식 등록과 재고가 어디에 속하는지도 다시 정리할 필요가 있었다.

이번 지시는 통계 계산을 다시 바꾸는 것이 아니었다. PC·모바일 사용 흐름을 연결하고, 기존 자료를 잃지 않은 채 설정과 물품의 역할을 나누는 데 범위를 맞췄다. 3열·4열은 고정 요구가 아닌 배치 후보였으므로 실제 가용 폭에 따라 결정했다.

## PC의 옆 패널과 모바일의 펼침 영역

오늘과 돌봄 기능이 같은 일정 부분을 사용하게 했다. PC에서는 본문 오른쪽에서 완료·건너뜀·안내 닫기와 관리 화면으로 이어지고, 화면이 좁아지면 빠른 기록 위에서 접었다 펼친다. 같은 일정이 본문과 패널에서 두 번 나오지는 않는다.

카드마다 설명이 길어져도 버튼은 하단에서 찾을 수 있도록 기존 공통 동작 부분을 유지했다. 첫 모바일 화면을 보니 PC 카드를 한 열로 쌓는 것만으로는 여전히 길었다. 그래서 제목 옆에 핵심값을 두고 설명과 버튼을 아래로 모아 높이를 줄였다. 화면이 좁다는 이유로 기능을 숨기지는 않았다.

## 설정을 많이 만드는 대신 적용 범위를 나눴다

공식 서비스 도움말에서 개인 알림과 공동 공간 설정을 구분하는 방식을 살폈다.[1][2] 테일리에서는 실제로 이미 작동하던 항목만 먼저 정리했다. 개인에게만 보이는 일정 안내, 공간 전체에 적용되는 시간대, 방장만 변경하는 민감 기록 공개 범위를 일반 설정에 넣었다. 반려동물 상태에는 이름·종·품종·생일·성장 상태·체격만 남겼다.

사용자는 체격 자동값을 비활성으로 보여주는 방법도 제안했다. 나는 기존 수동 예외와 품종을 알 수 없는 경우를 보존하기 위해 제안값을 직접 바꿀 수 있도록 구현했다. 별도의 '선택 방법' 단계는 없애고, 자동 제안을 썼는지 직접 선택했는지는 저장 정보로만 구분한다.

## 물품 목록을 하나 더 만드는 대신 기존 정보를 연결했다

사료·간식 등록은 기존 Product를 사용하고 있었다. 이를 버리고 새 목록을 만드는 대신 영양제·약·위생용품·생활 소모품 분류와 선택 메모를 추가했다. 음식일 때만 영양정보를 보여주고 일반 물품에는 불필요한 열량 입력을 요구하지 않는다.

등록한 물품은 급여·투약·위생·청소 기록에서 고를 수 있다. 재고는 별도의 소비 기록을 자동으로 또 만드는 대신 그 돌봄 기록의 실제 사용량을 읽는다. 수정하거나 취소하면 같은 원기록의 효과를 다시 계산한다. 양을 적지 않은 사용은 임의로 1개를 차감하지 않는다.

약품이 일반 참여자에게 숨겨져 있어도 재고 이름으로 노출될 수 있다는 경로도 확인했다. 그래서 물품 목록뿐 아니라 재고·이력·상세·통계의 조회 전에 같은 권한을 적용했다. 기존 제품을 나중에 바꾸더라도 당시 사용 기록의 이름·연결은 유지한다.

## 검사하면서 고친 두 문제

기존 테스트 일부는 현재 시각에서 두 시간을 빼서 '오늘 기록'을 만들고 있었다. 새벽에 실행하니 실제로는 전날이 되어 검사 결과가 달라졌다. 서비스 계산을 시험에 맞춰 바꾸지 않고, 검사용 시각은 정오에서 흐르도록 고정했다. 자정 전후를 의도적으로 확인하는 검사는 별도로 남겼다.

다른 문제는 낮은 화면에서 연속으로 설정창을 여는 경우였다. 새 폼에 이전 폼의 세로 위치가 잠깐 남아 하단 저장 버튼이 화면 밖으로 나갔다. 창을 보여주는 순간 새 크기·위치를 계산하도록 바꾸고, 실제 보이는 화면 높이가 달라지면 다시 맞추게 했다.[3][4]

## 이번에 확인한 범위

자동 검사 418개와 Chromium·Firefox의 28개 동작, 76개 배치·경계 검사를 통과했다. 물품을 등록하고 10개를 입고한 뒤 2개 사용, 3개로 수정, 취소하여 10개로 돌아오는 과정은 화면 결과와 DB를 함께 확인했다. 같은 요청 재전송과 설정 저장 후 화면 갱신도 검사했다.

자료가 없는 목록, 긴 물품명, 32개 일정, 375px와 글자 확대를 확인했다. 실제 스마트폰으로 키보드를 띄워 본 것은 아니다. 화면 높이를 줄인 브라우저 검사는 그 공간을 모의한 것이라고 구분해 기록한다.

기존 시연 예시와 사용자 문서는 재생성하지 않았고, 동작 검사는 복사 DB에서 했다. 최종 로컬 반영에서도 기존 필드의 값이 유지되는지 대조한다. 이 글과 코드는 로컬에만 두며 외부 게시·배포는 하지 않는다.

구체적인 항목별 역할·권한·검사와 로컬 실행은 [8차 사용 흐름과 물품 관리](../../docs/23_테일리_8차_사용흐름과물품관리.md)에 정리했다. 실제 보호자의 사용 시간이 줄었다는 실험이나 건강 분석의 효과를 확인한 것은 아니다.
