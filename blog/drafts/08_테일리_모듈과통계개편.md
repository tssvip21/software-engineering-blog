# 기록을 쌓는 것에서 비교의 의미를 설명하는 것으로

사용자는 “체중이 늘었어요”가 의미 없다고 한 것이 아니었다. 얼마나 늘었는지, 무엇과 비교한 것인지까지 설명하지 않은 점을 지적했다. 화면의 색이나 카드 수보다 입력한 정보를 끝까지 처리하는 방식부터 다시 살폈다.

기존 20개 모듈의 입력·저장·집계·표시를 비교한 뒤 새 선택은 19개로 정리했다. 미용은 위생·손질에 포함시키되 과거 기록을 다른 키로 바꾸거나 지우지 않았다. 기존 루틴과 구형 데이터는 별도 호환 경로로 남겼다. 상한이 20이라고 해서 남은 자리를 새 기능으로 채우지는 않았다.

최근 통계의 핵심은 같은 길이의 이전·최근 기간, 실제 값, 차이, 관측일 수를 함께 보여주는 것이다. 체중의 품종 자료는 참고 범위이지 개체의 정답이 아니며, 산책은 측정방법이 다른 센서 평균을 억지로 가져오지 않았다. 원래 기록에서 확인할 수 있는 정보와 외부 기준의 적용 가능성을 분리했다.

조사와 코드 검토 과정에서는 제공량 예상 열량과 실제 섭취량을 더한 수치, 종료 시각으로 입력 최대값을 우회하는 산책 시간, 카드와 상세의 관찰 수면 집계 차이 등을 확인해 수정했다. 버튼이 다시 줄바꿈되는 문제는 CSS 우선순위로 재현했고, 계산된 스타일과 실제 화면 폭을 검사했다. 원래 존재했던 BCS 정수 검증은 새로 고친 문제라고 쓰지 않았다.

완성한 결과는 자동·브라우저 검사와 기록 보존을 확인한 로컬 검수본이다. 실제 보호자 대상 사용 시간이나 임상 정확도를 실험한 것은 아니다. [모듈별 흐름·비교 정의·화면과 검증](../../docs/19_테일리_6차_모듈과통계.md)에 확인 범위와 한계를 함께 남겼다.

이 글은 미게시 초안이며 GitHub 업로드·외부 배포는 하지 않았다.
