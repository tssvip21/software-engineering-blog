# 테일리 8차 피드백 정리

2026-11-13~14 대화 기준. 현재 작업은 피드백 문서 정리까지다. 별도 구현 지시 전에는 코드·화면·데이터를 변경하거나 구현 작업을 시작하지 않는다. 아래의 정해진 방향도 구현 완료를 뜻하지 않는다.

## 1. 화면 비율과 일정·루틴

오른쪽 여백이 크고 카드에 비해 내용이 적어 화면이 붕 떠 보인다. 불필요한 내용을 추가하기보다 본문 폭, 카드 높이와 열 수를 함께 조정한다.

- 오늘 화면: 일정·루틴을 오른쪽 사이드 패널에 배치해 아래로 내려가지 않고 확인할 수 있게 한다.
- 돌봄 기능: 같은 방식으로 일정·루틴을 함께 확인할 수 있게 한다.
- 정확한 패널 폭, 고정·스크롤 방식, 카드 열 수는 설계 시 결정한다. 오늘 3열×2행, 돌봄 기능의 넓은 화면 4열은 앞서 나온 제안이며 고정값이 아니다.
- 최근 통계도 본문과 카드의 폭·끝선을 정돈하는 방안을 검토한다. 원기록 상세를 옆에 보여주는 안은 제안 단계이며, 새 통계 산식 적용을 승인한 것은 아니다.

확인한 현상: 1920px 화면에서 본문 최대 폭은 1480px로 제한돼 왼쪽에 배치되고, 내부 카드에도 별도 폭 제한이 있다. 오늘의 빠른 기록은 5개+1개, 돌봄 기능의 먹이·체중 분류는 3개+1개로 나뉘었다.

## 2. 반려동물 상태와 설정 분리

- 기존 “공간 설정”을 “반려동물 상태”로 바꾼다.
- 반려동물 상태와 일반 설정은 별개의 모달 두 개로 구성한다.
- 사이드바 구성원 영역 아래에 구분선을 긋고, “구성원”처럼 “설정”이라는 구역 제목을 표시한다. 제목 없이 메뉴만 추가하는 뜻이 아니다.
- 반려동물 상태에는 이름·동물 종류·품종·성별·생일·성장 상태·체격 등 동물 정보만 남긴다.
- 사료·간식 정보는 물품 관리로 분리한다.
- “구성원과 초대” 중복 진입 항목은 반려동물 상태에서 제거한다. 기존 구성원 영역과 구성원·초대 기능 자체를 삭제하지 않는다.

## 3. 체격 입력 단순화

핵심 피드백은 “체격 선택 방법”이 직관적이지 않고, 별도로 존재할 이유를 모르겠다는 것이다. 회색 표시만 바꾸는 수준으로 끝내지 말고 선택 단계 자체의 필요성을 검토한다.

- 현재 코드: `care/forms.py`의 `RoomForm.size_origin`은 “품종 자료로 제안”과 “직접 선택”을 전환한다. 자동일 때는 품종·성별에 따른 제안값을 적용한다.
- 제안: 화면에서는 “체격 선택 방법”을 없애고 “체격”만 둔다. 제안 가능한 품종이면 자동으로 채우고, 믹스·품종 미상 등 제안할 수 없는 경우 같은 항목에서 직접 선택하게 한다.
- 앞선 사용자 의견: 품종을 선택하면 체격을 자동 선택하고 회색 비활성 상태로 보여주는 편이 맞지 않는지 검토한다.
- 미정: 자동값의 수정 허용 여부, 품종별 매핑의 적절성, 종별 적용 범위, 성장 중·모름 처리. 자동·직접 구분은 사용자에게 불필요한 선택을 강요하지 않는 방향으로 정리한다.

## 4. 물품 관리

메뉴 이름은 **물품 관리**로 정한다. 사이드바의 **루틴·반복 알림 바로 아래**에 둔다.

안에서는 **등록한 물품 / 재고·소비**로 구분한다. 기존 사료·간식 정보는 등록한 물품으로 옮기고, 재고·소비 기능과 연결해 같은 정보를 중복 등록하지 않도록 한다. 실제 사용은 급여·투약·위생 등 해당 돌봄 기록에서 연결한다.

함께 다룰 물품 후보는 다음과 같다. 구체적인 지원 범위와 항목별 입력값은 설계 시 확인한다.

| 분류 | 예시 |
| --- | --- |
| 먹는 제품 | 사료, 간식, 영양제 |
| 건강 관리 | 복용약, 구충제 |
| 위생용품 | 샴푸, 치약, 귀 세정제 |
| 생활 소모품 | 고양이 모래, 배변패드, 탈취제 |

물품 관리의 구체적인 화면 형태와 기존 재고 화면 통합 방식은 아직 정하지 않았다.

## 5. 설정창 구성 — 구현 작업에 남기는 지시

구현 단계에서 테일리의 현재 기능과 실제 사용 흐름을 확인하고 필요한 설정 항목을 알아서 조사해 구체적으로 구성할 것. 단순히 빈 공간을 채우는 항목은 넣지 않는다. 앞서 나온 후보 목록을 그대로 따를 필요는 없다.

- 반려동물 정보와 일반 설정의 역할을 분리한다.
- 설정창의 구역, 항목, 표시 문구, 기본값, 개인·공동 적용 범위와 배치까지 제안한다.
- 기존 기능과 새로 필요한 기능을 구분한다.
- 기록 공개 범위와 기록 시간대는 기존 항목에서 옮길 후보이며, 최종 목록은 아니다.
- **동작 줄이기**는 추후 추가할 설정으로 남긴다.

이 내용은 문서에 남기는 후속 작업 지시다. 현재 세션에서 모델 호출이나 구현을 시작하라는 의미가 아니다.

## 6. 모바일도 함께 개선

기존 반응형 코드만으로 모바일 대응이 끝났다고 보지 않는다. PC 개편과 함께 모바일 배치와 사용 흐름도 점검하고 손볼 것.

- 오늘·돌봄 기능의 일정·루틴 패널을 좁은 화면에서 어디에 배치하고 어떻게 열지 정한다. 기록 버튼을 방해하지 않으면서 일정도 쉽게 확인하게 한다.
- 반려동물 상태·설정 모달은 화면 높이와 가상 키보드를 고려해 입력란, 저장·닫기 버튼이 가려지지 않도록 한다.
- 물품 관리도 등록 목록과 재고·소비를 모바일에서 찾아보고 사용할 수 있게 구성한다.
- 사이드바·하단 탐색, 카드 열 수와 간격, 줄바꿈, 터치 영역, 잘림·겹침·가로 스크롤을 확인한다.
- 실제 좁은 화면에서 탐색, 모달 열기·닫기, 입력·저장, 일정 확인 흐름을 점검한다. 브라우저 모바일 화면 검증과 실제 기기 확인 범위는 구분해 보고한다.

## 7. 기존 구현 확인 — 연타와 동작 줄이기

### 버튼 연타·재시도

빠른 기록은 저장 처리 중 같은 동작을 막고, 서버는 같은 요청 번호의 재전송을 기존 결과로 처리한다. 입력 모달도 저장 중 추가 제출을 막고, 응답 유실 시 같은 본문과 요청 번호로 재시도한다.

별도 테스트 DB에서 기존 `PresetAndActionTests`, 재고 중복 차감 방지 검사, `test_input_ui`를 실행해 **41개 모두 통과**했다. 동일 요청의 기록·변경 이력·처리 내역 중복 방지와 입력 모달 기록·루틴 재시도가 포함된다. 이번에는 브라우저 연타 검사를 다시 실행하지 않았다.

저장 성공 후 다시 누르는 별개의 빠른 기록은 새 기록으로 저장한다. 모든 반복 입력을 하나로 합치는 기능은 아니다.

PPT 표현: **“저장 처리 중 연속 클릭과 동일 요청 재전송으로 인한 중복 저장을 방지한다.”**

### 동작 줄이기

OS·브라우저의 `prefers-reduced-motion`에 대응하는 코드가 있다. 앱 설정창의 별도 켜기·끄기 기능과는 구분한다. 전체 애니메이션이 실제로 꺼지는지는 이번에 브라우저로 검사하지 않았다. 앱 내부 설정은 추후 항목이다.

## 8. 반영·취소·작업 상태

- 예시 이름: 로컬 시연 DB의 알려진 가상 예시 11개에서 “n차 검수 · ” 접두어를 이미 제거했다. 공간 ID, 기록, 구성원, 일반·추가 예시 구분은 유지했다. 이전 검수 DB와 기존 생성 스크립트는 변경하지 않았다.
- 하단 “모든 돌봄 공간”·“로그아웃” 아이콘 추가는 사용자가 취소했다. 후속 작업에 넣지 않는다.
- 일정 패널은 피드백을 구현 승인으로 잘못 해석해 코드 수정을 시작했으나, 사용자 정정 후 해당 변경과 새 파일을 모두 되돌렸다.
- 이후에는 피드백 문서 정리와 읽기·기존 테스트 확인만 수행했다. 이번 정리에서도 코드·화면·데이터는 변경하지 않았다.

## 9. 구현 후 후속 피드백 — 루틴 완료와 필수 입력

2026-11-14. 8차 구현본을 사용하면서 추가로 확인한 문제다. 이번 요청은 후속 수정 사항의 문서 정리까지이며, 아래 동작을 지금 구현하라는 의미가 아니다.

### 문제와 확인된 원인

- 일정의 ✓를 누르면 루틴이 완료될 것으로 보이지만, 일부 항목은 “필수 항목입니다”만 표시되고 목록에 남는다.
- 현재 루틴 완료 요청은 상세 돌봄 기록 저장도 함께 시도한다. 기록에 필요한 값이 없으면 저장이 거부되어 완료되지 않는다.
- 오류 문구에 어떤 항목이 빠졌는지 나오지 않고 해당 입력으로 이어지는 동선도 부족하다.
- 스크롤 확인용으로 추가한 시연 루틴 12개 중 5개에서 확인했다. 아침 상태 메모·하루 관찰 메모는 “특이사항 메모”, 식기 청소·생활공간 청소는 “청소 대상”, 털 손질은 “관리 항목”이 누락됐다. 값을 저장하지 않고 실제 폼 검증으로 확인했다.

### 후속 작업에서 정리할 내용

- 사용자가 루틴의 ✓를 눌렀을 때 기대하는 “했다는 확인”과 상세 돌봄 기록 저장의 역할을 명확히 설계한다. 단순 완료와 상세 기록을 분리할지, 입력이 필요한 경우 완료 전에 입력창으로 안내할지는 아직 확정하지 않았다.
- 추가 입력이 필요한 경우 어떤 값이 필요한지 구체적으로 알리고, 그 자리에서 입력·저장·취소할 수 있는 동선을 제안한다. 이름 없는 필수 오류만 남기지 않는다.
- 누락값을 임의로 채우거나 필수 검증을 제거해 성공 처리하지 않는다. 루틴 완료가 실제 급여량·산책 시간·투약량 등의 측정 기록을 꾸며내지 않도록 한다.
- 성공한 경우에만 미완료 목록에서 완료 묶음으로 이동한다. 실패하거나 입력을 취소하면 항목과 입력 내용을 유지하고, 재시도로 중복 저장되지 않게 한다.
- 완료 후 바로 목록에서 빠져 변화가 잘 보이지 않는 문제도 함께 검토한다. 완료 표시·이동 안내 등 피드백을 정리하되 애니메이션 추가가 확정된 것은 아니다.
- 스크롤 확인용 예시가 실제 완료 동작을 오해하게 하지 않도록, 입력이 있는 경우와 없는 경우를 구분해 확인한다.

### 현재 상태와 확인 기준

- 버튼 모양은 사용자의 정정대로 체크박스가 아닌 테두리 없는 ✓로 이미 변경했다. 위의 완료·입력 정책은 아직 변경하지 않았다.
- 후속 검증에서는 추가 입력 없이 완료 가능한 루틴, 필수 입력이 있는 루틴, 입력 취소·오류·재시도, 완료 후 목록 이동을 각각 확인한다. 화면 표시와 실제 기록 생성·연결 상태를 함께 대조한다.
- 구현 후 변경 과정은 `12_테일리_8차_구현과검증.md`에 이어서 남기고, 기존 기본 작업 규칙을 그대로 적용한다.
