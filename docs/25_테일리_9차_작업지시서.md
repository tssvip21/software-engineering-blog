# 테일리 9차 개선 작업지시서

작성: 2026-11-16
프로젝트: `software-engineering-project`

## 목표와 실행 권한

테일리의 전체 가독성과 수치 표현을 사용자 관점에서 개선하고, 빠르게 기록의 배치와 루틴 완료 흐름을 완성한다. Windows·Mac 실행 호환성을 확인하고 최신 버전을 실제 외부 배포해 사용할 수 있게 만든다. 다섯 과제 모두 수행하며, 가독성은 높은 우선순위의 독립 과제다.

이 문서는 실행을 맡을 사람을 위한 지시서다. 지시서 작성 단계에서는 구현이나 배포를 시작하지 않는다. 사용자가 실행을 맡기면 아래 범위를 수행한다.

- 구현 방법과 구체적인 디자인은 실행자가 판단한다. 글자 크기·굵기·폰트·색상·간격·카드 배치에 자율권이 있으며, 세부 선택마다 재승인을 받지 않는다.
- 변경은 의미 있는 단위로 로컬 커밋한다. **GitHub push, 원격 PR 작성·병합, 릴리스 게시는 하지 않는다. 사용자의 검수 후 업로드 지시가 있을 때 진행한다.** 자체 검사 통과를 원격 업로드 승인으로 해석하지 않는다.
- 실제 서비스 배포는 사용자가 이미 요구한 완료 범위다. 필요한 기존 클라우드 VM 재시작과 재배포를 포함한다. GitHub 업로드와 서비스 배포를 구분하며, 검증한 로컬 소스로 기존 배포 패키지를 만들 수 있다. 배포를 이유로 GitHub에 먼저 올리지 않는다.
- 새 유료 자원·유료 전환·도메인 구매, 기존 데이터 삭제, 별도 설치형 앱 개발은 임의로 추가하지 않는다.

마지막 운영 문서상 클라우드 VM은 사용자 요청으로 정지됐고 운영 DB·디스크는 보존돼 있다. 최신 8차의 클라우드 재배포는 완료되지 않았다. 이번 작성 단계에서는 클라우드 상태를 다시 조회하지 않았으므로 배포 착수 시 실제 상태·비용 조건·외부 주소를 확인한다. 로컬 시연 DB와 운영 DB는 서로 다른 자료다.

`git status`와 관련 변경을 먼저 확인한다. 다른 작업자의 파일, 미추적 문서와 사용자 자료를 되돌리거나 이번 커밋에 섞지 않는다. 이 지시서는 이전 대화를 읽지 않아도 요구를 알 수 있도록 작성했다.

## 1. 전체 가독성 개선 — 높은 우선순위

오늘, 돌봄 기능, 기록 목록·상세, 통계·그래프, 물품·재고, 일정·루틴, 설정·입력창 등 서비스 전체를 살핀다. 빠르게 기록 카드의 일부 수정만으로 완료하지 않는다.

- 제목·본문·보조 설명·숫자·단위·버튼의 글자 크기, 굵기, 폰트, 색 대비, 줄 간격·줄 길이·정렬을 사용자 관점에서 조정한다.
- 먼저 읽을 정보, 현재 상태, 다음 행동이 쉽게 구분되게 한다. 작거나 흐린 글씨, 약한 대비, 핵심 정보와 부가 정보의 모호한 구분을 개선한다.
- 모든 글자를 일괄 확대하거나 모든 요소에 강조색을 넣지 않는다. 필요한 여백을 유지하고, 불필요한 설명·장식·배지를 늘리지 않는다.
- 입력 라벨, 단위, 오류·상태 안내까지 포함한다. 색에만 의존하지 않고 의미를 알 수 있게 한다.
- 큰 화면, 좁은 화면, 글자 확대에서 읽기 쉬운지 확인한다. 글자·버튼 잘림, 겹침, 불필요한 가로 스크롤과 초점 표시 누락을 살핀다.

완료 기준: 전체 화면을 확인한 목록과 공통 표현 기준, 필요한 예외가 있으며, 주요 화면의 전후 비교에서 읽기 어려웠던 문제가 어떻게 개선됐는지 설명할 수 있다. 카드 하나의 개선이나 CSS 변경 자체가 완료 기준은 아니다.

## 2. 전체 수치 표현 개선

숫자를 사용자가 무엇을 알고 판단하는 데 쓰는지부터 확인한다. 특정 사례만 고치거나 모든 숫자에 하나의 형식을 적용하지 않는다. 전체 항목을 먼저 살핀 뒤 의미와 용도에 맞는 공통 기준과 예외를 정한다.

- 입력창·빠른 기록·목록·상세·요약·통계·그래프·물품·재고·일정·알림에 나타나는 수치를 포함한다. 실제 서비스에 있는 양·개수·무게·부피·거리·시간·횟수·주기·금액·비율·날짜·기간·평균·합계·변화량을 확인한다.
- 개수, 무게, 부피 중 적절한 표현을 선택하고, 필요하면 함께 보여준다. 같은 물품도 보유 수량, 포장 용량, 개봉 후 잔량, 실제 사용량에 따라 표현이 달라질 수 있다.
- 단위와 소수 자릿수를 함께 판단한다. g/kg, ml/L 등은 수치의 크기·측정 정밀도·사용 목적에 맞게 선택한다. 비교표나 그래프에서는 값끼리 비교하기 쉬운 단위를 유지한다.
- 불필요한 소수와 끝자리 0은 줄인다. 작은 잔량이나 차이가 반올림 때문에 0으로 사라지지 않게 하고, 실제보다 정밀한 측정처럼 보이지 않게 한다.
- 개당/전체, 1회/하루/기간 합계, 평균의 대상과 기간, 변화량의 비교 대상을 명확히 한다. 실제 0, 미입력, 기록 없음, 계산 불가, 추정값을 구분한다.
- 사용자가 입력한 값이 저장·조회·집계에서 이해 가능한 형태로 이어지게 한다. 표시를 위한 반올림과 내부 계산을 구분하고, 원기록의 정밀도를 임의로 줄이지 않는다.

사용자가 제시한 사례는 다음과 같다. 작업 범위는 이 사례에 한정되지 않는다.

| 사례 | 반영할 의도 |
| --- | --- |
| 시간이 소수점 셋째 자리까지 표시됨 | 소수 분 대신 정수 또는 분·초 등 자연스러운 표현을 선택한다. |
| 먹이량(g)·산책 거리의 과도한 자릿수 | 소수점 첫째 자리 정도의 간결한 표시를 기본 방향으로 삼되, 다른 단위·수치까지 기계적으로 적용하지 않는다. |
| 치약이 `0.055kg`으로 표시됨 | 보유 개수, 개당 용량, 실제 잔량 중 사용자가 필요한 정보를 알맞게 표시한다. 사료·간식 등도 같은 관점에서 검토한다. |
| 몸무게 | 현재 표시를 유지한다. |

모든 재고를 개수로 바꾸라는 요구가 아니다. 예를 들어 포장 정보가 확인된 경우 개수와 개당 용량을 함께 보여줄 수 있고, 실제 급여·소비량은 무게가 적합할 수 있다. 기존 데이터에 없는 개수·용량을 만들거나 환산 근거 없이 변환하지 않는다. 데이터 구조 보완이 필요하면 기존 값·참조를 보존하는 전환과 검증을 함께 수행한다. 신규 건강 판정이나 통계 의미 변경으로 범위를 확대하지 않는다.

완료 기준: 전체 수치 항목의 의미·사용 위치·단위·표시 정밀도·예외를 정리하고 실제 화면에 적용한다. 누락·0·작은 값·큰 값·환산 경계·평균·차이를 확인하며, 저장값·집계와 표시가 일치한다.

## 3. 빠르게 기록의 공간 사용과 배치 개선

현재 사용자 화면에서는 빠르게 기록이 3열, 돌봄 기능이 4열로 보이며 빠르게 기록의 카드가 내용에 비해 비어 보인다. 이 열 수는 관찰한 상태이며 고정 요구가 아니다.

- 카드 높이·안쪽 여백·카드 간격·열 수와 정보·버튼 배치를 내용에 맞게 조정한다. 읽는 데 필요한 여백은 유지한다.
- 무엇을 기록하는지, 기록할 설정값, 실행 버튼이 한눈에 보이게 한다. 전체 가독성 과제의 기준을 적용한다.
- 기존 정보의 배치와 표현을 먼저 개선한다. 추가 정보는 빠른 기록의 판단·실행에 직접 도움이 되는 경우에만 넣는다.
- 중복 설명, 불필요한 배지·통계·장식을 덧붙여 카드를 채우지 않는다. 공백 감소가 과밀하고 산만한 화면으로 이어지지 않게 한다.

완료 기준: 화면 폭과 내용 길이가 달라도 과도한 공백·과밀함 없이 핵심 정보와 동작을 찾을 수 있고, 기존 빠른 기록 기능이 정상 작동한다.

## 4. 루틴 완료 흐름 개선

현재 ✓를 눌렀을 때 상세 기록 저장에 필요한 값이 없으면 완료되지 않고 이름 없는 필수 오류가 나타나는 문제가 있다. 과거 시연에서는 메모·청소·손질 등에서 확인됐으며, 이후 시연 데이터가 바뀌었으므로 현재 코드와 재현 사례를 다시 확인한다.

- 사용자가 기대하는 완료 확인과 상세 돌봄 기록의 관계를 설계한다. 추가 입력 없이 완료할 수 있는 경우와 상세 입력이 필요한 경우의 기준을 일관되게 정한다.
- 입력이 필요하면 누락 항목을 구체적으로 알리고 그 자리에서 입력·저장·취소할 수 있게 한다.
- 누락값을 임의로 채우거나 필수 검증을 제거하지 않는다. 단순 완료가 실제 급여량·산책 시간·투약량 등의 측정을 만들어내지 않게 한다.
- 성공한 경우에만 완료 상태와 목록을 갱신한다. 오류·취소 시 항목과 입력 내용을 보존하고, 연타·재시도·응답 유실로 중복 저장되지 않게 한다.
- 완료 후 목록 이동을 사용자가 알아볼 수 있게 한다. 특정 애니메이션이나 체크박스 도입을 고정 요구로 삼지 않는다.

완료 기준: 추가 입력 없는 완료, 입력이 필요한 완료, 입력 취소·검증 실패·재시도·연타·완료 후 목록 이동을 실제 흐름으로 확인한다. 화면 상태와 기록 생성·연결·재고 반영을 함께 대조한다.

## 5. Windows·Mac 실행 및 실제 배포 완료

Docker 구성의 실행 호환성과 브라우저의 사용 호환성을 각각 확인한다. Docker 사용 자체로 Mac 검증이 끝난 것은 아니다. 공개 사이트 이용자에게는 브라우저만 필요하며 Docker 설치를 요구하지 않는다.

- Windows·macOS에서 필요한 Docker 실행 방법을 정리하고 실제로 검증한다. 이미지·의존성, CPU 아키텍처, 경로·볼륨, 환경 설정·실행 명령의 호환성 문제를 수정한다. 실제 확인한 OS와 CPU를 명시한다.
- Windows의 대상 브라우저와 Mac Safari·Chrome에서 로그인, 입력·수정·조회, 모달·스크롤, 일정·통계의 주요 흐름을 확인한다.
- iPhone 실기기 검증은 필수 범위가 아니다. 별도 모바일 앱·PWA·백그라운드 GPS 구현을 이번 작업에 추가하지 않는다. 기존 반응형 화면은 유지하고 회귀를 확인한다.
- 실제 Mac 환경을 확보하지 못하면 이용 가능한 연결 환경부터 확인한다. 다른 OS의 브라우저 모의 검사로 Mac 완료를 대신하지 않는다. 가능한 구현·검증은 계속하고, 필요한 환경·시도·남은 확인을 구체적으로 보고한다.
- 운영 상태·비용 조건을 확인하고 기존 데이터와 설정을 백업한 후 최신 버전을 기존 클라우드에 배포한다. 데이터 구조 변경은 복사본에서 먼저 확인하고 복구 가능한 순서로 적용한다.
- VM 재시작 후 외부 IP·도메인·HTTPS·OAuth 주소를 실제 확인한다. 비밀값은 저장소·문서·로그에 노출하지 않는다. 환경 파일·DB·백업·개인 자료를 배포 패키지에 넣지 않는다.
- 외부 URL에서 로그인과 기록 저장·수정·재조회, 정적 파일·일정·통계가 정상 동작하는지 확인한다. 기존 운영 데이터와 로컬 시연 자료를 섞거나 덮어쓰지 않는다. 운영 환경에 검사용 가상 자료를 무단 생성하지 않는다.

완료 기준: 최신 버전이 외부 URL로 접속되고 주요 동작과 데이터 보존이 확인돼야 한다. 실제 배포와 Windows·Mac 확인을 준비 문서만으로 대체하지 않는다. 확인하지 못한 환경·기능은 미완료로 명시한다.

## 작업·검증·기록 방식

- 시작 전에 이해한 목표와 결과에 영향을 주는 가정을 한두 줄로 밝힌다. 목표·범위 변경이나 필수 입력·권한 부족으로 진행할 수 없을 때만 첫 줄을 `QUESTION`으로 시작해 해당 사항을 질문한다. 영향을 받지 않는 작업은 계속한다. 그 외 선택은 합리적으로 판단해 진행한다.
- 기존 사용자 변경·실행 중인 작업·기록·권한·초대·저장 동작을 보존한다. DB·시연 예시를 초기화하거나 결과를 좋게 보이게 하려고 자료를 교체하지 않는다.
- 검증은 별도 복사 DB에서 수행한다. 기존 검사 도구를 확인해 재사용하고 변경 위험에 맞는 기능·회귀 검사를 수행한다. `scripts/verify_phase8_browser.py` 등 과거 도구를 그대로 실행하기 전에 데이터·서버에 미치는 영향을 확인한다.
- 전후 화면은 같은 데이터와 조건에서 비교한다. 넓은 화면·좁은 화면·글자 확대, 긴 이름·빈 목록·오류 상태를 포함한다. 화면 검사를 자동 테스트 통과만으로 대신하지 않는다.
- 새로운 문서 형식을 늘리지 말고, 수치 표현 기준과 실제 변경·검증 결과를 프로젝트 문서에 간결하게 남긴다. 주요 판단과 실제 실패·수정 과정은 관련 블로그 초안에 기록한다. 글을 외부 게시하거나 LMS에 제출하지 않는다.
- 맡은 다섯 과제의 핵심을 후속 작업으로 넘기고 완료하지 않는다. 실제 장애가 있으면 수행한 작업, 시도와 결과, 남은 핵심, 막힌 이유와 재개 지점을 명시한다. 가능한 작업은 끝까지 수행하고 근거 없는 성공을 기록하지 않는다.

## 커밋과 최종 전달

변경 파일과 검사 결과를 확인한 뒤 이번 작업 파일만 명시적으로 스테이징해 로컬 커밋한다. 기존 사용자 변경과 비밀값·DB·임시 결과를 포함하지 않는다. **검수 전 GitHub 업로드는 하지 않는다.**

최종 결과에는 다음을 간결하게 남긴다.

1. 다섯 과제별 변경 내용과 확인 결과, 미완료 항목.
2. 가독성·카드 배치의 전후 화면과 수치 표현 기준의 위치.
3. 기능·데이터 보존 검사 결과와 실제 확인한 OS·브라우저·CPU 환경.
4. 로컬 커밋 ID, 배포 버전·접속 주소, 운영 데이터 보존·복구 관련 정보.
5. GitHub에 업로드하지 않았다는 상태와 사용자가 검수할 위치.
