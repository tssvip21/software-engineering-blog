# 테일리 수정 계획

> **2026-11-04 실행 결과:** 14개 항목을 로컬에 반영하고 검증했다. 현재 결과와 확인 방법은 [테일리 2차 개선](10_테일리_2차개선.md)을 기준으로 한다. 아래 내용과 ‘반영 예정’ 상태 표시는 작업 전에 합의한 요구사항 기록으로 보존한다.

1차 초안 확인 후 모으는 수정 사항이다. 현재 14개이며, 실제 반영 전이다.

2차 작업은 전체 UI의 정보 구조와 사용자 동선 재설계부터 시작한다. 이를 바탕으로 아래 기능·화면 개선을 연결하고, 세부 디자인 정돈과 검증을 진행한다. 항목 번호는 작업 순서를 뜻하지 않는다.

이번 실행 범위는 로컬 수정·검증과 작업 단위의 로컬 커밋까지다. GitHub push, PR 생성, 외부 게시와 서비스 배포는 하지 않는다. 결과를 검수로 넘긴 뒤 업로드 여부를 판단한다.

## 1. 서비스 이름 변경

- 한글 이름: **테일리**
- 영문 표기: **Taily**
- 사이트에서 사용하는 임시 서비스명 ‘반려동물 돌봄’을 테일리로 변경한다.
- 화면의 서비스명, 브라우저 제목, 서비스 소개 등 이름이 표시되는 곳을 일관되게 맞춘다.
- 상태: 반영 예정.

## 2. ‘발정·산란’ 모듈 재검토

- 사용자 의견: 명칭뿐 아니라 발정·산란을 중심으로 한 모듈의 전체 구성이 서비스에서 불편하게 느껴진다.
- 이름만 바꾸는 수준에 그치지 않고 모듈의 목적, 입력 항목과 통계 구성을 함께 재검토한다.
- 대체 명칭과 내용, 다른 모듈로 교체할지는 아직 정하지 않았다.
- 상태: 수정 방향 논의 중.

## 3. 통합 상태 화면 재구성

- 사용자 의견: 현재 화면은 모듈별 영역이 세로로 쌓인 형태여서 전체 상태가 직관적으로 들어오지 않는다. ‘오늘’ 화면 쪽이 더 깔끔하다.
- 통합 상태 화면을 모듈별 카드나 구역으로 나누어 반복하는 구조에서 벗어나 새 형식으로 구성한다. 20개 카드를 격자로 재배치하는 정도로 끝내지 않는다.
- ‘오늘’ 화면의 간결한 정보 배치를 참고해, 여러 모듈의 기록에서 나온 핵심 상태와 변화를 하나의 통합 요약으로 정리한다. 화면을 길게 훑거나 모듈을 하나씩 열지 않아도 반려동물의 전체 관리 현황을 한눈에 파악할 수 있게 한다.
- 외부 사이트를 참고해 통합 상태의 구성과 사용 흐름을 검토한다.
- 모든 상태를 종합하되 상세 기록과 모든 수치를 나열하지 않는다. 서로 다른 단위의 값을 억지로 합하거나 근거 없는 하나의 건강 점수로 바꾸지 않는다.
- 현재·7일 전·1개월 전 비교와 적용 가능한 분류별 참고 기준 비교는 통합 요약 안에서 자연스럽게 확인할 수 있게 유지한다.
- 세부 내용이 필요하면 관련 상세 통계로 이동하게 한다. 개별 모듈의 기록·통계 기능은 유지하며, 이번 변경은 통합 상태 화면의 표현 구조에 적용한다.
- 상태: 재구성 방향 반영 예정. 구체적인 화면 배치는 후속 설계에서 정한다.

## 4. 왼쪽 사이드바 너비 조절과 접기

- ‘오늘’, ‘돌봄 모듈’, ‘루틴’ 등이 있는 왼쪽 탐색 사이드바를 사용자가 조절할 수 있게 한다.
- VS Code의 파일 탐색 영역처럼 사이드바와 본문 사이 경계를 드래그해 너비를 늘리거나 줄인다. 본문은 바뀐 너비에 맞춰 배치된다.
- 사이드바를 접거나 숨겨 본문을 넓게 사용할 수 있게 하고, 숨긴 상태에서도 다시 펼치는 버튼을 제공한다.
- 상태: 반영 예정.

## 5. 화면 문구를 자연스럽고 담백하게 정리

- 사용자 의견: 현재 문구가 기계적이고 딱딱하다. 사람이 안내하는 듯 자연스럽게 바꾸되, 감정을 과하게 담아 어색해지지 않게 한다.
- 메뉴, 제목, 버튼, 입력 안내, 빈 화면, 오류·완료 메시지 등 사용자에게 보이는 문구를 전체적으로 살핀다.
- 익숙한 단어와 짧은 문장으로 필요한 내용을 바로 전달한다. 설명은 자연스러운 해요체를 기본으로 하고, 버튼·메뉴는 행동과 목적이 드러나는 간결한 표현을 사용한다.
- 과한 감탄, 억지 친근함, 귀여운 말투, 불필요한 응원·칭찬과 감성 문구를 덧붙이지 않는다.
- 오류 안내는 사용자를 탓하지 않고 어떤 문제가 생겼는지와 다음에 할 일을 알려준다. 권한, 삭제, 기록·통계의 의미는 말투를 바꾸더라도 정확하게 유지한다.
- 상태: 반영 예정.

## 6. 빠른 기록 중심으로 입력 흐름 재설계

- 사용자 의견: 모듈마다 세세한 항목을 길게 입력해야 해서 보고서를 작성하는 것처럼 부담스럽다. 여러 모듈을 반복해서 사용하는 상황에서, 기록에 드는 수고를 감수할 이유가 부족하다.
- 통계에 필요한 정보를 많이 수집하는 것보다 사용자가 일상적으로 쉽게 기록하고 바로 도움을 받는 것을 우선한다. 문구를 줄이는 수준이 아니라 모듈별 필수 항목과 기록 동선을 다시 검토한다.
- 일상적인 활동은 몇 번의 선택으로 기록할 수 있게 한다. 상세 설명·메모·추가 측정값은 필요한 사람만 펼쳐 입력하며, 매번 요구하지 않는다.
- 기록 시각과 기록자처럼 서비스가 이미 아는 정보는 자동으로 처리한다. 평소와 다른 시간·수행자로 기록해야 할 때만 변경하게 한다.
- 반복되는 제품·활동·입력값은 최근 사용값이나 사용자가 정한 기본값을 재사용하기 쉽게 제시한다. 이전 수치를 실제 측정값으로 몰래 기록하지 않고, 사용자가 확인하고 저장할 수 있게 한다.
- 입력 방식 예시: 청소·물 교체는 완료 기록, 산책은 시작·종료, 체중은 측정값 입력, 식사는 자주 쓰는 제품·양 선택. 모듈 성격에 맞는 최소 입력을 정하며 모든 모듈을 같은 긴 폼으로 처리하지 않는다.
- ‘오늘’ 화면에서 자주 하는 활동을 바로 기록하고 그 자리에서 결과를 확인할 수 있게 한다. 모듈 페이지를 하나씩 돌아다녀야 하는 부담을 줄인다.
- 간단히 기록한 내용만으로도 최근 돌봄 여부, 담당자, 일정 완료 등 유용한 정보를 제공한다. 정확한 양이나 측정값이 없는 기록은 해당 수치를 미확인으로 두고, 통계를 위해 임의의 값이나 0을 채우지 않는다.
- 잘못 눌렀을 때 쉽게 취소·수정할 수 있게 한다. 상세 항목을 채우지 않았다는 이유로 반복해서 추가 입력을 재촉하지 않는다.
- 상태: 반영 예정. 실제 반복 사용 흐름을 기준으로 각 모듈의 최소 입력과 상세 입력을 재설계한다.

## 7. 주기에 맞춰 필요한 모듈만 노출

- 사용자 의견: 청소·미용 등 자주 기록하지 않는 활동까지 매번 화면에 보여줄 필요는 없다. 활성화한 모듈에 한해 사용자가 정한 간격이나 적용 가능한 권장 기간이 되면 자동으로 알려준다.
- 모듈 활성화와 화면 상시 노출을 구분한다. 주기가 긴 활동은 평소 ‘오늘’ 화면의 주요 영역을 차지하지 않고, 관리할 시점이 되면 필요한 항목으로 나타난다.
- 사용자가 활동별 반복 간격을 설정할 수 있게 한다. 같은 청소·미용 모듈 안에서도 세부 활동의 주기가 다를 수 있으므로 일괄적으로 주 단위로 고정하지 않는다.
- 권장 기간을 제공할 경우 대상 동물과 활동에 맞는 근거를 확인하고, 사용자가 자기 상황에 맞게 조정할 수 있게 한다. 확인된 권장 기간이 없으면 임의의 주기를 권장값으로 채우지 않는다.
- 시점이 된 활동은 팝업, 알림 또는 ‘오늘 할 일’ 등으로 보여준다. 구체적인 표시 형식은 후속 설계에서 정하며, 같은 항목이 반복해서 화면을 가리지 않게 한다.
- 알림에서 바로 완료를 기록하거나 미루기·일정 변경으로 이어질 수 있게 한다. 완료 뒤에는 다음 주기에 맞춰 다시 안내한다. 기록이 없다는 이유만으로 실제 돌봄을 하지 않았다고 단정하지 않는다.
- 평소에 숨겨진 활성 모듈도 필요하면 모듈 목록에서 직접 열어 기록할 수 있게 한다. 모듈을 끄면 해당 모듈의 주기 안내와 자동 노출도 중단한다.
- 상태: 반영 예정. 자주 쓰는 빠른 기록과 시점에 맞춰 나타나는 할 일을 함께 고려해 화면을 정리한다.

## 8. 루틴 화면의 정보·동작 배치 개선

- 사용자 의견: 이름과 아이콘은 왼쪽에, ‘기록하기’ 같은 동작은 오른쪽 끝에 떨어져 있어 같은 루틴의 정보와 행동이 자연스럽게 연결되지 않는다.
- 화면 전체 너비를 사용하는 긴 행을 반복하는 배치를 재검토한다. 루틴 이름, 일정·상태와 실행 동작이 하나의 묶음으로 읽히도록 가까이 배치한다.
- 카드·그리드 등 적합한 형식을 검토하고, 여러 루틴을 쉽게 훑어보고 원하는 루틴을 바로 기록할 수 있게 한다. 구체적인 열 수나 카드 형식은 아직 고정하지 않는다.
- 좁은 화면에서도 정보와 해당 버튼의 관계가 유지되게 한다. 빠른 기록 개선과 연결해 불필요한 화면 이동을 줄인다.
- 상태: 반영 예정.

## 9. 전체 기록 화면의 공간 활용과 가독성 개선

- 사용자 의견: 기록을 긴 행으로 쌓아놓아 가운데 빈 공간이 많고 화면 낭비가 심하다. 내용을 읽기 위해 시선을 멀리 이동해야 한다.
- 기록의 종류, 핵심 내용·수치, 시간·기록자를 읽기 좋은 간격으로 묶는다. 좌우 끝에 정보를 흩어놓거나 내용에 비해 과도하게 긴 행을 사용하지 않는다.
- 실제 기록을 비교하고 훑어보는 목적에 맞춰 간결한 표·목록·카드 등 적절한 형식을 검토한다. 모든 화면에 같은 그리드를 일괄 적용하는 것으로 해결하지 않는다.
- 날짜 순서와 필터의 맥락을 유지하고, 자세한 내용은 필요할 때 열어볼 수 있게 한다. 글자를 작게 줄이거나 정보를 억지로 채워 빈 공간을 없애지 않는다.
- 상태: 반영 예정.

## 10. 모듈·전체 기록·통합 상태의 역할 구분

- 사용자 의견: 모듈과 전체 기록이 보여주는 정보량과 표현 방식이 비슷해 두 화면의 차이를 체감하기 어렵다. 통합 상태까지 각 화면의 목적과 성격이 드러나도록 구성을 바꾼다.
- 현재 개별 모듈 화면과 전체 기록 화면은 같은 기록 목록 표현을 사용한다. 모듈 화면에 일부 요약값만 추가하는 정도로는 사용 목적이 충분히 구분되지 않는다.
- **모듈:** 활동 종류별 관리와 기록을 중심에 둔다. 사용 중인 돌봄 기능을 선택하고 빠르게 기록하며, 해당 활동에 필요한 상태·설정·상세 통계를 확인하는 화면으로 구성한다. 전체 기록을 모듈별로 필터링한 목록이 화면의 중심이 되지 않게 한다.
- **전체 기록:** 여러 모듈에서 발생한 일을 날짜·시간순으로 확인하는 이력 화면으로 구성한다. 언제, 누가, 무엇을 했는지 훑고 검색·필터로 과거 기록을 찾는 데 집중한다. 모듈 소개와 설정, 반복되는 요약 카드를 다시 나열하지 않는다.
- **통합 상태:** 여러 기록을 해석해 전체 관리 현황과 핵심 변화를 간결하게 보여주는 화면으로 구성한다. 개별 기록 목록이나 모듈별 관리 화면을 반복하지 않는다. 구체적인 재구성 방향은 3번 항목을 따른다.
- 동일한 기록 데이터를 공유하되 첫 화면의 정보 우선순위와 주요 행동은 목적에 맞게 구분한다. 모듈별 활동 관리 → 필요한 이력 조회, 통합 요약 → 상세 통계의 이동 관계가 자연스럽게 드러나게 한다.
- 상태: 반영 예정. 3번 통합 상태, 6번 빠른 기록, 9번 전체 기록 개선과 함께 반영한다.

## 11. 사이드바에 구성원 이름·역할 바로 표시

- ‘구성원·초대’ 메뉴를 ‘구성원’으로 바꾸고, 사이드바의 해당 제목 아래에 현재 방의 참여자 이름을 직접 표시한다. 별도 구성원 화면을 열기 전에도 누가 참여하고 있는지 볼 수 있게 한다.
- 현재 사이드바의 빈 공간을 활용해 참여자 정보를 배치하고, 함께 돌보는 사람들을 쉽게 확인할 수 있게 한다.
- 방장은 왕관 아이콘 등으로 구별하고, 관리자·일반 참여자·게스트도 이름 옆에서 역할을 알아볼 수 있게 한다. 구체적인 표시는 후속 설계에서 정한다.
- 참여자가 많을 때 사이드바를 과도하게 채우지 않도록 일부 표시와 더 보기·전체 보기 등 대체 방식을 검토한다. 기본 표시 인원은 아직 정하지 않았다.
- 참여자 확인과 초대 동작을 명확히 구분한다. 초대 버튼을 별도 위치에 둘지, 구성원 제목 옆에 둘지는 사용하기 편한 배치를 검토해 정한다.
- 사이드바 너비 조절·접기 기능과 함께 이름의 가독성, 많은 인원과 좁은 화면에서의 접근성을 고려한다.
- 상태: 반영 예정.

## 12. 첫 진입 화면의 빈 느낌 보완

- 사용자 의견: 사이트에 처음 들어왔을 때 화면이 지나치게 비어 보인다. 기존 구성을 바탕으로 첫인상을 보완한다.
- 테일리가 어떤 서비스인지, 어떤 도움을 받을 수 있는지, 어디서 시작하면 되는지가 자연스럽게 보이도록 소개와 시작 동선을 정리한다.
- 핵심 기능 소개나 실제 서비스 화면 미리보기 등 의미 있는 내용을 검토하고, 콘텐츠의 크기·배치·여백을 조절한다. 대규모 홍보 페이지로 확대하는 것은 이번 요청의 목적이 아니다.
- 화면 예시를 사용할 경우 실제 사용 데이터와 구분하고, 구현하지 않은 기능이나 근거 없는 성과를 소개하지 않는다.
- 상태: 반영 예정.

## 13. 전체 UI 구조 재설계와 Unslop 재점검

- 사용자 의견: 사이트 전반의 UI와 배열이 실제 사용자에게 적합하지 않고 획일적인 느낌이 강하다. 세부 디자인을 손보기 전에 전체 UI 구조부터 개선한다.
- 첫 진입 화면뿐 아니라 오늘, 모듈, 전체 기록, 루틴, 통합 상태, 구성원·설정 등 주요 화면을 함께 살핀다.
- 외부 사이트를 참고해 사이트 구성과 사용 흐름을 검토한다. 이를 바탕으로 전체 화면 구조를 먼저 정하고 각 수정 사항을 연결한다.
- 같은 긴 행과 반복 카드를 모든 화면에 적용하지 않고, 실제로 수행할 일과 읽을 정보에 맞게 배치한다. 자주 쓰는 동작, 정보 밀도와 화면 간 이동을 함께 개선한다.
- 앞서 정리한 구조·사용성 개선을 반영한 화면을 기준으로 여백, 정보 위계, 글자, 색상, 아이콘, 반복되는 카드·행과 버튼 배치를 다시 정돈한다.
- 테일리의 이름과 자연스럽고 담백한 문구를 일관되게 적용한다. 화면 목적에 맞는 차이는 살리되 공통 조작과 표현은 통일한다.
- 장식 변경만으로 끝내지 않고 사용자가 내용을 파악하고 바로 행동하기 쉬운지 확인한다. 이미 잘 작동하는 구성은 유지하고, 수정 후 주요 기능과 모바일 화면도 확인한다.
- Unslop 재적용 사실과 실제 변경 내용, 필요한 출처 표기는 개발 기록에 남긴다.
- 상태: 반영 예정. 전체 구조 재설계 → 기능·화면 개선 → Unslop 세부 정돈 → 실제 사용 흐름 검증 순서로 진행한다.

## 14. 모듈 추가·제거와 드래그 정렬 개선

- 사용자 의견: 현재 모듈 선택 화면은 전체 모듈과 온오프·정렬 조작이 섞여 있어 사용 중인 항목을 찾기 어렵고, 기대한 순서 변경도 작동하지 않는다.
- 왼쪽은 ‘넣은 모듈’, 오른쪽은 ‘전체 모듈’로 나누어 사용 중인 항목 관리와 추가할 항목 찾기를 구분한다. 적은 모듈만 사용하는 사람은 왼쪽의 해당 항목들만 보고 관리할 수 있게 한다.
- 왼쪽에서 모듈의 드래그 핸들을 잡아 위아래로 이동하면 다른 항목들이 실시간으로 자리를 옮기며 들어갈 위치를 보여주는 일반적인 목록 정렬 방식을 적용한다. 놓은 뒤 정한 순서가 저장되고 실제 모듈 배치에 반영돼야 한다.
- 지금의 위·아래 화살표 중심 조작을 드래그 중심으로 바꾸고, 순서 변경이 실제로 동작하는지 확인한다. 키보드·터치에서도 조절할 방법을 마련한다.
- 오른쪽에서 모듈을 추가하고 왼쪽에서 제거한다. 이미 넣은 모듈은 오른쪽에 ‘추가됨’으로 표시해 중복 추가를 막고, 제거하면 다시 추가할 수 있게 한다.
- 목록에서 제거하는 동작은 사용 중인 모듈 구성을 바꾸는 것이며 기존 기록을 삭제하지 않는다. 모듈 설정은 기존 방별 권한을 따른다.
- 좁은 화면에서도 두 목록의 역할이 구분되도록 배치를 조정한다. 구체적인 모바일 표현은 후속 설계에서 정한다.
- 상태: 반영 예정.
