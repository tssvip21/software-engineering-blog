# 테일리 4차 수정 계획

3차 개선 화면을 사용하며 모으는 피드백이다. 현재 6개이며, 실제 반영 전이다.

## 권장 작업 순서

아래는 의존관계를 고려한 권고안이다. 실제 구현 담당자가 현재 구조와 조사 결과를 보고 세부 작업과 순서를 조정할 수 있다. 중복 요구는 의도를 보존해 통합한다. 충분한 조사와 설계 판단을 거친 뒤 본격적인 제품 수정을 시작한다.

1. **현재 사용 흐름과 문제 확인:** 이번 피드백에 해당하는 화면·문구·분석 결과를 확인하고 개선 전 비교 기준을 남긴다.
2. **국내외 사례와 이론 연구:** UX, 자연스러운 한국어, 통합 상태의 분석·표현, 글자·색상·대비를 조사하고 실제 설계에 적용할 근거를 정리한다.
3. **공통 설계와 결과 정의:** 분류 중심 탐색, 화면 간 이동, 한국어 작성 기준, 종합 결과와 관련 데이터의 표현·입출력을 정한다. 구체적인 방법은 조사 결과로 판단한다.
4. **의존 기능과 분석 로직 개선:** 필요한 분석·조회·분류별 모듈 설정 처리를 먼저 정리하고 확인한다. 결과에 맞춰 화면을 연결할 수 있게 한다.
5. **문구 전면 재작성과 UI·UX 구현:** 공통 용어와 문장을 먼저 맞추고, 전체 기록·통합 상태·분류별 선택 창 등 화면과 조작을 연결한다. 다른 모든 화면의 서비스 문구도 빠뜨리지 않는다.
6. **세부 디자인 정돈:** 실제 문구와 정보량을 기준으로 글꼴·크기·굵기·대비·색상·간격을 조정한다.
7. **사용 흐름과 변경 영향 확인:** 대표 작업의 개선 전후를 비교하고, 기능·권한·기록 보존·모바일을 필요한 범위에서 확인한다. 결과와 한계를 정리해 검수로 넘긴다.

로컬 커밋은 의미 있는 실제 작업 단위로 남긴다. GitHub push·PR 생성·외부 게시·서비스 배포는 이번 실행 범위에 포함하지 않는다.

## 1. 사용자에게 보이는 용어·문장 전면 재작성

- 사용자 의견: 사이트 전반의 단어와 문장이 영어를 한국어로 그대로 옮긴 것처럼 어색하다. 문장은 딱딱하고 기계적이며, 용어 자체도 한국어 사용자에게 자연스럽게 읽히지 않는다. 이전 말투 개선으로 충분히 해결되지 않았다.
- 추가 의견: 화면을 읽는 것 자체가 불쾌하게 느껴질 정도이므로 일부 표현만 고치는 방식은 원하지 않는다. 사용자에게 보이는 문구 전체를 대상으로 다시 작성한다.
- 어미를 해요체로 바꾸는 수준을 넘어 단어 선택, 문장 구조와 정보 전달 방식을 전체적으로 다시 살핀다.
- 메뉴·화면 제목·버튼·입력 항목·도움말·상태 설명·분석 결과·오류 안내에 한국어 사용자가 익숙하게 이해할 수 있는 표현을 사용한다. 내부 개발 용어나 분석 용어를 그대로 화면에 노출하는 부분도 점검한다.
- 첫 화면부터 로그인·등록·초대·설정·모듈·루틴·기록·통합 상태까지 모든 사용 흐름을 포함한다. 빈 화면, 확인창, 툴팁, 저장·실패 안내와 코드에서 동적으로 생성하는 문구도 빠뜨리지 않는다.
- 한국어 표현 자체를 별도의 연구 대상으로 삼는다. 국내 서비스에서 실제 사용하는 메뉴·버튼·입력 안내·빈 화면·오류·결과 설명을 맥락과 함께 살펴보고, 자연스러운 용어 선택과 문장 구성 방식을 테일리에 반영한다. 국내 사례를 화면 배치 참고용으로만 사용하지 않는다.
- 영어 표현을 먼저 정한 뒤 한국어로 직역하는 흐름에서 벗어나, 한국어 사용자가 해당 상황을 어떻게 이해하고 표현하는지를 기준으로 작성한다. 짧고 명확한 동작 이름, 설명에 필요한 정보 순서, 익숙한 표현과 용어의 일관성을 함께 검토한다.
- 조사에서 정리한 한국어 작성 기준을 바탕으로 서비스가 제공하는 모든 문구를 다시 쓰고, 실제 화면과 연결된 사용 흐름에서 읽어본다. 종결어미 교체나 단어 몇 개의 치환만으로 완료 처리하지 않는다.
- 사람이 자연스럽게 설명하는 문장으로 다듬되, 과한 감성·칭찬·감탄이나 억지로 친근한 말투를 덧붙이지 않는다.
- 같은 기능은 일관된 용어로 표현하고, 기록·수치·권한의 의미는 정확하게 유지한다. 개별 문구뿐 아니라 실제 화면에서 이어 읽었을 때도 자연스러운지 확인한다.
- 상태: 반영 예정.

## 2. 모듈 중심 UX 이론 연구와 실제 사용 부담 개선

- 사용자 의견: UI의 외형은 이전보다 나아졌지만 UX는 여전히 만족스럽지 않다. 많은 모듈과 정보를 다루는 사용자의 탐색·선택·입력·설정 부담을 충분히 연구해 보완해야 한다.
- 전달받은 이전 작업의 자체 평가에서는 통합 상태의 통계 방법 조사·구현과 달리, 모듈 UX의 사용자 관점 이론 연구와 실제 사용자 사용성 확인이 부족했다고 설명했다. 이는 이번 보완의 배경이며, 4차에서 새로 수행한 검증 결과로 취급하지 않는다.
- 국내외 여러 서비스의 실제 사용 흐름과 관련 논문·연구·공식 지침을 함께 검토한다. 모듈형 서비스를 우선 살펴보되 많은 정보를 다루는 다른 분야까지 넓혀, 테일리의 문제에 적용할 수 있는 근거를 찾는다.
- 이론 이름이나 참고 사례를 나열하는 데서 끝내지 않는다. 각 설계 선택이 어떤 사용자 부담을 줄이려는지, 근거의 적용 조건과 한계가 무엇인지, 테일리에서 어떻게 확인할지를 연결한다. 특정 이론의 이름을 필수 구현 방법으로 고정하지 않는다.
- 대표 작업을 정하고 개선 전후의 탐색·선택·입력 단계, 불필요한 조작, 오류·되돌아감과 정보 이해의 어려움을 살핀다. 기능 작동 검사를 사용성 검증으로 대체하지 않는다. 개발자의 점검과 실제 사용자의 평가를 구분하고 수행하지 않은 사용자 연구를 했다고 기록하지 않는다.
- 국내 서비스 조사에서는 1번의 한국어 문구 연구도 함께 수행한다. 한국어 이해의 어려움과 화면·동선에서 생기는 불편을 함께 개선한다.
- 통합 상태도 3번에 따라 분석 로직과 UI를 함께 심층 재검토한다. 기존 연구·검증 자료를 출발점으로 삼되, 현재 방법이 실제 사용 목적에 적합한지는 새로 판단한다.
- 논문이나 연구를 참고했다는 사실만으로 실사용 타당성이 입증됐다고 하지 않는다. 실제로 확인한 개선과 남은 한계를 구분해 개발 과정에 남긴다.
- 상태: 조사·설계 보완 및 반영 예정.

## 3. 통합 상태를 쉬운 핵심 결과와 간략한 관련 데이터로 재구성

- 사용자 의견: 현재 통합 상태는 연구 결과를 설명하는 문서처럼 딱딱하고 복잡하다. ‘중앙값’, ‘실측’ 같은 용어와 분석 과정이 앞에 나와, 일반 사용자가 상태를 빠르게 이해하기 어렵다.
- 추가 의견: UI뿐 아니라 분석 로직 자체도 만족스럽지 않으므로, 통합 상태의 목적·분석 방법·결과 표현을 함께 더 깊이 연구해 개선한다.
- 사용자가 어떤 상황을 알아야 하고 그다음 무엇을 확인할 수 있어야 하는지부터 검토한다. 관련 논문·연구·공식 자료와 여러 분야의 실제 서비스를 살펴보고, 유용한 결과를 만드는 분석과 이를 이해하기 쉽게 전달하는 UI를 연결한다.
- 기존 알고리즘을 유지하는 것을 전제로 하지 않는다. 지표 선택, 관련 기록의 결합, 비교 기간, 자료 부족·상반된 변화 처리와 결과 도출이 적절한지 비교·검토한다. 실제 근거와 사용 목적에 따라 유지·보완·교체 여부를 구현 담당자가 판단한다.
- 계산이 코드대로 작동하는지와 그 결과가 사용자의 상태 파악에 유용한지를 구분해 확인한다. 정상적인 변화·중요한 변화·자료 부족 등 서로 다른 기록 상황에서 결과가 납득되는지, 놓치거나 과장하는 정보가 없는지 검토한다. 확인하지 않은 실사용 효과를 입증했다고 쓰지 않는다.
- 주화면에는 반려동물의 핵심 상태와 중요한 변화만 쉬운 한국어로 보여준다. 분석 과정·방법론·긴 설명을 결과와 함께 늘어놓지 않는다.
- 사용자 추가 의견: 선그래프와 수치를 직접 해석해야 현재 상태를 알 수 있는 구성은 불편하다. 처음 보는 사람도 현재 어떤 상태인지와 그 의미를 바로 파악할 수 있는 결과 표현이 필요하다.
- 사용자에게 계산·그래프 해석을 맡기지 않고, 분석 결과의 의미가 먼저 읽히도록 상태 표현과 시각화를 연구해 선정한다. 기존 선그래프를 유지하거나 대화에서 든 예시의 형식을 그대로 채택하는 것을 전제로 하지 않는다. 실제로 어떤 표현이 빠른 이해에 도움이 되는지 국내외 사례·연구와 사용 흐름을 바탕으로 판단한다.
- 그래프·수치는 결과를 이해하는 데 도움이 되는 위치와 수준에서 사용한다. 시각화의 복잡함이나 데이터 표시량을 개선의 성과로 삼지 않고, 사용자가 자기 반려동물의 상황을 바로 이해할 수 있는지를 기준으로 확인한다.
- 결과를 눌렀을 때는 그 판단과 관련된 날짜·기록값·기간별 변화 등 필요한 데이터만 간략하게 보여준다. 상세 영역에도 계산 과정이나 이론 설명을 넣지 않는다.
- 계산식·알고리즘·통계 방법의 설명은 개발 문서에서 관리한다. 일반 사용 화면에 별도의 계산 방법 설명창을 만드는 것으로 요구를 대신하지 않는다.
- 내부 분석은 필요한 정확성을 유지하되, 사용자에게 표현하는 단어와 정보량은 전문지식 없이도 이해할 수 있는 수준으로 다시 구성한다.
- 1번의 한국어 전면 재작성, 2번의 국내외 사례·UX 연구와 함께 진행한다. 기술 용어 몇 개를 바꾸는 수준을 넘어 결과·관련 데이터·사용 동선 전체를 개선한다.
- 상태: 재구성·반영 예정.

## 4. 전체 기록을 분류 중심으로 재구성

- 사용자 의견: 전체 기록을 날짜별로 먼저 묶어 보여주면 원하는 내용을 찾기 불편하다. 분류를 기준으로 기록을 살펴볼 수 있게 바꿔야 한다.
- 전체 기록의 기본 탐색과 화면 구성을 분류 중심으로 바꾼다. 기존 모듈 분류와 연결해 원하는 종류의 기록에 바로 접근할 수 있게 한다.
- 날짜는 선택한 분류의 기록에서 시점을 확인하거나 조회 기간을 좁히는 보조 정보로 사용한다. 날짜순 목록에 분류 필터만 덧붙인 채 기본 구조를 그대로 유지하는 것으로 완료하지 않는다.
- 여러 분류의 차이와 현재 선택한 범위가 바로 보이도록 구성한다. 분류를 바꾸거나 기록 상세를 확인한 뒤에도 탐색 맥락이 유지되게 한다.
- 이전 계획의 날짜 우선 이력 화면보다 이번 분류 중심 요구를 우선한다. 구체적인 배치와 조작은 2번 UX 연구와 함께 검토한다.
- 상태: 반영 예정.

## 5. 글자·색상·대비와 시각적 구분 재설계

- 사용자 의견: 글자 크기와 색상, 선명도가 비슷비슷해 중요한 내용이 눈에 들어오지 않는다. 요소를 쉽게 구별할 수 있으면서도 전체적으로 과하지 않은 디자인이 필요하다.
- 한국어에 맞는 글꼴과 크기·굵기·행간, 글자와 배경의 대비, 색상의 역할을 세밀하게 조사해 조정한다. 제목·핵심 상태·주요 수치·본문·보조 설명·조작 요소의 중요도와 기능이 시각적으로 드러나게 한다.
- 강조가 필요한 부분에 힘을 주고 나머지 요소는 읽기 쉬운 수준으로 정돈한다. 모든 글자를 크게·진하게 만들거나 많은 색상을 추가하는 방식으로 구분하지 않는다.
- 구분선·배경·선택 상태·아이콘도 함께 살펴 요소의 경계와 조작 가능 여부를 쉽게 파악할 수 있게 한다. 색상 하나에만 의미를 의존하지 않는다.
- 국내외 사례와 관련 디자인·가독성·접근성 자료를 조사하고 실제 화면에서 비교해 선택한다. 한국어 문구 전면 재작성과 정보 구조 개선을 반영한 상태에서 검토한다.
- 데스크톱과 모바일, 정보가 적은 화면과 많은 화면에서 글자가 흐릿하거나 핵심 내용이 묻히지 않는지 확인한다. 구체적인 글꼴·수치·색상은 조사와 화면 확인 후 정한다.
- 상태: 조사·디자인 조정 예정.

## 6. 분류 안에서 모듈 추가·제거

- 돌봄 모듈의 각 분류에서 관리 버튼을 눌러 작은 모달 선택 창을 연다. 모듈을 간단히 추가·제거하려고 다른 페이지로 이동하지 않게 한다.
- 선택 창에는 해당 분류에 속한 모듈만 표시한다. 사용 중인 모듈은 선택된 상태로 보여주고, 선택·해제로 추가하거나 뺄 수 있게 한다.
- 적용하면 선택 창을 닫고 현재 보고 있던 분류에 변경 결과를 바로 반영한다. 화면의 탐색 맥락을 유지한다.
- 전체 구성을 관리하는 기존 ‘모듈 구성’ 기능은 유지한다. 기존 모듈 설정 권한을 따르고, 목록에서 빼더라도 저장된 기록은 삭제하지 않는다.
