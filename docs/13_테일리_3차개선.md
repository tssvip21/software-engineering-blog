# 테일리 3차 개선 — 구현 결과와 검수 방법

2026-11-05. 수정 계획의 13개 항목을 로컬 구현에 연결했다. 외부 사이트의 구성과 사용 흐름을 참고해 분류·탐색·입력·근거 확인의 연결을 검토했다. 이 문서는 구현 결과이며 실제 구글 계정 연동, 임상 검증, 외부 배포 완료를 뜻하지 않는다.

## 이번 결과를 여는 방법

프로젝트 폴더에서 다음 명령을 실행한다.

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\run_phase3_preview.py
```

브라우저에서 `http://127.0.0.1:8013`에 접속한 뒤 ‘방장으로 보기’를 선택한다. 기존 실행 환경과 구분한 검수 주소다. 이미 실행 중이면 서버를 중복으로 켜지 않는다. 다른 포트가 필요하면 `--port 8015`처럼 명시할 수 있다.

검수 실행기는 기존 `data/demo.sqlite3`를 **처음 한 번만 복사**하여 `tmp/handoff/phase3/preview-data/demo.sqlite3`에서 사용한다. DB와 쿠키 이름, 정적 파일 경로도 별도다. 이후 실행에서는 검수 DB에서 입력한 내용을 유지한다. 원본 DB를 초기화하거나 기존 8000·8001 서버를 종료하지 않는다. 기존 서버가 떠 있더라도 이번 3차 검수에는 8013 주소를 사용한다.

현재 검수 복사본에는 원래 시연 공간과 별도로 ‘검수 예시 · 평소와 비슷함’, ‘검수 예시 · 함께 변한 기록’, ‘검수 예시 · 엇갈린 변화’를 준비했다. **기능을 확인하기 위한 가상 기록**이며 실제 돌봄 자료가 아니다. 각 공간의 통합 상태에서 평소 패턴·동시 변화·상반 신호의 차이를 확인할 수 있다. 새 PC에서는 자동 생성되지 않으며, 자동 검사 자체는 독립적인 가상 자료를 만들어 재현한다.

## 종합 상태 계산

`care/patterns.py`는 네트워크 없이 입력 기록에서 결과를 계산하며, `care/insights.py`가 현재 방의 열람 권한을 먼저 적용하고 화면과 근거 링크로 연결한다. 외부 언어모델 API나 생성형 AI 응답으로 결과를 작성하지 않는다.

최근 7일의 유효 관측 중앙값을 직전 28일의 개인 기준과 비교한다. 중앙값·MAD 기반 변화 탐색과 반복 관측 조건, 실제 날짜 차이를 사용하는 Theil–Sen 보조 기울기를 사용했다. 관련 지표가 함께 변하거나 방향이 엇갈리면 개별 수치를 단순 나열하는 대신 관계와 주의점을 설명한다. 현재·7일 전·달력 기준 1개월 전에도 같은 기간 정의를 적용한다.

**계산 원리의 출처와 서비스 설계값은 구분한다.** 지표별 변화 문턱값과 최소 관측일은 검증된 의학적 기준이 아니라 과한 표시를 줄이려는 조정 가능한 설계값이다. 이 결과는 기록된 생활 패턴의 변화이며 건강 진단·위험 확률·인과관계 판정이 아니다. 미기록은 0이나 미급여·미활동으로 간주하지 않는다. 자세한 선택 이유, 수식, 범위, 한계는 [종합 상태 분석 방법](12_종합상태_분석방법.md)에 있다.

수치가 거의 없으면 ‘비교 준비 중’으로 표시하되 현재 기록을 숨기지 않는다. 비교 가능한 일부 지표가 비슷하다고 다른 모든 상태도 정상이라고 쓰지 않는다. 한 번의 극단값은 지속 변화와 구별해 계산 근거에 남긴다. 제한된 기록을 분석 설명·그룹 이름·근거 링크로 유출하지 않도록 열람 범위를 먼저 제한한다.

## 품종과 참고 범위의 의미

초기 카탈로그는 주요 개 45종·고양이 39종이다. 모든 품종을 망라하지 않으며 목록에 없어도 직접 입력하거나 나중에 선택할 수 있다. 한글명·영문명·별칭으로 찾고, 검색하지 않고 목록을 스크롤해 고를 수도 있다. 스크립트가 꺼져 있으면 기본 선택 목록을 사용한다.

확인한 양쪽 경계가 있는 체중 참고 범위는 개 39종·고양이 3종이다. 단일 수치·상한만 있는 자료에 가상의 하한이나 평균을 만들지 않았다. 성별 자료가 분리돼 있으면 해당 범위를 쓰고, 미상이면 암수 범위를 함께 표시한다. **성장 완료를 확인한 경우에만** 성견·성묘 범위와 현재 측정값을 비교한다.

개의 체격은 확인된 품종 범위 전체가 한 탐색 구간에 들어갈 때만 제안한다. 소형 ≤10kg, 중형 >10~25kg, 대형 >25kg은 탐색용 설계 구간이며 보편적인 의학적 분류가 아니다. 경계에 걸치거나 자료가 없으면 직접 고르거나 비워 둔다. 제안한 값도 사용자가 변경할 수 있다. 고양이에는 개의 체격 분류를 강제하지 않는다. 믹스·품종 미상도 품종 범위를 추측해 채우지 않는다.

품종 범위와 BCS는 종합 판단 아래의 보조 영역이며, 보조 자료가 없어도 개체별 기록 분석은 작동한다. 출처와 조건은 해당 화면과 [분석 방법 문서](12_종합상태_분석방법.md)에 표시한다.

## 검증과 데이터 보존

2026-11-05 기준 자동 회귀 테스트 189개, 실제 Chromium 브라우저 검사 지점 26개, 11개 화면 × 6개 폭의 레이아웃 66개를 확인했다. 폭은 360·390·768·1024·1440·1920px이며 문서 전체 가로 넘침이 없었다. 모듈 6개와 20개를 사용하는 화면도 별도로 비교했다.

브라우저에서는 품종 한글·영문 검색과 저장, 믹스 직접 체격, 고양이 체격 처리, 분류·그룹 교차 탐색, 모듈·그룹의 마우스·터치·키보드 정렬, 빠른 저장·취소, 그룹의 네트워크 실패·재시도·동시 변경, 구성원 권한 조작과 서버 접근 차단을 확인했다. 터치는 브라우저의 터치 입력 기능으로 검증했으며 실물 휴대전화 전체 호환성을 뜻하지 않는다.

자동 검사에는 정상 유사 패턴, 한 지표 변화, 여러 관련 변화, 상반 신호, 기록 부족, 실제 0과 누락, 단위 환산, 같은 날 중복, 극단값, 월말·기간 경계, 취소, 게스트·타 방 권한, 표시 그룹을 바꿔도 분석 결과가 같은지, 분석 중 외부 네트워크 호출 차단을 포함한다.

원본 DB 두 개의 복사본에서 마이그레이션과 백업 복원·재마이그레이션을 검사했다. 각각 기존 23개 테이블의 원래 열과 행 값을 비교해 변경이 없었다. 실제 원본에는 해당 검증을 실행하지 않았고, 사용자 기록을 가상 사례로 덮어쓰지 않았다.

재검사 명령:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\verify_phase3.py
.\.venv\Scripts\python.exe -X utf8 scripts\verify_phase3.py --browser
```

두 번째 명령은 8014번 포트를 사용하며, 실행마다 새 임시 DB에서 기록을 만들고 확인한다. 사용 중인 포트를 임의로 종료하지 않는다. 상세 로그·스크린샷은 `tmp/handoff/phase3/`에만 저장한다. 자동 테스트 통과는 임상 성능·사용자 효용·실계정 인증·외부 배포의 검증과 구분한다.

## 실제로 고친 오류와 추가 점검

최종 사용 흐름 검사에서 빠른 기록을 저장하면 화면 교체와 함께 선택한 분류·그룹·검색이 초기화되는 문제를 재현했다. 같은 페이지의 화면 교체에서 선택을 복원하되 현재 권한에서 사라진 그룹은 복원하지 않도록 수정했다. 저장과 취소 양쪽에서 같은 조건이 유지되는지 실제 브라우저로 재검사했다.

초기 연결 과정의 품종 자동 체격 초기값, 구성원 폼의 `action` 값과 URL 충돌, 정렬의 첫 항목 Home 키 경계, 시간대 전환 시 경과시간 계산도 수정·검증 범위에 포함했다. 실패를 성공 결과로 덮어쓰지 않고 각 검사 로그를 로컬에 보관했다.
