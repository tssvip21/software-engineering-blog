# [기획 기록] 테일리 — 화면 정리에서 실제 상태 분석으로

> 2026-11-04 · 3차 개선 논의 초안. 앞부분은 사용자가 2차 화면을 보고 제시한 피드백과 변경 방향이다. 11월 5일 구현·확인 과정은 아래에 별도로 이어 적었다. 아직 게시하지 않은 초안이다.

## 직접 사용하니 남아 있던 불편

모듈 구성의 점 6개 드래그 핸들이 흐릿해 조작부를 알아보기 어려웠다. 같은 기능의 위·아래 화살표는 제거하고, ‘빼기’는 의미를 알아볼 수 있는 아이콘으로 바꾸도록 요청했다. 구성원 이름 옆에도 더보기 메뉴를 두어 방장이 권한 변경과 내보내기를 바로 할 수 있게 하려 한다.

돌봄 모듈과 전체 기록은 내용에 비해 가로로 긴 행이 세로로 반복됐다. 여러 모듈을 활성화하면 아래까지 훑어야 했고, 항목 안의 공백은 큰데 필요한 정보는 한눈에 들어오지 않았다. 루틴의 날짜 입력도 너무 넓고, 주요 동작은 관련 내용에서 멀리 떨어져 있었다. 여백을 조금 줄이는 수준을 넘어 화면 배치와 동선을 다시 검토할 필요가 있었다.

## 모듈이 많을 때 사용자가 떠안는 부담

검색만으로 원하는 모듈을 찾게 하기보다 기본 분류를 제공하고, 사용자가 원하는 그룹도 만들 수 있게 하자는 의견이 나왔다. 분류는 이름이 비슷한 기능을 묶는 데서 끝내지 않고, 식사·간식·체중·활동처럼 함께 살펴볼 기록의 관계도 고려하기로 했다.

모듈형이라는 형식에만 매이지 않고, 많은 정보를 효율적으로 배치하는 방법을 넓게 검토하기로 했다. 필요한 정보와 동작이 잘 보이면서 사용자가 모든 설정을 직접 정리해야 하는 부담은 줄이는 것이 목표다.

## 통합 상태에 기대한 것은 따로 있었다

2차의 통합 상태는 개별 요약 네 가지를 우선 보여주는 구성이었다. 사용자가 원한 것은 일부 모듈을 골라 보여주는 화면이 아니라, 여러 기록을 함께 분석해 현재 반려동물의 상황과 그 이유를 알려주는 기능이었다.

이에 체중 변화, 식사 간격과 활동 기록 등의 관계를 분석하는 내부 기능을 설계하기로 했다. 계산 방법은 구현 담당자가 관련 이론과 방법론을 조사해 선택한다. 완성된 서비스는 외부 언어모델 API를 호출하지 않고 구현된 코드로 상태를 계산한다. 기록이 부족한 것과 실제 활동이 없었던 것도 구분해야 한다.

분류별 평균·참고 범위 비교는 별도 보조 정보로 두기로 했다. 현재 상태를 파악하는 주된 기능은 개별 반려동물의 기록을 바탕으로 작동해야 한다.

## 개·고양이의 품종 정보도 연결하기

체격이나 품종별 참고 자료가 있다면 API가 없어도 정리해 사용할 수 있다는 방향을 정했다. 등록할 때 국가 선택 목록처럼 품종을 스크롤하거나 한글·영문으로 검색해 고르는 방식도 제안했다.

품종 선택 후 체격을 자동으로 연결하고 믹스·품종 미상은 직접 선택하게 하는 아이디어가 있었지만, 모든 개와 고양이에게 같은 규칙을 적용해도 되는지는 추가 검토가 필요하다. 이 부분은 구현 담당자가 자료와 사용 흐름을 확인해 판단하도록 맡겼다.

## 구현 순서는 의존관계에 맞춰

화면을 먼저 완성한 뒤 계산 방식이나 데이터 구조 때문에 다시 만드는 일을 줄이고 싶었다. 그래서 공통 분류와 분석 입출력을 먼저 검토하고, 실제 결과에 맞춰 UI를 설계하는 순서를 제안했다. 실제 작업은 구현 담당자가 더 세분화하거나 순서를 조정할 수 있게 하고, 의미 있는 변경 단위로 커밋을 남기기로 했다.

이후에는 선택한 방법, 실제 바뀐 동작과 화면, 확인한 결과와 남은 한계를 이 논의 기록에 이어서 정리할 예정이다.


## 11월 5일 — 실제로 연결한 방식

외부 사이트의 구성과 사용 흐름을 참고하되, 화면을 그대로 닮게 만들기보다 같은 기록을 어떻게 찾고 행동으로 연결할지 검토했다. 사용자가 제안한 분류·그룹의 방향을 바탕으로 구현 담당자가 기본 분류와 그룹 저장 방식을 정했다. 기본 분류는 검색을 몰라도 활동을 찾게 하고, 사용자가 만든 그룹은 화면 정리만 바꾼다. 그룹 이름을 바꿨다는 이유로 분석 기준이 달라지지 않게 했다.

분석은 별도 API에 문장을 요청하는 대신 기록을 입력받아 결과를 내는 코드로 만들었다. 최근 7일을 직전 28일과 비교하고, 중앙값·MAD와 반복 관측으로 차이를 찾은 뒤 관련 지표의 변화를 연결했다. 실제 날짜 간격을 쓰는 기울기는 보조 근거로 사용했다. 이 방법과 적용 조건은 구현 담당자가 비교·선정했으며, 사용자가 특정 알고리즘이나 문턱값을 처음부터 지정한 것은 아니다. [분석 방법과 출처](../../docs/12_종합상태_분석방법.md)에 수학적 근거와 서비스 설계값을 구분했다.

평소와 비슷한 기록, 체중만 변한 기록, 급여·체중·활동이 함께 변한 기록, 방향이 엇갈린 기록, 날짜나 수치가 부족한 기록은 서로 다른 결과와 설명을 만들도록 검사했다. 임상 검증을 한 것은 아니므로 건강 점수나 위험 확률로 표시하지 않았다. 모르는 양을 0으로 넣지 않고, 제한된 기록이 다른 참여자의 결과에 나타나지 않도록 권한을 먼저 적용했다.

품종은 개 45종·고양이 39종의 한글·영문 선택 목록으로 시작했다. 모든 품종에 자동 체격을 넣는 대신, 확인된 개의 성견 범위가 한 구간 안에 있을 때만 제안한다. 고양이·믹스·품종 미상에 같은 기준을 강제하지 않는다. 자료가 없어도 등록과 기록이 가능하고, 참고 범위 비교는 종합 결과 아래의 별도 기능으로 두었다.

## 실제 화면에서 다시 발견한 문제

처음 연결한 화면에서는 빠른 기록 저장이 성공하면 본문을 새로 받아왔지만, 사용자가 고른 분류·그룹·검색 조건이 함께 초기화됐다. 저장 여부만 검사하면 놓칠 수 있는 문제였다. 브라우저에서 이 실패를 재현하고, 같은 페이지의 본문을 교체할 때 현재 허용되는 탐색 조건을 복원하도록 수정했다. 실행 취소 뒤에도 조건이 유지되는지 확인했다.

그룹 저장 요청이 끊기면 이름과 선택 항목이 남아 있어야 하고, 다른 참여자가 먼저 저장했다면 그 구성을 덮어쓰면 안 된다. 실패 후 재시도와 두 탭의 동시 수정으로 이 동작을 확인했다. 정렬은 DOM 순서를 강제로 바꾸는 검사뿐 아니라 실제 마우스·키보드·터치 입력으로 이동하고 새로고침 뒤 순서가 남는지 확인했다.

초기 연결 중에는 품종의 자동 체격 초기값과 구성원 폼의 요청 주소 처리도 고쳤다. 이미 있던 시간 계산에서는 일광절약시간 전환을 통과할 때 화면 시각의 차이가 아니라 실제 시각의 차이를 써야 하는 경우를 추가 검사했다. 기존 기록과 권한의 보존은 실제 DB가 아닌 복사본에서 마이그레이션과 복원으로 확인했다.

## 화면 정돈과 현재 범위

구조를 연결한 뒤 Damir Sokolovsky (@heydamir)의 **Unslop**을 다시 활용했다. 기본 분류 묶음, 짧은 이력, 가까운 동작을 살리고 같은 크기의 그래프·관계 카드를 반복하는 배치를 줄였다. 색상을 늘리기보다 중요한 추세 하나와 판단 근거를 구별했다. 원본·사용 커밋·CC BY 4.0 표기는 [출처 문서](../../THIRD_PARTY_NOTICES.md)에 유지했다.

최종 코드의 자동 회귀 테스트는 189개, 브라우저 확인 지점은 26개를 통과했다. 6개 화면 폭에서 주요 11개 화면의 가로 넘침을 확인했고, 모듈 6개와 20개를 사용하는 화면도 비교했다. 이런 검사는 구현한 동작의 확인이지 실제 사용자 만족도나 의학적 정확도 검증은 아니다.

현재는 별도 로컬 검수 화면과 로컬 커밋까지 정리했다. 실제 구글 계정 연결, 실물 휴대전화의 최종 사용감, 기록량에 따른 분석 안내의 효용 평가는 남아 있다. GitHub 업로드·PR·외부 게시·서비스 배포는 이번 작업에서 하지 않았다.
