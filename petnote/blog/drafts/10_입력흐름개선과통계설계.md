# [개선 10] 같은 기록을 더 짧은 흐름으로 남기기

> 2026-11-12 작업 초안. 공개 게시 전 검토용이다. 화면·입력 흐름 개선과 아직 확인받지 않은 통계 설계안을 구분해서 기록했다.

## 이번 수정의 출발점

기능이 저장되는 것과 실제로 사용하기 편한 것은 달랐다. 오늘 화면의 빠르게 기록에서는 글이 길어지면 버튼이 다른 높이로 밀렸고, 돌봄 기능 쪽에서는 하단에 정렬돼 있었다. 같은 일을 하는 두 화면이 서로 다른 규칙을 가진 셈이었다.

구성원 이름을 눌러 열리는 권한 설정도 정보와 조작이 한꺼번에 나열돼 있었다. 여러 링크가 밑줄로 강조되고, 루틴 한 항목은 오른쪽까지 길게 늘어나 내용보다 빈 공간이 많았다. 기록이나 루틴을 입력할 때마다 별도 페이지로 이동하는 점도 불편했다.

이번에는 범위를 나눴다. 버튼·권한 화면·입력 모달과 같은 사용 흐름은 먼저 구현하되, 통계의 산식과 정보 구조는 근거와 구체적인 안을 정리하고 사용자 확인을 받은 다음 구현하기로 했다. 이 구분 없이 다시 전체를 바꾸는 일을 피하기 위해서다.

## 카드 하나가 아니라 같은 행동의 규칙을 맞췄다

빠르게 기록과 돌봄 기능의 액션 부분을 공유하게 했다. 기본 설정과 보조 정보, 상태 메시지 다음에 주 행동을 두고, 카드 전체를 세로 구조로 만들어 버튼이 하단에 남게 했다. 한 행에 텍스트 길이가 다른 카드가 섞여도 주 버튼의 위치를 비교할 수 있게 검사했다.

루틴은 화면이 넓다고 무조건 한 줄 전체를 점유하지 않도록 폭과 열 배치를 정했다. 통계도 특정 모듈 이름이라는 이유만으로 두 열을 차지하던 규칙을 제거했다. 다만 이 조정은 공간 활용에 대한 것이고, 통계가 답하는 질문이나 계산법을 개선한 것과는 별개다.

호버에서는 이름과 근거 링크에 항상 표시되던 밑줄을 줄이고, 실제로 가리킨 링크만 강조했다. 마우스 장식만 바꾸고 끝내지 않고 키보드로 선택한 위치가 보이는지도 확인했다.

## 입력창을 바꿔도 저장 규칙은 그대로 남겼다

새 기록, 기록 수정, 루틴 등록·수정, 저장 설정 편집은 현재 화면 위에 모달로 열린다. 데스크톱에서는 폼이 지나치게 길어지지 않게 최대 폭을 제한했고, 모바일에서는 내용만 스크롤하면서 취소·저장 버튼이 보이게 했다. 기존 주소로 직접 들어오는 단독 입력 화면도 없애지 않았다.

입력창에 새 저장 로직을 따로 만들지는 않았다. 기존 Django 폼의 검증과 권한·수정 이력을 그대로 쓰면서, 같은 주소에서 모달용 HTML 조각이나 저장 결과를 반환하게 했다. 화면만 분리하고 데이터 규칙이 달라지는 문제를 피하기 위한 선택이었다.

저장이 끝나면 원래 화면을 갱신하되 검색어·분류·펼친 내용·스크롤 위치를 유지하도록 했다. 닫힌 뒤에는 입력창을 연 버튼으로 초점을 돌려준다. 작성하다 ESC를 누르면 입력을 버릴지 같은 창에서 확인한다. W3C의 모달 상호작용 안내도 이러한 키보드 범위와 초점 복귀를 강조한다.[1]

## 네트워크 오류를 성공과 구별했다

복잡했던 경우는 서버가 이미 기록을 저장했는데 응답만 끊기는 상황이었다. 이때 새 요청 번호로 다시 저장하면 동일한 돌봄이 두 번 남을 수 있다.

입력 모달은 전송한 내용과 요청 식별자를 보존하고, 결과가 불확실할 때는 입력값을 바꾸기보다 같은 요청의 결과를 다시 확인하도록 했다. 유효성 오류는 같은 폼에 표시하고 입력을 유지한다. 브라우저 검증 중 영문 연결 오류가 그대로 노출된 사례는 한국어 안내로 수정한 뒤 응답 유실·재시도를 다시 시험했다.

재개 검수에서는 느리게 열리는 입력창을 닫고 다른 창을 바로 열 때 이전 응답이 새 창을 덮는 오류와, 새 창의 타임아웃이 사라지는 오류도 찾았다. 취소 상태를 요청별로 나누고 본문을 받은 뒤에도 현재 창이 맞는지 확인하도록 수정했다. 수정 전 실패한 두 상황을 다시 재현해 통과하는지 확인했다.

검사 스크립트가 끝났다는 사실만으로 충분하다고 보지 않고, 실제 DB에서 기록 수가 하나인지도 대조했다. 저장 성공을 알리기 위한 별도 모달은 만들지 않았다. 성공은 토스트, 입력 오류는 해당 폼의 안내, 위험한 접근 해제는 별도의 확인으로 역할을 나눴다.

## 권한 관리와 시연 공간을 정돈했다

구성원 이름과 더보기 메뉴는 같은 패널을 연다. 자기 화면에는 표시 이름과 일정 안내 설정, 다른 사람의 화면에는 역할 정보와 가능한 역할 변경을 보여준다. 내보내기는 접힌 접근 관리 구역으로 분리했다. 방장만 권한을 바꿀 수 있는 기존 규칙은 그대로다.

시연용으로 만들어 둔 여러 공간은 일반 목록에서 강아지·고양이·앵무새 세 가지를 먼저 보여주고, 빈 기록이나 이전 검수 공간은 추가 검수 목록에서 찾게 했다. 자료를 삭제한 것이 아니고, 실제 사용자가 만들 수 있는 반려동물 수를 세 마리로 제한한 것도 아니다.

## 통계는 왜 바로 다시 계산하지 않았나

체중의 이전 6일 평균과 최근 2일 평균을 크게 비교하거나, 간식 한 건에 빈 이전값과 큰 비교판을 붙이는 문제는 카드 크기를 줄이는 것만으로 해결되지 않는다. 먼저 각 모듈의 질문을 정해야 한다.

작성한 설계안에서는 체중의 실제 측정시각·간격과 최근성을 앞에 놓고, 간식은 제공 횟수와 제품별 확인 가능한 양을 먼저 보여준다. 제공한 양과 먹은 양은 다른 기준이다. 기록이 있는 날이 곧 그날의 모든 급여를 빠짐없이 기록한 날도 아니다. 공식 영양 기록 도구 역시 이 두 상태를 분리한다.[2]

관계 영역도 ‘체중과 급여 숫자를 나란히 놓기’에서 더 나아가, 선택한 측정 사이에 제품·급여 설정·생활 조건이 실제로 바뀐 사건을 찾아주는 방향을 제안했다. 다만 기존 기록에서 새 설정을 처음 확인한 날과 실제로 급여 방식을 바꾼 날은 다를 수 있다. 이력이 없는 과거 날짜를 만들어 채우지 않고, 실제 변경시각을 보존할 추가 구조도 승인 후에 적용하기로 했다. 같은 기간에 있었다는 사실과 원인도 구별한다. 기록 당시의 나이·상태를 모르면 현재 상태를 과거에 그대로 적용하지 않는다.

전체 18개 선택 모듈과 과거 두 기록 유형, 일곱 관계 후보를 검토했고 독립적인 산술 예시도 만들었다. 이것은 **설계안 검산**이지 새 통계 기능이나 건강 해석의 검증 완료가 아니다. 현재 통계 산식과 모델은 사용자 확인 전 그대로 유지했다.

## 확인한 것과 남은 것

자동 검사와 Chromium·Firefox의 실제 화면에서 반응형 배치, 모든 선택 모듈의 입력 모달, 키보드 조작, 오류 복구, 연타·응답 손실 재시도, 역할별 노출을 확인했다. 통계의 효과나 실제 보호자의 장기간 사용성을 입증한 것은 아니다.

현재 결과는 **사용 흐름 개선 구현 + 통계 구조 설계안**이다. 통계의 주요 지표와 관계 표현을 바꿀지는 확인을 받은 뒤 진행한다. 화면 잠금 중 GPS 수집이나 휴대전화 OS 푸시는 이번 작업으로 해결했다고 쓰지 않는다. 작업물과 검수 환경은 로컬에 두고, 기존 사용자 파일과 원본 DB를 보존했다.

더 자세한 적용 범위·계산 예시·근거는 [사용 흐름 개선과 통계 설계안](../../docs/22_사용흐름개선과통계설계안.md)에 모았다. 기존에 기록한 외부 디자인 도구의 출처·라이선스 표기는 유지하며, 이 글에서는 새로 사용하지 않은 도구를 사용했다고 적지 않는다.
