# 펫노트 프로젝트 딕셔너리

## 기능 범위

사용자가 선택하는 돌봄 기능은 18개다. 예전 기록을 읽기 위해 남겨 둔 두 종류(미용, 생활 변화)까지 포함하면 코드에 등록된 기록 종류는 20개다. 실제 목록은 `care/modules.py`의 `SELECTABLE_MODULES`에서 확인할 수 있다.

| 사용 흐름 | 기능 |
|---|---|
| 먹이와 활동 기록 | 먹이·급여, 간식, 물 관리, 배변, 산책, 놀이, 훈련 |
| 건강과 생활 관찰 | 체중, 위생·손질, 투약, 특이사항 메모, 병원·예방접종, 수면·휴식, 사육환경, 탈피·털갈이 |
| 용품과 비용 관리 | 용품·재고, 지출 |

인증, 권한, 루틴, 통계는 여러 돌봄 기능이 함께 쓰는 코드다. 요청 처리는 `care/views/`, 권한과 저장 업무는 `care/services/`, 통계 계산은 `care/reporting/`에서 찾을 수 있다.

## 실행 구조

현재 공개 서비스는 Vercel에서 Django를 실행하고 Supabase PostgreSQL에 기록한다. Docker 환경에서는 `frontend`(Caddy)가 정적 파일을 보내고 일반 요청을 `backend`(Django)에 전달하며, Django가 `db`(PostgreSQL)를 사용한다. Python 단독 시연은 실제 데이터와 분리한 SQLite를 쓴다.

| 위치 | 역할 |
|---|---|
| `care/views/` | 요청·폼·응답 처리, URL에 연결되는 화면과 API |
| `care/services/` | 공간·구성원·초대·기록·루틴의 권한 확인과 변경 업무 |
| `care/inventory/` | 물품 입력·단위·포장 정보·재고 원장 계산 |
| `care/reporting/` | 기간별 통계·비교·상태 계산과 근거 |
| `care/presentation/` | 대시보드·타임라인·기록 카드·탐색에 전달하는 데이터 구성 |
| `care/forms.py`, `care/modules.py` | 공통 입력 폼과 돌봄 기능 정의 |
| `care/models.py`, `care/migrations/` | 저장 항목과 관계, DB 구조 변경 이력 |
| `care/tests/` | 권한·입력·조회·동시성·성능·응답 회귀 테스트 |
| `config/`, `care/urls.py` | Django 설정, DB·세션·오류 처리와 URL 연결 |
| `templates/`, `static/care/` | 화면·스타일·브라우저 동작 |
| `deploy/docker/`, `compose*.yaml`, `Dockerfile` | 컨테이너·Caddy·상태 검사·서버 초기 설정 |
| `deploy/vercel/` | 소스 패키징, 빌드 검사, 검증 후 운영 전환 |
| `deploy/backup/` | PostgreSQL 백업·복원 확인·정기 실행 설정 |
| `deploy/source_files.py` | 두 배포 방식이 공유하는 애플리케이션 파일 선택 |
| `scripts/`, `scripts/qa/`, `scripts/tests/` | 개발 실행 명령, 브라우저 검사, 실행 도구 회귀 테스트 |

`views`는 요청의 입력을 읽고 업무 함수를 호출해 응답한다. 업무 코드는 화면 모듈을 가져와 사용하지 않는다. 화면에서만 필요한 표현은 `presentation`에 두고, 모델과 마이그레이션은 Django가 찾는 기존 위치를 유지한다.

## 업무별 시작점

| 찾는 코드 | 위치 |
|---|---|
| 로그인·세션 | `views/auth.py` |
| 상태 확인·오류 응답 | `views/system.py` |
| 공간 생성·목록·활성 상태 | `views/rooms.py`, `services/rooms.py` |
| 구성원·초대·참여 | `views/members.py`, `services/memberships.py` |
| 공간 접근과 역할 확인 | `services/access.py` |
| 기록 입력·수정·취소 | `views/records.py`, `services/records.py` |
| 빠른 기록과 재시도 | `views/dashboard.py`, `services/record_actions.py`, `services/idempotency.py` |
| 기록 검색과 분류별 미리보기 | `views/browsing.py` |
| 루틴 설정·완료 | `views/routines.py`, `views/completion.py`, `services/routines.py`, `services/completion.py` |
| 주기 안내와 일정 | `views/interactions.py`, `services/cadences.py`, `services/schedule.py` |
| 물품·재고 | `views/workspace.py`, `services/products.py`, `inventory/` |
| 공간 설정·개인 선호 | `views/workspace.py`, `services/profiles.py` |
| 통계·종합 상태 | `views/dashboard.py`, `reporting/`, `presentation/overview.py` |

`care.services`의 기존 공개 함수는 패키지 진입점에서 명시적으로 제공한다. 내부 구현은 담당 모듈에서 관리하며 같은 업무를 여러 파일에 복사하지 않는다. `views`는 담당 모듈의 함수를 URL에 직접 연결한다.

## 사용 흐름

아래에서 `R`은 `/rooms/<공간 ID>`다. 한 공간이 반려동물 한 마리를 나타낸다. 주소에 들어가는 ID와 별도로 서버가 현재 사용자의 공간 참여 여부와 역할을 확인한다.

| 사용자가 하는 일 | 주소와 방식 | 처리 코드 | 주요 저장 항목과 권한 |
|---|---|---|---|
| 로그인·내 공간 목록 | POST `/auth/google/start/`, GET 콜백·`/` | views.auth, views.rooms.home | GoogleAccount와 사용자, 활성 Membership. 개인 세션으로 목록 조회 |
| 반려동물 등록 | GET·POST `/rooms/new/` | views.rooms, services.rooms | Room, 방장 Membership, 기본 ModuleSetting과 설정 이력. 로그인 필요 |
| 구성원 초대·참여 | POST `R/invitations/new/`, `/join/preview/`, `/join/confirm/` | views.members, services.memberships | Invitation의 만료·사용 조건 확인 후 Membership 생성 |
| 오늘 화면·빠른 기록 | GET `R/`, POST `R/actions/` | views.dashboard, services.record_actions | Activity에 활동·시간·상태·입력값 저장. ActionReceipt로 같은 작업의 재시도 구분 |
| 직접 입력·수정·취소 | GET·POST `R/modules/<활동>/new/`, `R/records/<기록>/edit/`, POST 취소 | views.records, forms, services.records | Activity, ActivityRevision. 활성 기능·작성 권한·수정 버전 확인 |
| 기록 검색·조회 | GET `R/records/`, `R/records/<기록>/` | views.browsing, views.records | 공간과 공개 범위 안에서 분류·검색어·기간·작성자·상태로 조회 |
| 일정 등록·완료 | GET·POST `R/routines/new/`, `R/routines/items/<항목>/complete/` | views.routines, views.completion, services.completion | Routine과 RoutineItem, 시점별 RoutineVersion, 날짜별 RoutineRun 및 연결된 Activity |
| 물품·재고 | GET `R/supplies/`, GET·POST `R/products/new/` | views.workspace, inventory, services.products | Product의 단위·포장 정보와 Activity의 입출고·사용량으로 잔량 계산 |
| 측정값 비교 | GET `R/overview/`, `R/modules/<활동>/statistics/` | views.dashboard, reporting | 권한이 있는 기록의 단위·기간별 집계 |
| 프로필·공간 설정 | GET·POST `R/settings/`, `R/preferences/` | views.workspace, services.profiles | Room의 공동 설정과 Membership의 개인 설정. 민감 기록 공개 여부는 방장이 변경 |

운영의 Google 로그인, PC의 시연 계정, 자동 검사의 가상 사용자는 서로 다른 로그인 경로다. 시연 계정 선택기는 PC의 로컬 시연 모드에만 표시된다.

## 실행 명령과 보존 범위

`scripts/run_local.py`, `scripts/check.py`, `scripts/backup.py`와 바탕화면 서버 관리 명령은 기존 경로를 유지한다. Docker 관련 설정은 `deploy/docker/`, Vercel 배포는 `deploy/vercel/deploy.py`, PostgreSQL 백업은 `deploy/backup/`에서 관리한다. 실제 명령은 [개발·실행·백업](development.md), [자동 검사](testing.md), [배포와 운영](21_배포와운영.md)을 따른다.

구조 정리는 URL·모델·마이그레이션·화면·블로그를 바꾸지 않는다. 과거 설계·배포 기록에서 사용하는 이전 파일명은 당시 설명이며, 현재 코드를 찾을 때는 위 표를 기준으로 한다.
