# 테일리 2차 개선 — 구현과 확인 방법

2026-11-04. 1차 구현을 유지하면서 화면 역할과 기록 흐름을 다시 연결했다. 외부 사이트의 구성과 사용 흐름을 참고하고, 테일리의 개인·공동 돌봄 상황에 맞춰 설계했다. 공개 서비스 배포와 실제 구글 계정 검증은 별도 단계다.

## 화면별 역할

‘오늘’은 지금 수행할 돌봄과 빠른 기록, ‘돌봄 모듈’은 활동별 기능 관리, ‘전체 기록’은 날짜별 이력, ‘통합 상태’는 여러 기록의 의미와 기간 비교를 담당한다. 화면마다 같은 모듈 카드 전체를 반복하지 않는다. 자세한 설계 이유는 [화면 구조와 사용 흐름](history/09_화면구조와사용흐름.md)에 정리했다.

## 한 번의 기록이 반영되는 곳

빠른 기록도 기존 `Activity`와 방별 저장 서비스를 사용한다. 별도 완료 표시만 저장하는 구조가 아니다. 동일한 기록이 오늘, 루틴 연결, 전체 이력, 개별 통계와 통합 상태에 반영된다. 취소는 원본 삭제가 아니라 취소 표시와 수정 이력을 남긴다.

산책은 시작할 때 한 건을 만들고 종료할 때 같은 기록을 갱신한다. 재시도는 같은 요청 키를 사용하므로 같은 입력이 중복 생성되지 않는다. 저장소나 연결 문제로 응답이 실패하면 입력을 보존한다. 다른 구성원이 먼저 바꾼 기록·모듈 구성은 버전 충돌을 알리고 덮어쓰지 않는다.

## 활성화·오늘 고정·활동 주기

세 설정은 서로 다른 의미다. 모듈 활성화는 기능 사용 여부, 오늘 고정은 자주 쓰는 기록 동작의 배치, 주기 안내는 특정 활동의 다음 시점이다. 모듈을 제거해도 기록은 남고, 다시 넣으면 기존 이력과 통계를 볼 수 있다.

반복 간격과 첫 안내일은 사용자가 정한다. 일·주·개월 단위를 지원하며 개월은 달력 기준으로 계산한다. 예를 들어 1월 31일에서 한 달 뒤는 2월의 마지막 날이다. 의료적으로 권장되는 간격을 임의로 제시하지 않는다.

주기를 만든 뒤 해당 활동의 유효한 완료 기록이 생기면 다음 안내일을 계산한다. 취소하면 남은 완료 이력으로 다시 계산한다. 이번 안내를 미루는 동작은 반복 간격을 바꾸지 않는다. 주기 또는 모듈을 끄면 오늘 안내를 멈춘다. 기록이 없다는 이유만으로 실제 돌봄을 빠뜨렸다고 판정하지 않는다.

## 숫자의 의미

급여량과 활동 시간을 모르면 완료 여부만 기록할 수 있다. 비어 있는 측정값을 0으로 채우지 않고, 측정값 합계와 평균의 분모에서 제외한다. 실제 섭취량 0을 명시한 경우는 ‘양 미입력’과 다르다. 물 교체·보충량을 실제 음수량으로 계산하지 않는다.

실제 섭취량 기준 열량과 제공량 기준 예상 열량을 통합 설명에서 구분한다. 개별 통계의 확인된 열량 합계에는 두 기준이 함께 포함될 수 있음을 표시하고 각각의 합계도 제공한다. 체중은 합계가 아니라 측정값과 측정 날짜를 사용한다. 통화와 서로 다른 단위를 무분별하게 합치지 않는다.

이전의 발정·산란 기록은 원래 값 그대로 상세 조회·수정할 수 있다. 새 기록 화면은 생활 변화 항목으로 구성하며, 이전 기록을 새로운 종류로 일괄 변환하지 않는다.

브라우저의 의도적인 오프라인 검사에서는 네트워크 단절 메시지가 발생한다. 이를 실제 결함이나 예외가 없었다는 주장과 혼동하지 않는다. 정상·권한 검사에서 처리되지 않은 JavaScript 예외는 발견되지 않았다.

통합 상태는 변경 관찰·최근 체중·급여·활동을 우선해 **최대 네 가지 요약**을 먼저 표시한다. 나머지 항목은 ‘다른 돌봄 기록도 확인’에 그대로 남는다. 이를 건강 위험도의 자동 순위로 해석하지 않는다.

## 재검사

프로젝트 가상환경에서 실행한다.

```powershell
.\.venv\Scripts\python.exe scripts/check.py
.\.venv\Scripts\python.exe scripts/check.py --browser
```

첫 명령은 자동 회귀·마이그레이션 변경 여부·JavaScript 문법·주요 정적 검사·패키지 의존성 검사를 수행한다. `--browser`를 붙이면 검증용 시연 DB를 별도 경로에 준비하고 실제 Chromium 브라우저 검사도 실행한다. 개발 의존성과 Chromium은 실행 문서의 설치 절차에 따라 준비해야 한다.

브라우저 검사는 8012·8013번 로컬 포트를 사용한다. 이미 점유된 포트를 임의로 종료하지 않으며 실제 기록·사용자 시연 DB를 검증 데이터로 사용하지 않는다. 상세 결과는 `tmp/handoff/phase2/`에 생성된다. `verify_taily_browser.py`와 `verify_taily_access.py`는 각 검사 단계의 실행 스크립트다.

자동 검사 통과와 실제 구글 OAuth 성공, 실기기 전체 호환성, 공개 배포 완료는 서로 다른 판단이다. 실제 OAuth 자격증명과 외부 서비스 운영 검증은 이 변경의 완료로 간주하지 않는다.
