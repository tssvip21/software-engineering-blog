# 로컬 구현과 실행

## 현재 상태와 범위

사용자와 논의한 요구사항을 바탕으로 Django 서버, SQLite 저장소, HTML·CSS·JavaScript 화면을 연결한 1차 초안이다. 서버는 기본적으로 `127.0.0.1`에만 연결한다. 로컬 실행을 검증한 버전이며 실제 외부 서비스 배포는 별도 단계다.

식사·간식·물 관리·배변·산책·놀이·훈련·체중·위생·미용·생활공간 청소·투약·상태 관찰·병원·예방접종·수면·휴식·사육환경·발정·산란·탈피·털갈이·용품·재고·지출의 **20개 모듈**에 각기 다른 입력, 목록, 상세, 수정·취소와 통계를 연결했다. 화면에 예시 수치만 표시하는 방식이 아니라 저장된 기록을 조회·집계한다.

**미확인:** 실제 구글 OAuth 클라이언트가 설정되지 않아 실계정 로그인은 아직 검증하지 못했다. 인증 코드와 서버 검증, 모의 응답을 사용하는 자동 검사는 마련했지만 실제 로그인 성공과 동일하게 취급하지 않는다. 시연 계정은 구글 인증을 대신하지 않는다.

서비스 표시명은 임시로 `반려동물 돌봄`을 사용한다. 제품명이나 브랜드를 확정한 것은 아니다.

## 바로 실행

프로젝트 폴더에서 다음 중 하나를 실행한다. Python 3.13 환경에서 검증했다.

```powershell
# 가상 데이터와 시연 계정으로 화면·기능 검토
.\.venv\Scripts\python.exe -X utf8 scripts\run_local.py --demo
# 브라우저: http://127.0.0.1:8001

# 실제 기록용 로컬 환경 (구글 로그인 설정 필요)
.\.venv\Scripts\python.exe -X utf8 scripts\run_local.py
# 브라우저: http://127.0.0.1:8000
```

Windows에서는 `START_DEMO.cmd`, `START_LOCAL.cmd`를 더블클릭해도 된다. 이미 해당 포트의 서버를 실행 중이면 중복 실행하지 말고 브라우저에서 주소를 연다. 터미널에서 실행한 서버는 `Ctrl+C`로 종료한다.

시연 초기화는 이미 있는 시연 기록을 덮어쓰지 않는다. 시연 환경에는 `보리`, `초록이`와 방장·관리자·일반 참여자·빈 계정이 제공된다. 화면 상단에 시연 환경임을 표시한다. 무로그인 게스트는 방장이 만든 초대 링크를 별도 시크릿 창에서 열어 확인한다.

### 새 환경 설치

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade "pip>=26.2"
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -X utf8 manage.py migrate --noinput
.\.venv\Scripts\python.exe -X utf8 manage.py seed_references
.\.venv\Scripts\python.exe -X utf8 scripts\run_local.py --demo
```

동일 단계는 `scripts/setup.ps1`에 있다. PowerShell 실행 정책을 시스템 전체에서 임의로 완화하지 않고, 허용된 실행 환경에서 스크립트 또는 위 명령을 사용한다. `requirements.lock`는 검증 환경의 런타임 패키지 버전을 고정한다. 업그레이드할 때는 패키지 검사와 회귀 검사를 다시 수행한다.

## 실제 구글 로그인 설정

프로젝트 루트에 `.env.example`을 복사해 `.env`를 만든 뒤 다음 값을 설정한다. 이 파일은 Git 제외 대상이다.

```dotenv
DJANGO_DEBUG=1
DJANGO_SECRET_KEY=<충분히 긴 무작위 비밀값>
DJANGO_ALLOWED_HOSTS=127.0.0.1,localhost
APP_ORIGIN=http://127.0.0.1:8000
GOOGLE_CLIENT_ID=<구글 웹 애플리케이션 OAuth 클라이언트 ID>
GOOGLE_CLIENT_SECRET=<해당 클라이언트 비밀값>
GOOGLE_REDIRECT_URI=http://127.0.0.1:8000/auth/google/callback/
```

구글 OAuth 클라이언트의 승인된 리디렉션 URI와 `GOOGLE_REDIRECT_URI`를 정확히 일치시킨다. 동의 화면이 테스트 상태라면 로그인할 계정을 허용된 테스트 사용자로 등록해야 한다. 포트·호스트를 바꾸면 리디렉션 URI도 같이 변경한다. 비밀값을 채팅, 스크린샷, 소스, 커밋에 넣지 않는다.

설정 후 일반 환경을 재시작하여 로그인 → 방 생성 → 로그아웃 → 재로그인 → 기존 방·기록 유지까지 직접 확인해야 한다. 게스트가 구글 계정에 연결할 때는 **현재 게스트 세션과 구글 로그인 둘 다** 확인한다. 이름이나 이메일이 비슷하다는 이유로 참여 이력을 합치지 않는다.

Google 콜백은 `state`, `nonce`, PKCE, 토큰 서명과 발급자·대상·만료를 확인한다. 구글 `sub`로 계정을 식별하고 로그인만으로 관리자 권한을 부여하지 않는다.

## 저장소와 운영 설정

| 구분 | 기본 위치 또는 동작 |
| --- | --- |
| 일반 데이터 | `data/care.sqlite3` |
| 시연 데이터 | `data/demo.sqlite3` |
| 로컬 비밀값 | `DJANGO_SECRET_KEY` 미설정·개발 모드인 경우 `data/.local_secret` |
| 데이터 위치 변경 | `CARE_DATA_DIR` 환경 변수 |
| DB 초기 구성·변경 | Django 마이그레이션 |
| 정적 파일 | `static/` 원본 → 실행 시 `staticfiles/` 수집 |
| 로컬 서버 | Waitress, loopback 전용, 기본 8000/8001 |

시연과 일반 환경은 DB와 세션·CSRF 쿠키 이름을 구분한다. 시연 로그인 경로는 일반 환경에서 등록되지 않는다. 실행 스크립트는 기존 DB를 삭제하지 않고 필요한 마이그레이션만 적용한다.

운영 환경으로 공개할 때에는 별도 승인 후 HTTPS, 운영용 도메인·비밀값·OAuth URI, 프록시 설정, 백업 보관과 접근권한을 실제 배포 구성에 맞춰 검토해야 한다. 현재 로컬 실행은 외부 배포 완료를 뜻하지 않는다. `DEBUG=0`에서는 비밀키가 필수이며 안전한 쿠키·HTTPS 리디렉션이 적용된다. 대규모 동시 접속과 운영 부하 시험은 수행하지 않았다.

### 백업·복원

```powershell
# 실행 중인 일반 DB의 일관된 SQLite 백업과 SHA-256 검증 정보 생성
.\.venv\Scripts\python.exe -X utf8 scripts\backup.py
# 시연 DB는 별도 옵션
.\.venv\Scripts\python.exe -X utf8 scripts\backup.py --demo

# 해당 환경 서버를 종료한 뒤에만 복원
.\.venv\Scripts\python.exe -X utf8 scripts\backup.py --restore "backups\care-<시각>.sqlite3" --confirm-stopped
```

백업 DB와 같은 이름의 JSON 검증 파일을 함께 보관한다. 복원은 DB 종류와 SHA-256, SQLite 무결성을 확인한다. 기존 DB는 교체 직전 별도 안전 백업을 만들고, 연결을 닫은 뒤 교체한다. DB 백업은 `.env`나 로컬 비밀값을 포함하지 않는다. 이 설정은 별도로 안전하게 보관한다. 백업과 운영 데이터는 Git에 넣지 않는다.

## 권한과 공유

방장·관리자·일반 참여자의 권한을 방마다 확인한다. 무로그인 참여자는 화면에 게스트로 표시한다. 로그인 여부와 방 역할은 다른 값이다.

| 동작 | 방장 | 관리자 | 일반 참여자·게스트 |
| --- | --- | --- | --- |
| 공유된 기록 열람·추가 | 가능 | 가능 | 가능 |
| 자기 기록 수정·취소 | 가능 | 가능 | 가능 |
| 다른 사람 기록 수정·취소 | 가능 | 가능 | 불가 |
| 모듈·제품·루틴 설정 | 가능 | 가능 | 불가 |
| 초대 발급·폐기, 승격·해제·내보내기 | 가능 | 불가 | 불가 |
| 민감 모듈의 공유 범위 변경 | 가능 | 불가 | 불가 |
| 방 보관·영구 삭제 | 가능 | 불가 | 불가 |

투약·병원·지출은 기본적으로 방장·관리자에게만 보인다. 방장은 모든 참여자에게 공유하도록 변경할 수 있다. 선택한 범위를 초대 확인 화면과 방 정보에 표시한다. 계정 이메일·인증 비밀값은 구성원 목록에 노출하지 않는다.

초대는 1시간·24시간·7일 중 유효기간과 최대 100회의 사용 횟수를 선택한다. 초대 원문은 DB에 저장하지 않고 해시로 확인한다. 링크를 여는 것만으로 가입시키지 않고 공유 범위와 이름을 확인한 뒤 참여한다. 링크 폐기는 새 참여만 막고, 기존 참여자의 권한 해제는 내보내기로 처리한다. 무로그인 사용자의 재가입을 완벽히 식별한다고 보장하지 않는다.

## 기록·루틴·통계의 기준

- 기록마다 요청 식별자를 부여해 같은 요청의 재전송을 한 번만 저장한다. 독립적인 두 번의 활동은 각각 저장한다. 수정은 버전을 확인해 뒤늦은 요청이 새 내용을 덮어쓰지 않게 한다.
- 모듈 입력과 루틴은 같은 활동 기록을 참조한다. 루틴에서 입력해도 통계에 두 번 넣지 않는다. 기존 기록을 루틴에 연결할 수 있다.
- 기록 취소는 이력을 남기고 집계와 루틴 완료에서 제외한다. 모듈을 꺼도 이전 기록과 통계는 유지하며 해당 모듈의 새 루틴 활동은 일시 중지한다.
- 현재·7일 전·1개월 전의 흐름 지표는 각각 기준일을 포함한 최근 7일로 비교한다. 체중은 해당 기준일까지 마지막 측정값, 재고는 해당 기준일 말 잔량이다. 1개월 전은 고정 30일이 아닌 달력 기준이다.
- 과거 요약은 현재 유효한 기록을 활동 시각 기준으로 재집계한 값이다. 과거 기록을 정정하면 이전 기간 통계도 바뀐다. 당시 DB 화면을 고정 보관한 스냅샷은 아니다.
- 날짜 경계는 방의 시간대를 따른다. 미기록을 실제 값 0으로 채우지 않는다. 진행·예정·취소 기록은 완료 합계에서 제외한다.
- 체중을 합산하거나 물 보충량을 음수량으로 간주하지 않는다. 실제로 관찰한 수면 구간은 중복 구간을 한 번만 계산하고 자정 경계를 나눈다. 재고와 지출은 품목·단위·통화를 구분한다.
- 영양 계산에는 제품의 당시 값을 보존한다. 제품 정보를 수정해도 과거 기록의 의미는 바뀌지 않는다. 제공량 기준 예상치와 확인한 실제 섭취량을 구분한다.

### 분류별 참고 기준의 한계

출처를 확인한 개·고양이의 9점 BCS 참고 구간을 별도로 입력한 BCS와 연결했다. BCS는 체중에서 계산하지 않는다. 소형·중형·대형의 평균 체중만으로 저체중·비만을 판정하지 않는다. 종별 생활환경 등 근거를 확보하지 못한 항목에는 비교 기준 미확보 상태를 표시한다.

통계 화면에서 적용 대상·측정일·출처를 확인할 수 있다. 모든 동물·지표의 참고 기준을 완성한 것은 아니다. 의학적 진단, 자동 투약 용량 추천, 근거 없는 건강 점수는 제공하지 않는다.

## 검사

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -X utf8 manage.py test care.tests --noinput
.\.venv\Scripts\python.exe -X utf8 manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m pip_audit

# 먼저 별도 터미널에서 시연 서버를 실행한 뒤
.\.venv\Scripts\python.exe -X utf8 scripts\verify_browser.py
```

브라우저 검사는 시연 배너가 없는 환경에서는 중단한다. 검사용 방을 만들고 정상 완료하면 해당 방을 삭제한다. 중간에 검사가 실패하면 검사용 방이 남을 수 있다. 일반 운영 데이터를 검사용으로 사용하지 않는다.

실제 구글 로그인은 자격증명을 연결한 뒤 별도로 확인한다. OAuth 모의 응답 검사나 시연 로그인을 실제 공급자 연동 성공으로 보고하지 않는다. SQLite 다중 연결·중복 요청과 파일 기반 재시작·백업·복원은 별도 격리 데이터로 검증했다.

## 화면 정돈 및 도구 출처

Unslop의 실제 스킬·참고 규칙을 확인해 화면을 검토했다. 빠른 기록 영역은 우선 6개 모듈을 보여주고 나머지를 펼쳐 볼 수 있게 했으며, 기록 목록에 수치와 단위를 함께 표시하고 변경 이력은 읽기 쉬운 항목별 표시로 바꿨다. 공통 간격·버튼·폼의 구조를 유지하면서 모바일과 데스크톱을 확인했다.

Unslop 제작자, 원본 저장소, 확인한 커밋과 라이선스는 [사용 도구 및 출처](../THIRD_PARTY_NOTICES.md)에 기록했다. 원본 스킬 파일은 수정하지 않았다.
