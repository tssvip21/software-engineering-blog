# 11월 12일 사용 흐름 개선과 통계 설계안

**상태:** 입력·권한 화면·공통 배치(A~G)는 구현·검수 대상으로 처리했다. 아래 통계 제안(H~I)은 **사용자 확인 전**이며, 계산 엔진과 데이터 모델에는 적용하지 않았다. 로컬 작업만 수행하며 원격 게시·배포는 하지 않는다.

## 1. 이번에 실제로 고친 부분

### 입력 모달의 상태 흐름

원래 화면 → 입력창 로딩 → 입력 → 저장 → 기존 화면 갱신·토스트·호출 위치로 초점 복귀로 연결한다. 검색어·분류·펼침·스크롤을 가능한 한 보존한다. 필드 오류는 입력창 안에서 고치며, 작성 중 닫기는 같은 창에서 확인한다. 서버가 저장한 뒤 응답만 끊긴 경우에는 **전송했던 내용과 요청 번호를 그대로 유지**하여 결과를 다시 확인한다. 다른 내용을 같은 번호로 재전송하거나 저장됐다는 응답을 받기 전에 성공 안내를 띄우지 않는다.

재개 후에는 느린 입력창을 닫고 다른 입력창을 열었을 때, 이전 응답이 새 폼을 덮거나 새 요청의 타임아웃 정리를 방해하는 두 경로도 재현했다. 요청별 취소 처리와 응답 본문 수신 뒤 현재 창 확인으로 고쳤고, 동일 실패 조건의 재검사와 전체 회귀 검사를 구분해서 남겼다.

긴 모달에서 초점이 창 밖으로 이동하지 않도록 하고 닫힌 뒤 호출한 요소로 돌아오게 한다. 이 동작은 W3C의 모달 상호작용 지침을 참고했다.[S8] 실제 검사는 아래 로컬 테스트에 별도로 기록한다.

## 2. 통계에서 해결할 사용자 질문

숫자가 계산되는가와 사용자에게 필요한 답인가를 분리한다. 제안의 핵심 질문은 **최근 무엇을 실제로 기록했고, 어떤 조건에서 비교할 수 있으며, 다음에 어느 기록을 확인하면 되는가**다.

기존 구현을 확인한 결과 다음 차이가 남아 있다.

- 체중의 마지막 두 측정과 7일 평균 비교가 동시에 크게 표시되지만, 측정 간격·마지막 측정의 오래됨이 덜 드러난다.
- 한 번의 간식 기록도 이전/최근 평균 양식을 채우기 위해 큰 빈 비교 영역이 생긴다. 제공량·확인 섭취량·두 종류의 열량을 같은 중요도로 반복한다.
- 부분 기록이 있는 날을 일별 집계에서 통째로 제외하면 **확인한 수치까지 사라진다.** 반대로 나머지 날만 평균내면 그 평균이 실제 하루 전체량처럼 읽힐 수 있다.
- 나란히 놓은 수치를 '관계 분석'이라고 부르기 쉽지만, 기록 당시 나이·상태·제품 변경·측정 조건과 실제 사건의 선후가 빠져 있다.
- 현재 Room의 생일·성장단계·상태성 정보는 현재값이다. 수정 전후를 충분히 남기지 않아 **과거의 상태를 현재값으로 정확히 복원할 수 없다.**

이 문서는 두 기간 평균이 언제나 틀렸다고 결론내리지 않는다. **평균이 답하는 질문과 자료 범위가 맞을 때 상세 분석에 사용**하되, 모든 모듈의 첫 화면을 평균 비교로 강제하는 방식을 바꾸자는 제안이다.

## 3. 제안 ① — 체중은 실제 측정의 시간과 맥락부터

### 처음 보여줄 정보

- 최신 실제 체중, 측정 시각, 얼마나 지난 기록인지.
- 비교 대상으로 선택한 실제 측정값·날짜·간격과 절대 변화량. 이전 값이 양수일 때만 보조 변화율.
- 실제 측정일 간격을 반영한 작은 측정 이력. 입력일이 아니라 측정일을 축으로 사용한다. 긴 공백을 연속 측정처럼 채우거나 임의 보간하지 않는다.
- 관련되는 기간에 제품·급여 설정·활동 조건이 실제 바뀐 사건이 있으면 **변경 날짜와 내용**을 먼저 연결한다. 단순히 변수가 같이 존재한다고 관계 카드를 생성하지 않는다.

**사용자가 제시한 수치의 재표현 예:** `8.4kg · 11/04 00:22 측정` / `직전 11/03 18:00의 8.45kg보다 50g 감소 · 측정 간격 6시간 22분`. 11월 12일에 보면 `8일 전 측정`이다. 이는 사실 차이이며, 이 두 건만으로 장기적인 체중 감소 추세·정상/이상을 판정하지 않는다. 최근 두 기록이 가까운 시각이면 바로 앞 수치보다 사용자가 선택한 이전 측정과 비교하는 길을 함께 제공한다. 자동으로 의미 있는 시간 간격을 정했다고 주장하지 않는다.

**보조 체형 관찰:** BCS가 기록돼 있을 때만 `체형 관찰 5/9 · 평가일·평가자`를 작은 줄로 보여주고, 이 점수가 체중 계산값이 아니라 직접 관찰·평가한 체지방 상태라는 뜻을 짧게 연결한다. 숫자 아홉 칸이 화면의 중심이 되지 않게 한다. 다른 종에 개·고양이 척도를 강제하지 않는다. BCS와 근육상태는 서로 다른 평가라는 원칙도 구분한다.[S1]

### 외부 참고 기준과 나이

개체의 과거 측정, 사용자가 지정한 관리 목표, 품종 안내 범위, 연구에서 관찰한 분포는 **각각 다른 기준**으로 표시한다. 성장 중인 개의 체중은 연령·성별·성장 단계와 대상 조건을 고려해야 한다. 성장 표준 연구는 특정 연령대·선정된 개 집단에서 만들어졌고, 측정/출생일 오류와 비균일한 관측의 한계를 기록했다.[S6] 그것을 성견·고양이·앵무새의 적정 체중 기준으로 확대하지 않는다. 외부 참고값을 선택할 때 데이터 출처·버전·대상·단위·적용 자격을 명세하고, 조건이 맞지 않으면 개체의 기록만 남긴다.

**확인받을 결정:** 체중 첫 화면에서 두 기간 평균을 주지표로 두지 않고 **실제 측정·시간 간격 중심**으로 바꾼다. 기간 평균은 정의가 맞을 때 상세에서만 제공한다.

## 4. 제안 ② — 간식·급여는 사용자가 남긴 사건과 확인 가능한 양부터

간식 8g 한 건만 있으면 첫 화면은 `간식 1회 · 제공량 8g · 마지막 기록 날짜`로 끝나도 된다. 제품이 연결돼 있으면 제품 이름과 양을 함께 보여준다. 이전 기간에 기록이 없다고 `— → 8g`라는 큰 비교판을 만들지 않는다. 필요한 행동은 **기록 보기·수정 / 다른 제품과 구분 / 실제 먹은 양 입력** 정도로 모은다.

### 계산 계약 제안

| 데이터 조건 | 보일 수 있는 값 | 보여주지 않을 값 |
| --- | --- | --- |
| 제공량만 기록 | 제품/단위별 제공량 합계, 제공 횟수 | 실제 섭취량, 실제 하루 전체 열량 |
| 실제 먹은 양도 확인 | 제공량과 별도의 확인 섭취량 | 두 기준을 섞은 합계·비율 |
| 기록 당시 제품 열량 있음 | 해당 제공/섭취 기준의 `양 × 단위당 열량` | 현재 제품값으로 과거 값을 조용히 재계산 |
| 개수·개당 열량 있음, 개당 무게 없음 | 개수, 해당 개당 열량으로 계산한 kcal | 임의 g 환산 |
| 선택한 급여/간식 기록의 에너지가 모두 있고 같은 기준임 | `간식 열량 ÷ 기록된 전체 먹이 열량 × 100`을 **기록된 제공 열량 중 비중**처럼 범위를 밝힌 보조값으로 표시 | 하루 전체 식단에서의 실제 비중이라는 주장 |
| 같은 기간에 열량을 알 수 없는 먹이 기록이 섞임 | 확인 가능한 제품별 양·기록 횟수, 빠진 제품정보로 가는 링크 | 일부만 빼고 계산한 정확한 비중 |
| 기록이 있는 날이지만 일부 급여가 누락됐을 수 있음 | 기록된 사건의 사실 요약 | 그날의 전체 섭취를 빠짐없이 관측했다는 전제 |

공식 영양 기록 도구도 '모든 날', '기록이 있는 날', '완료로 표시한 날'을 분리한다.[S2] 테일리에는 하루 전체 급여의 완전성을 확인하는 정보가 없으므로 **기록일 수가 많다는 이유로 완전한 일일 섭취 자료라고 간주하지 않는다.** 완전 기록 확인 기능을 추가할지는 입력 부담과 함께 별도 승인받는다. 기본값으로 매일 설문을 강요하지 않는다.

AAHA의 영양 평가에는 주식뿐 아니라 간식·보조제·약을 먹이기 위한 음식까지 포함된다.[S1] 임상 지침의 '총 섭취량 중 비중' 기준을 일부 제공 기록의 비율에 그대로 적용해 경고나 급여량 조언을 생성하지 않는다.[S9]

**확인받을 결정:** 제공량·섭취량·열량의 네 동일 평균판을 없애고 **횟수·제품별 확인량을 우선**, 기록 조건을 만족하는 열량과 비중만 상세 보조값으로 둔다.

## 6. 제안 ③ — 관계는 ‘같은 기간의 숫자 나열’이 아니라 사건을 찾는 기능

근거상 식이·환경·활동·체중을 함께 살필 이유는 있으나,[S1] 개의 활동량 연구조차 관측 장비·질병·나이·크기·환경과 선택 편향을 다루며 보행/달리기 구분 및 모델의 한계를 남긴다.[S5] 따라서 테일리의 수동 산책시간을 그 연구의 센서 기반 일일 활동량이나 권장량으로 치환하지 않는다. 불규칙한 시계열을 표준 등간격 자기상관 계산에 그대로 넣는 것도 피한다.[S4]

**확인받을 결정:** 관계 영역을 일반적인 주의문구와 숫자 나열에서 **특정 시점의 설정/상태 변화와 실제 기록을 찾는 시간선**으로 바꾸고, 인과모형은 별도 검증 과제로 둔다.

## 7. 나이·상태·시간·기록 품질의 데이터 계약 제안

### 이미 있는 정보를 재사용

Room의 종·품종·성별·생일, Activity의 발생/종료/입력 시각·작성자·변경 이력, Product의 버전과 기록 당시 영양 스냅샷, RoutineVersion의 적용일을 우선 쓴다. 서비스는 현재 생일이 알려져 있어도 기록 당시의 나이·성장단계를 별도로 적용하는 통계 경로가 필요하다. 기본정보를 매번 입력시키지 않는다.

### 설정의 첫 사용 기록과 실제 변경일은 다르다

현재 Product/RecordPreset의 버전·수정 시각과 개별 기록에 저장된 당시 값은 재사용할 수 있지만, 그것만으로 **급여 방법이 실제 바뀐 날짜와 모든 과거 설정 내용**을 복원할 수는 없다. 기존 수정 로그는 주로 대상 ID를 남기므로 기록에 쓰이지 않은 중간 버전이나 실제 적용 시작일도 미상일 수 있다. 따라서 위의 `11/02 사료 설정 60→65g`은 그 변경 사건의 시점·이전/이후 값이 확보됐을 때의 제안 예시다. 기존 데이터에서 새 값이 처음 보이는 날짜만 확인된다면 `11/05 기록부터 65g 설정 사용 확인`처럼 **최초 확인 시점**이라고 써야 하며, 실제 변경일이라고 단정하거나 임의 백필하지 않는다.

승인 후에는 상태 이력뿐 아니라 제품·저장 설정에도 필요한 경우 `버전/이전값/새값/등록시각/선택적 실제 적용시각`을 보존하는 추가형 이력을 설계한다. 실제 적용일을 모르면 미상으로 두고 기존 기록 스냅샷을 변경하지 않는다. 이 추가 구조 역시 아직 구현하지 않았다.

### 현재 없는 정보 — 추가 구현은 승인 후

| 정보 | 필요한 구분 | 입력 부담과 과거 처리 |
| --- | --- | --- |
| 생일/추정 나이 | 알려진 생일과 `기준일 당시 추정 범위` 분리 | 생일 미상에 임의 정확일 생성 금지. 추정 범위는 최초 1회·변경 때만. |
| 프로필·상태 변화 | `실제 적용 시작/끝`과 `기록한 시각`, 출처·정정 여부 | 질환/회복·중성화·수의사 관리 조건은 필요한 선택 항목. 과거 상태 미상은 그대로 미상. |
| 측정 조건 | 기기·방법·위치·기준 단위·관찰 범위 | 재사용 가능한 측정 설정을 기본으로, 달라진 때만 갱신. 장비 정밀도 없는 소수점은 과장하지 않음. |
| 개체 귀속 | 개인 급여·음수와 다마리 공유 기록 | 공유량을 마릿수로 나눠 개인량으로 만들지 않음. |
| 기록 완전성 | 명시적으로 관찰한 구간·전체급여 확인 여부 vs 기록 존재 | 현재 기록일=완전일로 취급 금지. 선택적 완료 표시를 도입할지는 별도 확인. |

상태는 반개구간 `[effective_from, effective_to)`로 제안한다. 수정 등록 시각이 늦어도 사건의 실제 효력시각은 다를 수 있다. **오류를 정정한 것**과 **상태가 바뀐 것**을 구분하고 before/after/작성자를 보존한다. 과거 정보가 처음부터 없던 경우 현재 상태를 소급 적용하는 백필은 하지 않는다. 시간대 변경도 이전 기록의 해석 기준을 명시적으로 보존할 대상이다.

예: 생일 2026-08-01인 개의 10월 1일 기록은 61일령, 11월 12일 화면을 보는 현재는 103일령이다. 현재 '성장 완료'로 바꿨다고 이전 기록도 성견으로 해석하지 않는다. 제품 설정이 11월 5일 바뀌었다면 11월 4일 측정에 새 값을 끼워 넣지 않는다. 사건시각과 입력시각을 분리하는 사용 흐름은 공식 생활기록 도구의 태그 처리도 참고했다.[S3]

### 사용자에게 의미 있는 자료 상태

‘신뢰도 72점’ 같은 가중 점수를 만들지 않는다. `직접 측정 / 설정값으로 기록 / 일부만 확인 / 공유 기록 / 조건 변경 / 기준 자료 없음`처럼 **실제로 알고 있는 속성**을 쓴다. 첫 화면에는 해석을 바꾸는 속성만 짧게 남긴다. 사소한 계산식·일반 경고·출처 목록은 상세로 내린다. 권한 필터는 값·관련 사건·건수·문구 생성 전에 적용한다.

## 8. 제안 화면 구조 — 코드 미적용

**첫 영역:** 반려동물/조회기간과 사용자가 확인할 핵심 측정. 체중은 최신 실제 값·측정 간격, 간식은 최근 제공 사실. 큰 빈 비교 카드는 제외한다.

**두 번째 영역:** 사용자가 선택한 변화 구간에서 실제로 있었던 제품·설정·관찰 사건. 사건이 없으면 별도 대형 관계 카드를 만들지 않는다. 사건이 존재한다는 사실 자체를 강조하고 원기록을 연다.

**세 번째 영역:** 일정·관리·재고 등 목적별 짧은 요약. 건강 분석과 단순 수량관계를 같은 점수로 통합하지 않는다. 선택한 모듈별 전체 이력과 상세 통계는 계속 접근 가능하다.

모든 모듈을 상단에서 동일한 거대 카드로 나열하지 않는다. 이 순서와 선정 방식은 사용자 확인 후 구현할 **제안**이다. 현재 승인 없이 적용한 것은 카드 과도한 폭·버튼 하단 정렬 등 독립적인 레이아웃 수정뿐이다.

## 10. 검증·보존 및 승인 상태

최종 로컬 자동 검사 **369개**, Chromium·Firefox의 실제 입력·권한·오류·초점·호버·응답 유실 흐름 **26개**, 화면폭·텍스트 확대 배치 **52개**를 통과했다. 선택 가능한 18종 입력 모달을 두 브라우저에서 열고 닫는 경로도 포함한다. 설계 제안용 독립 계산은 **20개 사례**이며 제품 구현이나 의료적 검증으로 세지 않는다. 사용자 보호 파일 **14개**, 원본·이전 검수 DB **7개**의 업무 테이블과 기존 통계/모델 코드는 기준 상태와 동일함을 대조했다. 상세 최종 결과와 소스 해시는 `tmp/handoff/review-20261112/final-state.json`에 남긴다. 초점/오류/중복 처리뿐 아니라 **UI가 어떻게 달라졌는지** 전후 캡처도 별도로 남긴다. 원본 DB·사용자 작성 중 파일·지시서·관계 그림은 보호 기준과 비교한다.

실제 검수 주소는 **http://127.0.0.1:8036**이다. 기존 7차 시연 DB를 초기화하지 않고 확인된 해당 로컬 서버만 재시작했다. 실제 주소에서 일반 시연 세 공간, 기록·루틴 모달, 구성원 패널, 375px 배치를 다시 확인했다. 클라우드 VM은 재시작하지 않았다.

범위별 최종 상태는 **A~E·G 구현/검증**, **F의 독립적 폭·배치 수정 반영**, **H~I의 연구·구체 설계안 작성/사용자 확인 대기**다. 최종 통계 정보의 우선순위와 산식은 코드에 적용하지 않았다. 이 상태를 통계 개편 전체 완료라고 부르지 않는다.

**승인 요청은 세 가지:** (1) 체중 첫 화면을 실제 측정·시간 간격으로, (2) 간식·급여를 횟수와 제품별 확인량 우선으로, (3) 관계 영역을 구간 안의 실제 변경 사건 중심으로 바꾸는 것. 승인되면 시간 이력에 필요한 추가 데이터 구조와 산식을 비파괴적으로 구현하고 다시 검증한다. 승인 전에는 새 통계 계산을 적용하지 않는다.

화면 잠금·앱 전환 중 GPS 지속 수집, 휴대전화 OS 푸시, 실제 기기 검증은 이전 미완료 상태를 유지하며 이번 UI 작업으로 해결했다고 보고하지 않는다. 현재 클라우드는 재시작하지 않고 로컬만 사용한다.

## 참고 자료와 적용 범위

아래는 2026-11-12 확인한 공식 자료·원문 연구다. **자료에서 말하는 내용**과 **이 문서에서 제안한 테일리 설계**는 구분한다. 공식 제품 문서를 읽었다고 유료 계정 내부를 직접 사용했다고 쓰지 않는다. 다른 사이트의 코드·고유 이미지·수의학 척도 그림은 복제하지 않았다.

- **[S1] AAHA, Screening Evaluation (2021):** 식이·환경·활동·체중·BCS·MCS를 함께 살피며 BCS는 직접 평가다. 이 원칙은 맥락 선정의 근거이지 테일리의 자동 진단식을 보증하지 않는다. https://www.aaha.org/resources/2021-aaha-nutrition-and-weight-management-guidelines/screening-evaluation/
- **[S2] Cronometer, Nutrition Report (2026-06-25 업데이트):** 기록 존재와 완료된 날을 따로 선택하고 진행 중 오늘의 평균 문제를 설명한다. 데이터 범위 구분만 참고하며 사람 영양 기준은 적용하지 않는다. https://support.cronometer.com/hc/en-us/articles/360018569691-Nutrition-Report
- **[S3] Oura, Using Tags (2026-05-29 업데이트):** 사건 시작/끝·태그를 시간선에서 다룬다. 동물의 수면점수·인과 모델에 대한 근거가 아니다. https://support.ouraring.com/hc/en-us/articles/360038676993-Using-Tags
- **[S4] NIST, Autocorrelation:** 통상적 시계열 자기상관은 등간격 관측 전제를 가진다. 불규칙 기록에 기계적으로 적용하지 않는 이유이며, 모든 평균 비교가 금지된다는 뜻은 아니다. https://www.itl.nist.gov/div898/handbook/eda/section3/eda35c.htm
- **[S5] O’Rourke 등, Estimated activity levels in dogs at population scale with linear and causal modeling (2025):** 센서·건강기록에 기반한 관측 연구의 측정 정의와 선택/모델 한계를 확인했다. 그 일일 센서 활동량을 수동 산책시간이나 건강 목표로 이식하지 않는다. https://www.frontiersin.org/journals/veterinary-science/articles/10.3389/fvets.2025.1572794/full
- **[S6] Salt 등, Growth standard charts for monitoring bodyweight in dogs of different sizes (2017):** 성장 중인 개의 연령·성별·크기별 기준과 자료 한계를 확인했다. https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0182064
- **[S7] S6의 2024 정정:** 데이터 접근 경로 설명의 정정임을 확인했다. 표를 독립 검증하거나 구현하지 않았다. https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0314711
- **[S8] W3C, Dialog (Modal) Pattern:** 초점 범위·닫기·초점 복귀 등의 구현 기준. https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/
- **[S9] AAHA, Nutritional Risk Factors (2021):** 생애단계·질환·급여의 전체 맥락을 고려한다. 총섭취를 전제로 한 기준을 테일리의 일부 제공 기록에 그대로 적용하지 않는다. https://www.aaha.org/resources/2021-aaha-nutrition-and-weight-management-guidelines/nutritional-risk-factors/
