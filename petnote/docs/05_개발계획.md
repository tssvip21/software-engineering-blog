# 반려동물 돌봄 서비스 개발 계획 초안

개인이나 여러 사람이 다양한 반려동물의 돌봄 정보를 기록하고 통계와 종합 상태 확인에 활용하는 웹 서비스를 목표로 한다. 아래 범위는 2026년 11월 2일 정리한 기획을 반영한다. 기술 스택과 세부 데이터 구조, 분류별 수치 기준은 아직 정하지 않았으며 개발 순서는 설계 과정에서 구체화한다.

## 이번 학기 구현 범위

1. **사용자:** 개인·공동 사용을 지원하고, 필요한 모듈을 선택·배치해 돌봄 정보를 쉽게 기록하고 관리한다. 혼자 사용하는 흐름과 구성원을 초대해 기록을 공유하는 흐름을 모두 포함한다.
2. **반려동물:** 종·체격 등 기본 분류를 설정하고, 모듈에서 수집한 정보를 분류별 기준에 따라 통계와 종합 상태 확인에 활용할 수 있는 틀을 구축한다. 리트리버·푸들 같은 세부 품종보다 소형·중형·대형 정도의 기본 구분을 우선하며, 분류와 기준은 동물 종류에 맞게 둔다.

산책·밥·간식의 기본 기록, 루틴, 기간별 통계와 등록한 제품 정보에 따른 영양 계산을 연결한다. 실제 수치 비교는 근거와 적용 대상을 확인한 항목부터 제공한다. 세부 품종별 분석이나 모든 종별 전문 모듈의 완성까지 약속하는 범위는 아니다.

## 과제 조건과 일정

[학기프로젝트 안내](../학기프로젝트_안내.pdf)의 최소 조건은 접속 가능한 URL, 관계가 있는 2개 이상의 데이터 테이블, 데이터 입력과 목록 조회, GitHub 커밋 기록, 블로그 글 4편 이상이다. 1인 개발이며, 발표는 5분과 질문 2분으로 진행한다.

- 2026년 11월 2일 23:59: 주제 제안 블로그와 글 주소 제출
- 2026년 11월 9일 23:59: 데이터 설계와 ERD 초안 블로그 제출
- 2026년 11월 16일 23:59: URL로 접속할 수 있는 첫 버전과 첫 배포 블로그 제출
- 2026년 12월 7일 23:59: 최종 URL, GitHub 저장소, 블로그 주소와 회고 제출
- 2026년 12월 8일: 최종 발표

날짜는 안내문 기준이며 이후 LMS 변경 공지를 확인한다. 수업은 무료 범위의 도구 사용을 안내하고 있다. 실제 서비스 배포나 외부 게시 작업은 이 문서 정리 단계에서 수행하지 않는다.

## 1단계 주제와 사용 흐름 정리

11월 2일 제출 전까지 개인 또는 공동 돌봄에서 기록을 모아 보거나 관리 현황을 파악할 때 겪는 불편을 직접 확인한다. 혼자 기록해 통계를 보는 흐름과 구성원을 초대해 같은 기록을 확인하는 흐름을 대표 사용 예시로 정리한다. 실제로 확인한 경험과 아직 확인하지 않은 가정은 구분한다.

주제 제안에는 대상 사용자, 해결할 불편, 모듈·루틴·통계의 역할, 학기 안에 만들 기능과 기본 분류 범위를 작성한다. 기획 문서를 블로그 초안의 재료로 사용하되, 실제 경험과 확인한 내용을 본인의 말로 정리한다.

## 2단계 데이터와 화면 설계

11월 9일 제출 전까지 회원, 반려동물과 기본 분류, 구성원, 모듈 설정, 활동 기록, 루틴, 제품 정보와 비교 기준의 관계를 ERD로 정리한다. 공통 활동 기록 하나가 루틴과 모듈에 연결되고 통계에 한 번만 반영되는 구조를 확인한다. 분류 항목과 비교 기준을 이후 세분화할 수 있게 설계한다.

오늘 화면, 급여 기록 화면, 루틴과 통계·종합 상태 화면의 간단한 시안을 만든다. 인증과 초대 방식, 구성원 권한, 사용할 기술과 저장 방식을 결정한다. 제품 영양 정보와 분류별 비교 기준의 출처를 확인하고, 자동 조회를 붙일 경우 실제 사용할 제품 몇 개로 API 정보가 충분한지 확인한다.

## 3단계 첫 배포

11월 16일 제출까지 개인 사용자가 반려동물 공간에서 급여 기록을 입력하고 목록으로 다시 볼 수 있는 버전을 우선 만든다. 기본 분류를 등록하고 저장·조회 흐름을 확인한다. 구성원 공유가 가능하면 두 사용자로 같은 기록을 확인한다. 핵심 저장·조회 흐름을 먼저 배포하고 모든 확장 기능이 끝날 때까지 미루지 않는다.

첫 배포 블로그에는 실제 화면과 URL, 데이터 저장 방식, 막힌 문제와 해결 과정을 남긴다. 공개 시연에는 실제 가족 정보 대신 시연용 데이터를 사용한다.

## 4단계 핵심 기능 통합

첫 배포 후 산책·밥·간식, 종별 기본 모듈, 모듈 선택·배치, 루틴을 연결한다. 기록을 수정했을 때 오늘 화면, 공동 사용자의 화면, 통계와 종합 상태에 같은 결과가 반영되는지 확인한다.

제품 직접 등록과 기본 영양 계산을 구현하고, 적용 가능한 분류별 기준을 등록해 통계와 비교하는 흐름을 연결한다. 비교 기준이 없는 경우에도 기록·통계는 사용할 수 있게 한다. API의 데이터 범위가 충분하면 자동 조회를 검토한다. 산책은 수동 시간·거리 기록을 먼저 완성하고 GPS와 소모 칼로리 추정은 별도 검증 후 확장한다.

## 5단계 개인·공동 사용 확인과 최종 정리

12월 7일 제출 전까지 개인·공동 사용 흐름으로 기록 입력, 모듈 설정, 중복 확인, 루틴 완료, 통계와 종합 상태 확인을 점검한다. 기본 분류에 맞는 기준을 적용하는지와 미확인 항목 표시도 확인한다. 사용자가 헷갈리는 입력 항목과 불필요한 알림을 수정한다.

최종 블로그에는 처음 계획과 실제 구현 결과, 가장 오래 막혔던 문제, 수정 과정과 다음 버전의 기능을 정리한다. 발표는 문제 설명, 서비스 시연, 해결한 어려움, 다음 단계 순으로 준비한다.

## 기능을 확인하는 대표 상황

- 다른 구성원을 초대하지 않아도 모듈을 선택·배치하고 활동 기록과 통계를 확인한다.
- 기간별 급여량·활동량·영양 합계가 유효한 기록과 일치하고, 여러 모듈의 결과를 종합 상태 화면에서 확인한다.
- 반려동물의 종과 기본 분류를 저장하고, 해당 분류·지표·단위·기간에 맞는 기준만 비교에 사용한다.
- 적용할 기준이 없으면 통계는 보여주되 기준 비교는 미확인으로 구분한다.

- 한 구성원이 밥을 기록한 뒤 다른 구성원이 같은 완료 상태와 최근 기록을 확인한다.
- 루틴에서 완료한 밥이 밥 모듈에도 한 번만 나타나고 영양 합계에도 한 번만 반영된다.
- 모듈에서 먼저 입력한 활동을 루틴에 연결해도 새 활동이 중복 생성되지 않는다.
- 두 구성원이 동시에 같은 예정 항목을 처리하려 할 때 진행 상태와 최근 기록을 확인한다.
- 간식 모듈을 꺼도 기존 간식 기록이 하루 칼로리 합계에서 사라지지 않는다.
- 제품 칼로리가 없으면 0으로 표시하지 않고 확인된 합계와 미확인 기록을 구분한다.
- 초대받지 않은 사용자는 다른 반려동물 공간의 기록을 열 수 없다.

## 이후 검토할 기능

제품 포장지 사진 입력, 고양이 놀이·화장실 모듈, 앵무새 활동·케이지 모듈은 후속 후보로 둔다. 별도 인수인계 기능, 여러 반려동물의 활동 일괄 기록, 사용자 정의 모듈 제작은 현재 핵심 범위에 포함하지 않는다.

다음 버전에는 여러 동물을 그룹으로 묶어 관리하는 기능을 검토한다. 보호소나 사육시설에서 동물의 종류나 사육 공간별로 그룹을 만들고, 담당자·관리 기록·급여량·통계를 확인하는 방향이다. 개별 기록과 그룹 전체 현황을 함께 볼 수 있도록 하며, 상세 기능은 후속 설계에서 정한다.

## 최종 발표 초안

과제 안내의 네 항목에 맞춰 5분 안에 설명한다. 현재는 구현 전이므로 시연 내용과 개발 중 해결한 문제는 실제 결과에 맞춰 수정한다.

1. **누구의 어떤 불편을 풀려고 했나**
   반려동물을 돌보면서 기록이 체계적으로 모이지 않으면 관리 현황과 변화를 파악하기 어렵습니다. 여러 사람이 함께 돌볼 때는 정보 공유 부족으로 중복과 누락도 발생합니다. 개인이나 여러 사람이 필요한 모듈로 정보를 쉽게 기록하고, 모인 기록을 통계와 종합 상태 확인에 활용하도록 이 서비스를 기획했습니다.
2. **시연: URL로 들어가 실제로 써보기**
   배포 후 실제 구현한 기능을 기준으로 시연한다. 반려동물의 기본 분류와 모듈을 설정하고, 활동을 입력한 뒤 오늘 요약과 기간별 통계·종합 상태에 반영되는 흐름을 보여준다. 적용 기준과 비교하는 기능, 구성원을 초대해 같은 기록을 확인하는 기능은 실제 구현 결과에 맞춰 설명한다.
3. **가장 오래 막혔던 것 하나와 어떻게 풀었는지**
   개발 후 실제 겪은 문제 한 가지를 고른다. 어떤 상황에서 막혔는지, 원인이 무엇이었는지, 어떻게 수정했고 해결 여부를 어떻게 확인했는지 설명한다. 아직 발생하지 않은 문제나 해결 결과를 미리 작성하지 않는다.
4. **다음 버전에 넣고 싶은 것**
   다음 버전에는 여러 동물을 그룹으로 묶어 관리하는 기능을 넣고 싶습니다. 보호소나 사육시설처럼 많은 동물을 돌보는 환경에서도 동물의 종류나 사육 공간별로 그룹을 만들고, 그룹별 급여량과 관리 기록, 담당자와 통계를 확인할 수 있게 하는 것입니다. 개별 동물의 기록과 그룹 전체 현황을 함께 볼 수 있도록 확장하고 싶습니다.
