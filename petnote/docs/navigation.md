# 모바일 탐색 구조

기존 사이드바의 기능을 목적에 따라 묶었습니다. 모바일은 기본 하단바에서 영역을 선택하면 해당 영역의 메뉴가 담긴 플로팅 하단바로 바뀝니다. 기존 PC 사이드바는 변경하지 않고 모바일 전체 메뉴에서만 새 항목 정의를 사용합니다.

## 메뉴 구분

| 영역 | 포함한 기존 화면 | 모바일 하단바 표기 |
|---|---|---|
| 오늘 | 오늘의 돌봄과 일정 | 오늘 |
| 돌봄 | 돌봄 기능, 루틴, 물품 관리 | 기능 · 루틴 · 물품 |
| 기록 | 전체 기록, 최근 통계 | 기록 · 통계 |
| 관리 | 구성원, 반려동물 상태, 일반 설정 | 구성원 · 반려동물 · 설정 |
| 전체 | 모든 메뉴와 돌봄 공간 이동 | 전체 |

오늘과 전체 메뉴에서는 **오늘 · 돌봄 · 기록 · 관리 · 전체**가 화면 아래에 표시됩니다. 돌봄·기록·관리에 들어가면 하단바가 화면 가장자리에서 떨어진 둥근 형태로 바뀝니다. 왼쪽 돌아가기 버튼은 오늘 화면과 기본 메뉴로 이동합니다. 브라우저 뒤로 가기는 방문 이력을 그대로 따릅니다.

메뉴를 접어 둔 상태에서도 각 화면에는 실제 주소가 있습니다. 주소 직접 열기, 새로고침, 기록 상세·통계·물품 편집 같은 하위 화면에서도 소속 메뉴를 표시합니다. 메뉴 위치가 바뀌어도 기존 권한 검사는 서버에서 유지합니다. 구성원의 반려동물 상태 읽기, 개인 설정 접근도 유지합니다.

## PC와 모바일

PC의 사이드바는 유지보수 완료 시점의 메뉴 순서·구성원·설정 영역 및 입력창 동작을 그대로 사용합니다. 모바일 전용 스타일과 스크립트는 PC에 적용하지 않습니다.

모바일 상단의 공간 메뉴는 전체 메뉴를 여는 링크입니다. 스크립트를 사용할 수 있으면 대화상자로 열리고, 사용할 수 없으면 전체 메뉴 페이지로 이동합니다. 대화상자는 닫기 버튼과 Escape로 닫을 수 있으며, 닫은 뒤 열었던 링크에 초점을 돌려줍니다. 전체 메뉴의 공간 링크도 스크립트 없이 동작합니다.

하단바는 안전 영역과 본문 아래 여백을 확보합니다. 영역별 하단바에는 한 번에 필요한 메뉴만 표시하고, 선택 상태를 아이콘 배경과 글자 색으로 함께 나타냅니다. 애니메이션 축소 설정과 고대비 모드도 반영합니다.

## 구현 위치

| 파일 | 역할 |
|---|---|
| `care/navigation.py` | 메뉴 정의와 현재 영역 판정 |
| `care/templatetags/care_tags.py` | 화면 문맥에 맞는 공통 메뉴 구성 |
| `templates/care/`의 탐색 부분 템플릿 | 기존 PC 레이아웃 유지, 모바일 하단바·대화상자와 전체 메뉴 |
| `static/care/navigation.css` | 모바일 메뉴·플로팅 하단바·화면 크기별 배치 |
| `static/care/mobile-menu.js` | 메뉴 대화상자의 초점·닫기·기본 링크 동작 |
| `care/tests/test_navigation.py` | 메뉴·하위 화면·권한·레이아웃 서버 회귀 검사 |
| `scripts/qa/navigation_checks.py` | 실제 브라우저의 이동·뒤로 가기·반응형·기본 동작 검사 |

메뉴 구성은 기존 `active_tab`을 기준으로 계산하고 별도 저장소에 상태를 저장하지 않습니다. 새 DB 테이블이나 마이그레이션은 필요하지 않습니다.

## 검사

[자동 검사와 CI](testing.md)의 기존 실행 명령에 탐색 회귀 검사를 연결했습니다. `scripts/check.py`는 서버 검사를, `scripts/qa/verify_maintenance.py`와 `scripts/qa/verify_petnote_browser.py`는 브라우저 검사를 포함합니다. 검사 실패는 전체 실행의 실패 결과로 전달합니다.

실제 수행 결과는 해당 실행의 `tmp/` 결과 파일로 확인합니다. PC 브라우저의 작은 화면 검사는 실물 휴대전화의 키보드·브라우저 표시줄 동작 확인과 구분합니다.

### 적용 범위 정정

PC 사이드바의 원래 구조와 설정 대화상자 동작을 복원했습니다. 새 탐색 영역에만 페이지 이동 예외를 적용합니다. 모바일 전체 메뉴와 플로팅 하단바는 유지합니다. 최종 검증: SQLite 및 PostgreSQL 서버 검사 각각 523개, Chromium·Firefox 브라우저 검사 SQLite 216개 및 Docker 162개를 통과했습니다. 기존 PC 메뉴 순서, 설정 입력창, 모바일 전용 스타일·스크립트의 분리와 모바일 탐색을 확인했습니다. 실물 기기 및 GitHub Actions 실행은 별도입니다.
