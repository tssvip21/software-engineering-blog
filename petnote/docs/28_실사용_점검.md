# 펫노트 실사용 점검

아래 결과는 2026년 11월 23일 Windows PC에서 점검한 기록이다. 11월 24일부터 기본 시연에는 강아지·고양이 두 공간만 제공한다. 화면·요청 주소·DB 항목의 연결은 [프로젝트 딕셔너리](27_프로젝트_딕셔너리.md)에 정리했다.

## 고친 동작

- 반려동물 등록 화면은 원래 요청 번호를 보냈지만 서버가 이 값을 사용하지 않았다. 이제 같은 계정에서 같은 등록을 동시에 두 번 보내도 같은 공간을 돌려준다. 같은 번호로 이름을 바꾸면 409로 안내하고, 새 입력창에서 시작한 등록은 따로 저장한다. 요청 번호가 없는 예전 양식도 지원한다.
- 활동별 통계에서 시작일과 종료일을 거꾸로 넣거나 366일을 넘기면 오류 처리 중 종료일을 다시 읽어 서버 오류가 날 수 있었다. 검사할 날짜를 먼저 보관하도록 바꾸고 두 경우 모두 브라우저에서 안내를 확인했다.
- 첫 화면의 로컬 시연 선택지는 **빈 계정으로 시작**, **관리자로 보기** 두 개다. 실제로 눌러 보니 관리자가 볼 시연 공간이 없었다. 시연 데이터 준비 코드에서 기존 강아지·고양이·앵무새 공간에 관리자 계정을 연결했다. 빈 계정은 첫 반려동물 등록 화면으로 이어지고, 관리자는 세 동물의 기존 기록을 볼 수 있다.
- 주소 설정과 파이썬 호출을 대조해 `care/views.py`에서 쓰이지 않던 이전 화면 처리 함수 10개를 정리했다. 선택기에서 빠진 두 역할을 쓰는 과거 검사 도구는 로컬 검사 계정으로 접속하도록 바꿨다.

## 브라우저와 서버 검사

| 환경 | 확인한 결과 |
|---|---|
| Chromium → Caddy → Django → PostgreSQL | 서로 다른 검사 61개 통과. 새 공간 등록, 같은 등록의 동시 요청, 오늘 화면의 빠른 기록, 루틴 등록, 활동별 직접 입력, 수정 이력, 취소·검색·날짜 오류, 초대 참여·중단, 공개 범위, 모바일 탐색, 통계·재고·로그아웃 |
| 로컬 시연 서버 8036 | 첫 화면에 버튼 두 개 표시. 빈 계정에서 첫 등록 안내 확인. 관리자 계정으로 세 동물 목록과 강아지의 빠른 기록 화면 확인 |
| Django 자동 검사 | SQLite 486개, Docker PostgreSQL 486개 통과. 이전에 실패한 7개는 현재 쓰는 스타일·통계 화면·재고 탭에 맞춰 검사했다 |
| Docker 재시작 | QA용 컨테이너 세 개를 재시작했다. 전후 PostgreSQL 기록 1,231건의 ID·입력값·메모·수정 버전·취소 상태를 정렬해 비교한 값이 일치했다 |

브라우저 검사는 실행할 때마다 가상 보호자 계정을 새로 만들고 로그인 세션을 준비한다. 초대받는 사람은 별도의 빈 브라우저에서 실제 초대 화면으로 참여한다. Google 실계정 로그인은 이번 확인 범위에서 제외했다. 사람에게 맡기는 사용자 테스트도 진행하지 않았다.

커밋한 소스만 따로 꺼내 돌렸을 때는 예전 서비스 이름을 찾는 검사가 한 건 더 실패했다. 작업 폴더에 이미 있던 서비스 이름 수정 한 줄을 검사 커밋에 포함한 뒤, 독립된 사본에서도 SQLite 검사 486개가 통과했다.

## 성능

로컬 Docker PostgreSQL의 같은 공간에서 산책 기록 1,200건을 공동 보호자 계정으로 조회했다. 첫 요청으로 화면을 한 번 띄운 후 같은 요청을 7번 보냈다. 시간은 Django가 HTML 응답을 만드는 데 걸린 중앙값이다. 브라우저 다운로드와 화면 그리기 시간은 측정에 포함되지 않는다.

| 화면 | DB 조회 전 → 후 | 응답 시간 전 → 후 |
|---|---:|---:|
| 오늘 | 56 → 24회 | 89.0 → 49.0ms |
| 돌봄 기능 | 54 → 22회 | 83.9 → 44.9ms |
| 전체 기록 | 15 → 12회 | 19.6 → 13.9ms |

이 공간에는 재고 기록이 없는데도 여러 활동을 집계할 때마다 비공개 재고 이름을 다시 조회했다. 재고 기록을 실제로 만났을 때 조회하도록 바꿨다. 같은 보호자 정보를 기록 수만큼 반복해 읽는 부분과, 분류 미리보기에 표시할 기록이 0건인데도 DB를 찾는 부분도 줄였다.

## 같은 환경에서 다시 확인하기

현재 시연은 프로젝트 폴더에서 `docker compose up -d --wait`로 실행한다. Python 단독 실행은 `START_DEMO.cmd`를 사용한다.

Docker Desktop이 실행된 Windows PC에서 프로젝트 폴더의 PowerShell로 실행한다. 아래 프로젝트 이름과 포트는 검사 스크립트가 사용하는 전용 환경이다. 실행할 때마다 그 환경에 가상 계정과 검사 기록이 추가된다.

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/local_compose.py up --project taily-local-petnote-qa --port 8097
.\.venv\Scripts\python.exe -X utf8 scripts/verify_petnote_browser.py
.\.venv\Scripts\python.exe -X utf8 scripts/local_compose.py test --project taily-local-petnote-qa --port 8097
.\.venv\Scripts\python.exe -X utf8 manage.py test care.tests --noinput
```

브라우저 검사에 필요한 Playwright와 Chromium이 설치돼 있어야 한다. 통과 목록은 `tmp/petnote-browser-results.json`에 저장된다. 속도 측정은 같은 프로젝트에서 아래 명령으로 반복한다.

```powershell
$OutputEncoding = [Text.UTF8Encoding]::new($false)
Get-Content -Encoding UTF8 -Raw scripts/measure_room_pages.py | docker exec -i taily-local-petnote-qa-backend-1 python manage.py shell -c "exec(__import__('sys').stdin.read())"
```
