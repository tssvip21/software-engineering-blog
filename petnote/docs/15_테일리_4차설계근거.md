# 테일리 4차 설계 — 연구에서 작업으로

2026-11-05. 제품 구현 전에 개선 전 화면과 대표 작업을 기록하고, 외부 사이트를 참고해 구성과 사용 흐름, 한국어 표현을 검토했다. 아래는 연구가 제안하는 설계 판단과 확인 계획이다. 연구를 읽었다는 사실이나 자동 검사 통과를 실제 사용자의 만족·임상 효과로 바꾸어 표현하지 않는다.

## 읽은 연구와 적용 조건

|---|---|---|

정보 탐색에서는 목적과 일치하는 분류명을 보고 선택할 수 있도록 한다. 시간순 목록 위에 분류 필터만 붙이는 대신 첫 화면부터 분류별 기록 묶음과 관련 활동을 보여준다. 분류 전체 선택과 특정 활동 선택은 별개의 상태로 보존한다.

## 작업별 설계와 성공 조건

1. 분류 안 기능 추가: 분류 제목 옆 선택창 → 같은 분류의 체크박스 → 적용. 다른 분류의 순서·고정 상태·기록은 바뀌지 않는다. 저장 실패는 선택을 유지하고, 버전 충돌이면 덮어쓰지 않는다. Escape/닫기/취소 후 시작 위치로 초점이 돌아온다.
2. 과거 기록 찾기: 첫 화면은 분류별 기록 모음이다. 선택한 분류 안에서 활동·기간·기록자·검색을 좁힌다. 상세 확인·수정·취소 후 돌아와도 분류와 조건을 유지한다. 잘못된 외부 복귀 주소는 받지 않는다.
3. 최근 변화 확인: 쉬운 전체 결론과 관련된 변화만 먼저 제공한다. 결과를 누르면 관련 날짜·실제 기록값·기간별 비교만 보여준다. 계산식·알고리즘 설명은 일반 화면에서 제거한다. 비교할 수 없는 항목을 정상이라고 채우지 않는다.
4. 반복 입력: 빠른 입력, 최근값을 사용자가 선택하여 넣기, 저장 결과와 실행 취소를 유지한다. 짧은 안내 때문에 실제 섭취와 제공량, 기록 시각과 수행자 의미를 흐리지 않는다.

## 분석 방법의 재검토와 선택

평균/표준편차는 극단값에 민감하고, EWMA는 지속적인 관측 조건이 필요하다. 이 자료에 통계적 확률을 붙이거나 모든 쌍의 상관을 찾으면 기록 편향·다중 비교를 오해하기 쉽다. 기존 중앙값·MAD와 실제 날짜를 쓰는 Theil–Sen은 설명 가능한 내부 변화 탐색의 출발점으로 유지하되 다음 조건을 보완한다.

- 하루가 끝나지 않은 값을 완성된 날의 합계와 비교하지 않는다. 일별 합계의 최근 비교에는 마감된 날을 사용하고 화면 날짜를 일치시킨다. 최신 측정/관찰은 별도로 보여준다.
- 한 번의 큰 차이가 중앙값에 묻혀 아무 일 없는 듯 보이지 않게, 지속 변화와 구별해 확인할 기록으로 남긴다. 원본은 자동 삭제하지 않는다.
- 기록한 활동 종류·횟수가 달라진 경우 합계 변화만으로 실제 생활 변화를 확정하지 않는다. 해당 항목을 구분해 설명한다.
- 함께 변한 관계는 단순히 양쪽 기록이 있는 날짜가 아니라 실제 변화가 나타난 날의 겹침을 확인한다. 날짜가 다른 변화는 각각 설명한다.
- 하나의 식사 사실을 양·열량 등 여러 지표로 중복 가산하지 않는다. 비슷함·단일/함께/엇갈린 변화·자료 부족을 독립 시나리오로 확인한다.
- 수치 문턱과 최소 자료량은 임상 정상 범위가 아닌 서비스 설계값이다. 여러 강도의 변화/소음/누락/기록 방식 변화에서 민감도를 확인한다.

## 한국어와 글자 체계

행동은 짧은 동사로, 설명은 결과와 다음 행동 순서로 쓴다. 내부 용어 대신 사용자가 하는 일을 표현한다. 같은 기능은 같은 말로 쓰되 모든 글자를 기계적으로 치환하지 않는다. 사용자 데이터는 고치지 않는다.

한글 시스템 글꼴을 사용하고 본문은 16px 기준, 보조 정보 13px 이상, 제목·핵심 결과·조작부를 크기와 굵기로 구별한다. 본문 행간은 1.6을 출발점으로 실제 문구에서 조정한다. 어절 중심 줄바꿈에 긴 입력값의 비상 줄바꿈을 함께 둔다. KRDS는 설계 참고이지 우리 화면의 실험 결과가 아니다. W3C 한국어 조판 문서는 초안이며 규범으로 오인하지 않는다.

일반 글자 대비 4.5:1, 큰 글자 3:1을 확인한다. 색만으로 선택·변화 상태를 구분하지 않는다. 좁은 폭 320px과 글자 200%·간격 사용자 변경에서 내용을 잃지 않는지 검사한다. WCAG 텍스트 간격은 사용자가 간격을 바꿔도 동작하도록 하는 기준이며 그 숫자를 기본 스타일에 강제하는 조항이 아니다.

## 검증 범위

개선 전후의 대표 작업을 같은 데이터로 직접 재생하여 선택 단계·페이지 이동·표시 정보와 되돌아감을 비교한다. 자동 클릭 시간을 사람의 작업 시간으로 보고하지 않는다. 개발자 관점의 작업 점검과 자동 기능/접근성 검사는 사람을 대상으로 한 사용성 실험과 구분한다. 실제 사용자 선호와 장기간 효과는 이번 검사로 확인할 수 없다. 코드가 충분한 자료에서도 모든 결과를 자료 부족으로 회피하는지 별도 시나리오를 둔다.

## 후속 작업 점검의 평가 질문

구현 전 검토한 위 연구에 더해, 실제 작업 재생을 평가할 때 Wharton·Rieman·Lewis·Polson의 Cognitive Walkthrough 실무 지침(1993 기술보고서, 1994 수록본)의 네 질문을 적용했다. 매 단계에서 사용자가 이루려는 효과, 사용할 조작부의 발견 가능성, 조작 이름과 결과의 연결, 실행 후 진전의 확인을 따로 살폈다. 버튼이 눌린다는 사실만으로 네 질문에 모두 통과했다고 판정하지 않는다.

분류 제목 옆 ‘기능 선택’, 같은 분류만 담긴 선택창, ‘적용’ 후 해당 목록의 변경, 보던 기록으로 복귀하는 링크가 그 연결점이다. 화면을 처음 보는 보호자가 정확한 기능 이름을 외우고 있다는 전제는 두지 않았다. 실수·실패·되돌림도 같은 작업의 일부로 검사했다.

이 방법은 개발자가 탐색과 학습상의 문제를 찾는 점검이다. 실제 참여자의 생각·작업 시간·오류율·만족도를 측정한 실험을 대신하지 않는다. 네 질문도 모든 사람에게 적용되는 절대 법칙으로 취급하지 않는다. 연구를 추가로 읽은 시점은 후속 검수 단계이며, 이를 최초 구현 전에 읽었다고 소급하지 않는다.
