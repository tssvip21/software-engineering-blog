## 코드와 보안

- JSON 읽기를 공통 처리로 모으고 인코딩 오류, 과도한 중첩, 유한하지 않은 수, DB에 저장할 수 없는 문자를 입력 단계에서 거부한다. 잘못된 모듈 값과 UUID 조회도 500 오류로 이어지지 않도록 했다.
- 공통 조회 함수에서 공간 일치, 활성 구성원, 민감 기록 공개 범위를 확인한다. 비공개 재고의 경고·이벤트 식별자도 결과에서 제외한다.
- 재고 기록 카드마다 반복하던 공개 범위 조회를 묶었다. 같은 검사 공간에서 기록 1개→11개로 늘릴 때 조회가 기존 13회→33회에서 11회→11회로 바뀌었다. 11개 목록은 33회에서 11회로 줄었다.
- DB 연결 실패 시 상태 확인 주소는 내부 내용을 내보내지 않고 503 상태를 반환한다. 운영의 짧거나 예시 형태인 비밀키는 시작 단계에서 거절한다.
- 같은 출처의 GPS 사용을 브라우저 권한 허용 하에 지원한다. 카메라·마이크 등 사용하지 않는 권한은 기존 제한을 유지한다.
- 다른 구성원을 연 뒤 이전 응답이 늦게 도착해 현재 패널을 덮어쓰는 문제를 고쳤다. 부분 갱신 후 시간 막대가 멈추는 문제도 수정했다. 갱신 응답 HTML은 한 번 파싱한 결과를 재사용한다.

새 서버 회귀 테스트 21개를 추가했다. 첫 전체 검사에서는 잘못된 루틴 입력의 응답을 400으로 바꾼 수정이 기존 입력창의 422 계약과 충돌했다. 기존 기대값과 동작을 유지하도록 복구한 뒤 두 DB의 전체 검사를 다시 통과했다.

## 폴더와 실행 도구

- 중복 시연 실행기 7개를 `scripts/run_local.py --demo --profile <이름> --port <포트>`로 통합했다.
- 반복된 전체 검증 실행기 6개를 `scripts/check.py`로 통합했다. 현재 브라우저·성능 도구는 `scripts/qa/`, 과거 개별 화면 검사 도구는 `scripts/qa/legacy/`에 모았다.
- 문서·도구 37개를 용도별로 옮겼다. 완료된 작업 지시서 4개와 사용하지 않는 로고 후보 3개를 제거했다. 삭제한 이전 파일은 Git 이력에 남아 있다.
- 초기 설계·실행 기록은 `docs/history/`로 모으고 현재 문서의 시작점을 `docs/README.md`로 정했다. 블로그가 연결하는 기존 문서 경로와 블로그 파일은 유지했다.
- Python 시연은 운영 DB·OAuth 환경변수의 영향을 받지 않고 별도 데이터·정적 파일·쿠키를 사용한다. 백업 도구도 같은 시연 경로를 따른다.
- SQLite 복원 전 안전 백업에 검증 JSON을 함께 저장해 그 안전 백업으로도 복원할 수 있다. 무결성·파일 종류·검증값이 맞지 않으면 기존 DB를 바꾸지 않는다.

## CI와 Docker

CI는 코드·브라우저 검사와 Docker·PostgreSQL 검사를 병렬로 실행한다. 읽기 권한, 고정된 Actions 버전, 시간 제한, 결과 보관, 검사 환경 종료를 설정했다. 비밀 설정·개인 식별 정보·공개하지 않을 표현을 커밋과 현재 소스에서 검사하며 실제 일치 값을 로그에 출력하지 않는다.

Docker는 내부 DB 네트워크, 프런트엔드 상태 검사, 비관리자 백엔드, 읽기 전용 파일시스템과 권한 축소, 로그·메모리 제한을 적용했다. 로컬 초기화는 시연 모드·로컬 DB 이름·DB 호스트를 확인한 뒤 실행한다. 런타임 의존성은 공통 잠금 파일을 사용한다.

운영 설정 검사에서 오류는 없었다. HSTS의 모든 하위 도메인 적용과 preload에 관한 안내 두 개는 남아 있다. 실제 하위 도메인의 HTTPS 운영과 preload 등록을 확인해야 하는 설정이므로 임의로 켜거나 안내를 숨기지 않았다.

## 확인 범위와 근거

실제 Google OAuth 로그인, 실물 모바일 기기, 실제 사용자 대상 사용성 평가는 이번 자동 검사로 확인하지 않았다. 의존성 보안 검사는 검사 시점의 알려진 취약점에 한정된다.

PC의 `tmp/maintenance-20261126/`에 전체 로그와 결과를 보관한다. 핵심 파일은 `final-checks/results.json`, `final-infra-results.json`, `browser-final.json`, `compose-browser-final.json`, `backend-query-measurement.json`, `native-smoke.json`, `final-review.json`이다. 이 결과 폴더와 데이터·비밀값은 커밋 대상에서 제외한다.

## 2026년 11월 28일 추가 재검수

중간점검 권고를 현재 공개 소스와 대조한 뒤, 별도 작업 폴더에서 백엔드·Docker 실행기·업로드 전 검사를 보완했다. 기존 화면·모바일 메뉴·PC 사이드바·블로그·실제 데이터는 수정하지 않았다. 이 기록은 로컬 검증 결과이며 새 변경의 GitHub 반영과 운영 배포를 뜻하지 않는다.

### 수정한 내용

- 기록 탐색의 카테고리별 최근 기록 조회를 하나의 윈도 함수 쿼리로 묶었다. 기존 권한 필터, 목록·전체 개수, 정렬·페이지 계약을 유지하고 같은 시각의 기록은 식별자로 순서를 확정한다. 네 카테고리 요청에서 SELECT가 12회에서 9회로 줄었다.
- 운영 Compose 형식의 로컬 실행기는 상위 셸의 DB·OAuth·외부 바인딩·Compose 환경변수를 차단하고 저장된 로컬 설정만 사용한다. 실제 Docker 연결이 로컬 socket 또는 named pipe인지 확인하고 실행 중에도 같은 대상으로 고정한다.
- 같은 프로젝트의 컨테이너·볼륨이 남았는데 환경 파일이 없으면 비밀번호 재생성을 거절한다. 기존 환경 파일을 복구하거나 다른 프로젝트 이름을 사용해야 한다. 기존 데이터 볼륨은 삭제하지 않는다.
- 공개 검사기에 선택한 커밋의 전체 조상 및 모든 로컬 refs 검사 모드를 추가했다. 축소된 이력은 전체 검사로 인정하지 않는다.
- GitHub Actions에 전체 이력 Gitleaks 검사를 추가했다. 공식 배포 파일의 해시를 확인하고 기본 탐지 규칙·인코딩·압축 탐색·출력 가림을 사용한다. 저장소의 허용 주석과 예외 설정으로 검사를 축소하지 않는다.
- 설치형 pre-push hook을 추가했다. 실제 업로드할 현재 HEAD의 전체 이력·현재 파일·비밀값·서버와 도구 검사가 통과해야 한다. 미커밋 변경, 다른 커밋 업로드, 검사 중 변경, 도구 누락과 실패는 차단한다. 설치는 현재 worktree 설정에만 적용한다.

### 조회 성능 확인

기존 코드와 변경 코드를 같은 PostgreSQL 검사 DB에서 비교했다. 네 카테고리의 미리보기·전체 개수·목록 식별자가 모두 같았고 요청당 조회는 12회에서 9회로 줄었다. 합성 데이터만 사용했으며 실제 계정과 운영 DB는 대상이 아니다.

| 합성 기록 수 | 기존 요청 시간 중앙값 | 변경 후 중앙값 | 조회 수 |
|---|---:|---:|---|
| 24개 | 21.9ms | 19.6ms | 12 → 9 |
| 20,000개 | 84.5ms | 80.0ms | 12 → 9 |

각 조건은 예열 후 다섯 번 측정한 로컬 요청이다. 실행 환경·네트워크·로그인 상태에 따라 달라지므로 운영 사이트 전체의 속도 향상률로 환산하지 않는다. 기능·권한 회귀 검사 8개를 추가했다.

### 전체 이력과 공개 상태

공개 저장소의 확인 가능한 8개 브랜치와 6개 PR 참조, 합계 119개 커밋의 내용·커밋 메타데이터·고유 blob을 검사했다. 공개 이미지 22개와 문서 형식도 별도로 확인했으며 실제 비밀값·개인 식별 정보는 발견되지 않았다. 저장소 밖의 복제본이나 GitHub에서 노출하지 않는 삭제된 객체·캐시까지 검사했다는 뜻은 아니다.

과거 로컬 원본 저장소에서는 개인 식별 정보가 확인되어, 원본과 분리한 정제 사본을 만들었다. 공개 저장소에서 확인 가능한 객체와 해당 개인정보 객체가 겹치지 않는 것을 확인했다. 정제 사본의 자세한 변경 범위·검사 근거는 로컬 감사 기록에 남기며 실제 개인정보를 이 문서에 적지 않는다.

현재 공개 사이트는 Vercel·Supabase 구성이다. 익명 읽기 검사에서 HTTPS 첫 화면·상태 확인·정적 파일은 200, HTTP는 HTTPS로 308 전환했고, 보안 헤더도 확인했다. 이 확인은 신규 변경 배포나 실제 계정 로그인 성공을 뜻하지 않는다.

기존 공개 main의 [GitHub Actions 실행](https://github.com/tssvip21/software-engineering-blog/actions/runs/45861165179)은 성공 상태였다. 이번에 보완한 워크플로는 로컬에서 검증했으며 아직 GitHub Actions 서버에서 새 실행을 만들지 않았다.

### 근거와 남은 사람의 확인

이번 작업 폴더의 `tmp/review-20261128/`에 `full-checks/results.json`, `full-checks/browser-results.json`, `postgres-final-tests.log`, `compose-runtime.log`, `runtime-dependency-audit.json`, `cleanup-before.json`, `cleanup-after.json`을 보관한다. 추가 조회 비교는 `tmp/backend-review/record-query-comparison.json`에 있다. 이 폴더들은 커밋에서 제외한다. 로컬 업로드 검사는 설치 후 `.github/scripts/pre_push.py --check`로 업로드 없이 다시 실행할 수 있다.

실제 Google OAuth 로그인, 실제 사용자와 가족·친구의 입력·조회 후기, 교수님의 저장소 열람 권한과 최종 검수는 별도 확인이 필요하다. 접근할 수 없는 과거 원격 저장소의 현재 공개 범위나 숨겨진 이력은 확인 완료로 표시하지 않는다.
