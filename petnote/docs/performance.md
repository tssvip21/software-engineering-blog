## 확인한 병목과 조치

### 서버와 DB의 위치

기존 함수는 미국 `iad1`, 기존 PostgreSQL 풀러는 인도 뭄바이 `ap-south-1`에 있었다.
조회가 여러 번 필요한 페이지와 저장 작업마다 지역 간 왕복이 반복됐다.
보호된 검증 배포에서 한국 `icn1`과 비교한 뒤, DB와 같은 `bom1`을
`vercel.json`에 명시했다. 데이터베이스 자체를 이전하거나 복제하지 않았다.

공식 지역 대응과 배치 원칙:
https://vercel.com/docs/regions
https://vercel.com/docs/functions/configuring-functions/region

### DB 연결 재사용

기존 설정은 요청마다 연결을 닫고 다음 요청에서 TCP/TLS 및 연결 초기화를 다시 수행했다.
Django의 기본 PostgreSQL 풀을 사용해 요청 종료 시 연결을 반환한다.

| 항목 | 설정 |
| --- | --- |
| 최소 연결 | 0 |
| 최대 연결 | 프로세스당 4 |
| 연결 대기 | 최대 5초 |
| 대기 요청 | 최대 16개 |
| 유휴 정리 | 30초 |
| 연결 수명 | 300초 |
| 반환된 연결 재사용 전 검사 | 활성화 |

`CONN_MAX_AGE=0`은 유지한다. 풀 사용 시 이 값은 요청 종료에 풀로 연결을 반환하게 한다.
TLS 요구와 명시적인 인증서 검증 옵션, prepared statement 비활성화,
server-side cursor 비활성화를 유지한다.
연결 풀에는 사용자 화면·권한·기록 데이터를 캐시하지 않는다.

연결 상한은 전체 서비스 상한이 아니라 프로세스별 상한이다.
Python 런타임이 중단된 동안 백그라운드 유휴 정리가 실행된다고 보장하지 않는다.
재개 시 유효성 검사와 오류 복구가 끊긴 연결을 처리한다.

공식 지원:
https://docs.djangoproject.com/en/5.2/ref/databases/#connection-pool
https://www.psycopg.org/psycopg3/docs/api/pool.html
https://vercel.com/kb/guide/connection-pooling-with-functions

### 조회와 저장

- 오늘 및 돌봄 보드는 오늘 기록, 진행 중 기록, 최근 목록, 기능별 마지막 완료 기록 위주로 읽는다.
- 자정을 넘는 수면, 이전 체중·BCS, 재고 기초 잔량과 비공개 연결에 필요한 이력은 유지한다.
- 요청 내 참여 목록과 기능 설정 조회를 재사용하며, 작성자·실행자는 조인으로 함께 읽는다.
- 상세 페이지는 해당 기능을 계산하고, 사용하지 않던 별도 통계 계산을 제거했다.
- 읽기 전용 보고서는 현재 참여 권한을 재검사하되 방의 쓰기 잠금은 잡지 않는다.
- 빠른 기록은 하나의 기존 트랜잭션에서 방 잠금과 현재 권한을 확인하고 활동·영수증을 저장한다.
- 반복된 방·참여 조회와 세 쌍의 중첩 SAVEPOINT/RELEASE를 제거했다.
- 외부 호출자가 실패를 복구할 수 있는 공개 저장 함수의 트랜잭션 경계는 유지한다.
- 수정 권한, 비활성 기능, 다른 실행자, 재고, 기록 버전, 중복 요청 검사는 계속 DB의 현재 상태를 확인한다.
- 일반 입력 폼 저장은 명시적 JSON 리다이렉트 응답으로 목적지 GET 중복을 제거했다.
  오류 HTML, 입력값, 오류 필드 포커스와 재시도 동작을 유지하며 외부·비정상 URL을 거절한다.

### 글꼴과 정적 자원

`layout_desktop.html`의 body 이후 내용과 PC 사이드바는 기준 커밋과 동일하다.

## 측정 결과와 범위

### 실제 공개 주소

같은 Windows PC에서 기존 주소를 변경 전·후 각각 4회 요청했다.
각 경로의 첫 표본은 따로 남기고, 이후 3회의 TTFB 중앙값을 비교했다.
TTFB는 응답 본문 전체 로딩이나 로그인 후 모든 동작 시간을 뜻하지 않는다.

| 공개 경로 | 변경 전 | 변경 후 | 개선 비율 |
| --- | ---: | ---: | ---: |
| DB 확인 `/health/` | 1.576초 | 0.225초 | 약 7.01배 |
| 공개 홈 `/` | 0.262초 | 0.211초 | 약 1.24배 |
| 참여 안내 `/join/` | 0.279초 | 0.207초 | 약 1.35배 |

별도의 동일한 배포 보호 조건 비교에서는 DB 확인 응답이
1.655초에서 0.205초로 줄었다. 후보 배포에 동시에 보낸 6개 확인 요청은 모두 200이었다.
운영 반영 후 확인한 함수 지역은 `bom1`이며 모든 공개 측정 요청은 200이었다.

중간 한국 배포에서는 단일 DB 쿼리가 약 127ms였고, 뭄바이 후보에서는 약 1.1~1.4ms였다.
이는 지역 배치 원인을 분리하기 위한 비교이며 기존 미국 배포의 전체 화면 속도와 같은 지표가 아니다.

### 격리한 합성 데이터와 브라우저 측정

1,200개 기록과 루틴을 가진 새 SQLite 데이터로 동일한 소유자·게스트 경로를 비교했다.
실제 운영 기록을 복사하거나 수정하지 않았다.

| DB 문장 수 | 이전 | 이후 |
| --- | ---: | ---: |
| 오늘 | 21 | 16 |
| 돌봄 기능 | 23 | 17 |
| 전체 통계 | 16 | 11 |
| 산책 상세, 소유자 | 26 | 15 |
| 산책 상세, 게스트 | 28 | 17 |
| 산책 통계 | 17 | 12 |
| 빠른 물 기록 저장 | 27 | 18 |

빠른 저장은 마지막 수정 후 5회 모두 18개로 확인했다.
같은 토큰의 재요청은 같은 기록을 반환하고, 충돌 요청은 409, 잘못된 입력은 422를 반환한다.
이 세 경우의 활동 수·영수증 수·방 리비전은 바뀌지 않았다.

| 모바일 오늘 첫 로딩 자원 | 이전 | 이후 |
| --- | ---: | ---: |
| 전체 자원 | 2,318,664바이트 | 580,847바이트 |
| 글꼴 | 2,082,220바이트 | 286,620바이트 |

전체 자원은 약 75%, 글꼴은 약 86% 감소했다.
2Mbps·지연 150ms로 제한한 Chromium 모바일 조건에서 글꼴 준비는
공개 홈 10.00→2.81초, 오늘 10.10→3.07초였다.
동일 조건의 오늘 DOMContentLoaded는 1.46→1.69초였다.
따라서 글꼴 준비 개선을 첫 상호작용이나 모든 동작의 10배 개선으로 표현하지 않는다.
로컬 HTTP/1 측정과 운영 CDN의 전송 조건도 다르다.

GET 내부 처리 시간은 경로마다 달랐다. 오늘은 54.56→33.51ms,
소유자 산책 상세는 104.84→56.86ms였으나 전체 통계는 49.89→58.73ms였다.
통계의 로컬 CPU 개선을 주장하지 않는다.
최종 저장 CPU 시간은 다른 QA 작업과 동시에 측정되어 비교 수치로 쓰지 않는다.

사용자의 로그인된 실제 브라우저 탭에는 연결할 수 없었다.
검증은 분리된 로그인 테스트 데이터와 공개 주소를 대상으로 했다.
실물 휴대전화별 속도나 모든 로그인 동작의 10배 향상을 입증한 것은 아니다.
